# SQL 파싱 L1 검사 — 판독

**선언**: `docs/audit-reports/2026-09-19-SQL-파싱-L1검사-사전선언.md`
**구현**: `15ac268d` (검사 + 시험 11 + 개수 게이트 셋)
**게이트**: 실패 0 · 통과 4642 · 건너뜀 0 · 빌드 경고 0

## 1. 한 줄

**표본을 한 편에서 19 편으로 넓히자 「예약어 별칭 하나뿐」이 「가족 다섯」이 됐고, 그중 넷은 앞 검사가 구조적으로 못 보는 모양이었다.**

## 2. 선언 대 실측 — 넷 다 맞았다

| §4 예측 | 실측 | |
| :-- | :-- | :-- |
| 코퍼스 19 편 발화 펜스 **72** | **72** | ✔ |
| 코퍼스 **오탐 0** | **0** — 72 전부 §1 의 다섯 가족 | ✔ |
| 제외로 걸러진 펜스 **4**(자리표시자 2 · 조각 2) | **4**(자리표시자 2 · 조각 2) | ✔ |
| 기존 예약어 별칭 검사 **그대로** | 삭제 줄 **0**(`b4d38672` 대비 순수 추가 105 줄) | ✔ |
| 게이트 실패·건너뜀·경고 0 | **4642 · 0 · 0 · 0** | ✔ |

분모는 전부 **계획서 19 편 · ```sql 펜스 2628** 이고, 파싱 실패 전량이 **76** 이다. `76 − 4 = 72`.

---

## 3. 자를 한 번 틀렸다 — 「다르면 구현을 멈춰라」를 발동할 뻔했다

첫 스윕이 **47** 을 냈다. 선언 §4 의 결정 규칙은 「적으면 제외가 넓다 — 구현을 멈추고 자를 고친다」다.

**멈추기 전에 자를 의심한 것이 맞았다.** 내가 센 것은 `DetailedError.Lexemes` 의 개수인데, 그 자는 `Distinct` 로 **중복 제거된 원문 줄**이다. 같은 `SELECT … AS RowCount` 줄이 열두 펜스에 있으면 하나로 접힌다. 펜스 수는 메시지의 `발화 N건`(`hits.Count`)이고, 그 자로 재니 **72** 였다.

**틀린 것은 검사가 아니라 검사를 읽는 자였다.** 이 저장소가 같은 모양을 반복해 밟았고(「산출물 어휘가 탐침 어휘와 다르다」), 이번 자리의 이름은 **「귀속용으로 접은 수를 측정값으로 썼다」** 다.

⇒ 결정 규칙을 발동하기 전에 **「이 수의 단위가 예측의 단위와 같은가」** 를 먼저 물어야 한다. 예측은 「펜스」라고 적혀 있었고 내 스윕은 「줄」을 셌다.

---

## 4. 두 검사의 수를 나란히 놓으면 안 된다 — 자가 다르다

| | 파싱 검사 | 예약어 별칭 검사 |
| :-- | --: | --: |
| 발화 문서 | 15 / 19 | 14 / 19 |
| 발화 수 | **72** — **펜스** 단위(펜스마다 첫 오류 하나) | **155** — **자리** 단위(한 펜스의 별칭을 전부 센다) |

선언이 적은 「기존 검사 67 그대로」의 67 은 **펜스** 수였다. 별칭 검사는 애초에 자리를 세므로 같은 표에 놓을 수 없는 두 값이다. **그래서 「그대로」는 수가 아니라 `diff` 로 확인했다** — 삭제 줄 0.

## 5. 예상 밖이 셋

### 5-1. 앞 검사가 통째로 눈먼 문서가 하나 있었다 — `POQSettleBatch1`

| 문서 | 파싱 | 별칭 |
| :-- | --: | --: |
| `POQSettleBatch1` | **1** | **0** |

`Current AS (` — 예약어를 CTE 이름으로 썼다. 앞 검사는 **`AS` 뒤가 여는 괄호인 자리를 설계상 제외**한다(정상 CTE 를 안 먹으려고). 그 제외가 정확히 이 결함을 가렸다.

**정당한 제외가 곧 사각지대다.** 제외를 좁히는 것으로는 못 닫고, **축이 다른 자**(파싱)를 한 겹 위에 둬야 닫힌다.

### 5-2. 자리표시자 2 는 오류 메시지가 서로 달랐다

```
'<' 근처의 구문이 잘못되었습니다.    ← SELECT MIN(<ChunkKey>) …
'.' 근처의 구문이 잘못되었습니다.    ← DELETE FROM …dbo.<LiteralTargetTable>
```

**메시지로 가족을 세면 자리표시자가 「1」로 보인다.** 파서는 `<` 를 만난 자리가 아니라 **문법이 먼저 깨진 자리**를 보고한다. 제외는 메시지가 아니라 **펜스 본문의 모양**으로 판정해야 하고, 구현이 그렇게 돼 있어서 둘 다 걸렸다.

### 5-3. 조각 제외 하나가 시험 **둘**을 빨갛게 한다

선언 §6 은 「각각 **그 제외 시험만** 빨갛다」고 적었다. 실측은 자리표시자 제외 **1**, 조각 제외 **2** 다.

**어긋난 것이 아니라 내가 조각 시험을 둘로 나눠 뒀기 때문이다** — 첫 토큰이 `AND` 인 것과 `CASE` 인 것. 선언의 요구는 「두 제외가 서로의 시험을 덮지 않는가」였고 그것은 지켜졌다(1 과 2 가 겹치지 않는다).

## 6. 되돌림 네 층 — 넷이 서로 다른 집합을 빨갛게 한다

| 층 | 되돌린 것 | 빨개진 시험 |
| :-- | :-- | :-- |
| **효력** | 본문 조기 반환을 `hits.Count >= 0` 으로 무력화 | **6** — 양성 다섯 + 귀속 하나 |
| **배선** | `SafeCheck(() => CheckSqlFenceParses(…))` 줄 삭제 | **9** — 위 6 + **개수 게이트 셋** |
| **자리표시자 제외** | `AngleBracketPlaceholderPattern` 분기 삭제 | **1** — 자리표시자 시험만 |
| **조각 제외** | `OpensWithATokenThatCannotBeginAStatement` 분기 삭제 | **2** — 조각 시험 둘만 |

**효력과 배선이 갈린다**: 발화를 재는 시험은 검사가 아예 안 불려도 같은 값을 낼 수 있다. 여기서는 개수 게이트 셋이 배선만 잡는 자로 서 있다.

원복은 `copy2` 뒤 **`utime`** 까지 했고(`copy2` 가 mtime 을 되돌려 낡은 `bin/` 이 도는 것을 이 저장소가 2026-09-18 에 겪었다), 원복 후 `git diff --stat` 이 **삽입 105 · 삭제 0** 으로 되돌림 흔적이 없음을 확인했다.

## 7. 두 검사를 다 두는 이유 — 중복이 아니다

같은 펜스가 둘 다에 걸리면 **둘 다 발화한다**. 실패의 **67/72** 가 예약어 별칭이고, 파싱 검사가 그 자리에 실을 수 있는 문구는 `'AS' 근처의 구문이 잘못되었습니다` 뿐이다 — 그것만 받은 모델은 **무엇을 고쳐야 하는지 모른다**. 앞 검사가 「대괄호로 감싸거나 이름을 바꾸십시오」와 **지목된 낱말**을 준다.

⇒ 한쪽은 **진단**, 한쪽은 **처방**이다. 이 중복을 결함으로 세지 않는다고 선언 §2 에 못박았고 여기서 다시 적는다.

## 8. 이 검사가 잡지 않는 것

- **파서와 SQL Server 가 100% 같다고 보증하지 않는다.** 이번 다섯 가족은 실물 SQL Server 2022 로 교차 확인했지만, ScriptDom 이 받고 SQL Server 가 거부하는(또는 반대) 모양이 남아 있을 수 있다. **대상 서버 버전도 모른다** — 코드는 `TSql160Parser` 를 쓰고 로컬 원천 넷이 `compatibility_level 160` 인 것만 확인했다.
- **파싱은 문법만 본다.** 없는 컬럼·타입 불일치·권한·미선언 변수는 밖이다(미선언 변수는 **의도적으로** 통과시킨다 — 앱이 파라미터를 넣는다).
- **이미 배송된 72 자리를 고치지 않는다.** 다음 판부터 막는다. 기존 산출물은 재생성으로만 닫히고 그것은 사람 결정이다.
- **명세서 경로(`Validate`)는 범위 밖이다.** 구현 전 측정에서 **명세서 31 편의 ```sql 펜스가 0** 이었다(mermaid 31 · 태그 없는 펜스 33). 걸 자리가 없어서 안 건 것이지 「안 재고 뺀 것」이 아니다.
- **조각 판정은 목록이다.** 문장을 시작할 수 있는데 목록에 없는 토큰이 있으면 **조각인데 안 걸러지는** 자리가 생긴다. 코퍼스 실측으로는 0 이다.

## 9. 다음

1. **배송된 72 자리의 처리는 사람 결정이다.** 재생성은 전건 비용이고, 이 검사는 재생성 없이 다음 판을 막는다.
2. **「SQL 유효성」 축의 두 번째 검사는 재료 층이 생긴다** — 존재하지 않는 컬럼 참조·타입 불일치는 스키마가 필요하고, 그 재료는 `output/offline_snapshot.json` 에 있다(축 A 감사에서 4,651 컬럼 · 불일치 0 으로 정합성을 확인해 뒀다).
3. **같은 물음을 단계 지시서에도 물어야 하는가** — 이번 검사는 계획서만 본다. 단계 파일의 SQL 펜스는 계획서에서 잘라 쓴 사본이라 **계획서를 막으면 사본도 막힌다**는 것이 앞 판독 §5 의 실측이었다. 그 전제가 앞으로도 성립하는지는 **재생성 때 다시 재야 한다**.

---

## 10. 이 회차에서 배운 것 하나

앞 선언은 **한 편**을 재고 「다른 구문 오류는 없다」로 닫았고, 이번 선언은 그것을 뒤집었다. 그리고 이번 판독은 **자를 한 번 틀렸다**(§3).

**두 오류가 같은 모양이다 — 「무엇을 분모로 잡았는가」를 문장에 안 적었다.** 앞 선언은 「325 펜스」를, 이번 스윕은 「줄이냐 펜스냐」를 적지 않았다. 적었으면 둘 다 그 자리에서 보였다.
