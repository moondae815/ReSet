## 0. 잰 것 — 배너의 축 이름이 사유를 말하지 않는다

「품질 불합격 — 예외 기준 미달」 배너가 매 판 붙는데 그 사유가 판독된 적이 없었다. 리뷰 JSON **23 개**(Job 10 편)를 전수로 읽었다.

| 축 | 평균 | 8 미달 |
| :-- | --: | :-- |
| 정합성 | 8.0 | 9/23 |
| CRUD | 9.0 | 3/23 |

| **예외** | 7.8 | **10/23** |
| 가독성 | 9.0 | 1/23 |

「예외」가 8 미달인 열 자리의 **실제 사유는 예외 처리가 아니다**. 네 가족으로 갈린다 — 통제 합계 이름 계약(B7·B8·B13·B17, K2 가족) · 트랜잭션 경계 파기(B18 1 차) · 배치 객체 이름 계약(B11) · 조인 키 오류(B8). 즉 Critic 은 **아무 축에나 감점을 싣는다**(축 이름은 사유가 아니다).

### B18 이 남긴 배너의 사유(이 회차의 자리)

B18 은 1 차의 트랜잭션 결함을 **2 차에서 닫았고**(예외 6 → 7, 총점 90 → 92) 배송본은 옳다 — S16·S17 이 `groupTx` 를 공유 문맥에서 받고 「자체 트랜잭션을 시작하거나 커밋하지 않는다」고 명시하며, 여는 것은 `controlConn`(저널·체크포인트) 뿐이다. 남은 감점 사유는 **「한 문서 한 표기」 위반**이다:

- 다중 행 조회가 세 이름으로 — `queryAll`(S01·S14·S18) · `queryMany`(S16·S19) · `query`(S12)
- 실패 저널 기록이 두 이름으로 — `writeFailureJournal`(대부분) · `markStepFailedInSeparateControlTransaction`(S07·S09)

**원인은 계약 공백이다.** 프롬프트는 의사코드 리포지터리 API 이름을 **아예 규정하지 않는다**(`AiService` 의 프롬프트 전문에서 `repository` 는 다른 규칙 한 줄에만 나온다). 그래서 모델이 단계마다 이름을 새로 짓고, Critic 이 그 산포를 감점한다.

## 1. 설계 — 계약으로 못박는다(검사는 이번에 만들지 않는다)

정본 이름을 **관측에서** 고른다(가장 많이 쓰인 것, 뜻이 다른 것은 남긴다):

| 연산 | 정본 이름 | 근거 |
| :-- | :-- | :-- |
| 문장 실행(쓰기·DDL) | `execute` | 610 회·7 편, 경쟁 이름 없음 |
| 스칼라 하나 | `queryScalar` | 71 회·5 편, 경쟁 이름 없음 |
| 행 여러 개 | `queryRows` | 37 회·4 편(최다) — `queryAll`·`queryMany`·`query` 를 대체 |
| 행 하나 또는 없음 | `queryRow` | 33 회·4 편(최다) — `queryOne`·`querySingle`·`queryRowOrNone` 를 대체(없을 수 있음을 계약에 적는다) |

- 싣는 자리: `AiService.AppendSharedStepContext`(단계·골격·단일 호출 폴백 **세 경로**가 함께 쓴다).
- 문구에 담을 것: 이 넷만 쓴다 · 같은 연산에 다른 이름을 만들지 않는다 · 저널·체크포인트 기록도 문서 안에서 한 이름으로 쓴다(이름은 모델이 고르되 **하나**여야 한다).
- **검사는 이번에 만들지 않는다.** 이유는 둘이다 — ① 이름 정확 대조 검사는 계약 **전에** 생성된 배송본 13 편 중 아홉 편에 발화해 스윕(내 회귀 기구)을 덮는다 ② B18 이 가르쳐 준 대로 **계약이 검사보다 앞선다**. 다음 판에서 계약이 듣는지 보고, 들으면 그때 회귀 방지용 검사를 붙인다(들지 않으면 그 검사에 실물 대상이 생긴다).

**범위 밖**: 저널·체크포인트 헬퍼 이름의 정본 지정(모델 자유, 한 이름만 요구) · 「인터페이스」 축 감점(11/23 으로 더 흔하다 — 다음 후보) · 이미 배송된 문서의 이름 통일.
