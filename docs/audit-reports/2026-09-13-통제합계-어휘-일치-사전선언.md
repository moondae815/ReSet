**작성 시점**: 2026-09-13, **구현 전**. 설계·착수 조건 실측·합격선을 코드보다 먼저 적는다.
**기준 커밋**: main `c4ff4aca` · 워크트리 `.worktrees/control-total`.

## 0. 결함 — `POQSettleBatch11` 배송본, Critic 만 잡았다

| 단계 | 표 | 통제명 |
| :--- | :--- | :--- |
| `S13` 원장 동결 통제 합계(쓰기) | `batch.BatchControlTotal` (계약 정본) | `CROSS APPLY (VALUES (N'LedgerRowCount', …), (N'TxAmt', …) …)` |
| `S20` 통합 정합성 검증(읽기) | `batch.ControlTotal` (계약 **별칭**) | `WHERE StepCode IN (N'S13', N'S20') AND ControlName IN (N'LEDGER_ROW_COUNT', …)` |

`S20` 은 `S13` 몫의 행을 **어떤 실행에서도** 못 찾는다. 스윕 발화 0, 판 안 하한 재생성 0.

## 1. 뿌리 — 재서 확인한 것

1. **목차가 계약 별칭을 적었다.** `S13`·`S20` 의 `TargetTables` 가 `batch.ControlTotal`. 목차를 따른 `S20` 은 별칭을 썼고,
   골격(`BatchControlTotal`·`N'LedgerRowCount'`)을 따른 `S13` 은 정본을 쓰면서 본문 13 행에 스스로 풀어 적었다 —
   「승인 단계 목록의 `batch.ControlTotal`은 논리 대상 명칭이며 … 실제 물리 대상은 `batch.BatchControlTotal`이다」.
2. **계약은 이 별칭을 이미 안다 — 배선이 0 이다.** `BatchControlContract` 의 `batch.BatchControlTotal` 에 `Aliases: ["ControlTotal"]` 과
   `FindAlias`(2026-08-24 `6cce1a8d`, 주석: 「별칭은 받아들일 것이 아니라 보고할 것이다」)가 있는데 **제품 코드 호출부가 0**, 단위 시험만 부른다.
3. T36(`CheckUndeclaredWriteTargets`)은 배송본 `B11/S13` 에서 이미 발화한다(「본문이 `BatchControlTotal`에 쓰는데 목차는 `ControlTotal`만」) —
   목차 결함이라 재생성이 못 고치고 배너로만 남았다. **옳은 단계가 고발당하고 틀린 단계(`S20`)는 조용하다.**
4. **단계 사이 통제명을 맞대는 검사는 없다.**

## 2. 분류 — 이 가족의 칸 전부

| 칸 | 무엇 | 층 | 기준(오라클) | 처치 |

| **K1** | 단계 SQL 이 계약 별칭 표를 참조 | 단계(`ValidateBatchStep`, `SafeCheck`) | 커밋된 계약 — 비순환 | 정본을 요구하는 하한 오류. 귀속 어휘는 원문 SQL 줄(작성 계약 9) |
| **K2** | 읽는 단계가 `StepCode = X` 몫으로 거르는 통제명이 단계 X 가 쓰는 통제명과 **하나도** 안 겹친다 | 문서(`ValidateControlStatusTerminalWrites` 옆, 오케스트레이터 합류) | 자기일관성 — 쓰는 쪽·읽는 쪽 둘 다 모델 산출(N12·T36 계열) | 읽는 단계 지목 |

**K0 만으로는 부족하다** — 이름은 정본이 돼도 `S20` 이 `LEDGER_*` 를 지어내면 여전히 영원히 불일치다. **K2 만으로도 부족하다** — 표 이름이 갈리면
같은 이름으로도 못 찾는다. 셋이 한 가족이다.

## 3. 착수 조건 ①②③ (실측 — 정규식 탐침, 최종 수는 제품 코드로 다시 잰다)

| | K0 | K1 | K2 |
| :--- | :--- | :--- | :--- |
| ① 행 수 (코퍼스 7 Job) | **1 Job · 2 단계**(B11 S13·S20) | **1 Job · 1 단계**(B11/S20, 펜스 안 3 곳 · 산문 5 곳) | **1 Job · 1 단계**(B11/S20, 통제명 5) |
| ② 도달 | 목차 전량 | SQL 펜스 전량 — 앵커 불필요 | SQL 펜스 전량 |
| ③ 자를 쓰는가 | `BatchControlContract.FindAlias` | 같다 | 쓰기 리터럴(`VALUES` 행 · `SELECT` 목록) ↔ 읽기 필터(`ControlName =`/`IN`, `StepCode =`/`IN`) |

**표본이 하나다.** 그래서 ⑤(오탐이 다수가 아니다)는 코퍼스로 거의 못 잰다. 대신:

- **음성 대조를 실물로** — `B4/S16`(자기가 쓴 이름을 자기가 읽는다) · `B10/S17`(`@p_controlName` 매개변수 쓰기) · `B8/S22`(리터럴 쓰기, 읽는 단계 없음) ·
  `B11/S13` 산문의 별칭 언급 2 곳(K1 이 산문을 보면 안 된다).
- **K2 는 보수적으로 좁힌다** — 쓰기 이름은 넓게(그 INSERT 문장의 리터럴 전부), 읽기 이름은 좁게(`ControlName` 필터만) 모은다.
  단계 X 의 쓰기에 매개변수 이름(`@…`)이 하나라도 있거나 리터럴 이름이 0 이면 X 에 대해 침묵한다. `StepCode` 리터럴 필터가 없는 읽기는 침묵한다.
  **발화는 「교집합이 비었다」일 때뿐이다** — 「일부만 겹친다」는 정당한 부분 비교일 수 있어 보고하지 않는다.
