## 0. 공통 규율

- **빌드·테스트는 이 격리 워크트리에서만.** 동료 세션(`reset-67`)이 같은 파일
  (`MechanicalValidator.cs`)의 **정화기 구역 `:6252~6300` 과 `VerificationBanner`** 를 만진다.
  내 구역은 `ValidateBatchStep` 계열과 파일 끝의 새 메서드다 — 겹치면 미리 알린다.
- 게이트는 **실패 0 · 건너뜀 0 · 경고 0.** 절대 통과 수는 게이트로 쓰지 않는다.
- **발화 수를 판정으로 쓰지 않는다. 새 발화는 전부 열어 본다.**
- **숫자를 맞추려고 아래 조건을 손보지 않는다.** 어긋나면 되돌린다.

## 1. 무엇을 잡는가

원본에서 **한 트랜잭션 안에 있던 일**이 이행에서 **서로 다른 단계**로 갈려,
**원본이 보장하던 원자성이 깨진 것**을 잡는다.

실물(`POQSettleBatch1`):

```
원본  UP_Util_Settle_Summary : BEGIN TRAN(23) … EXEC AcqManual(221) … EXEC SUMMARY_EXTRA(230) … COMMIT TRAN(239)
이행  S11 = Summary          S12 = AcqManual          S13 = SUMMARY_EXTRA      ← 셋이 각자 트랜잭션
```

**피호출자 둘은 자기 DDL 에 트랜잭션이 없다.** 언제나 호출자의 트랜잭션 안에서 돌았기
때문이다. 별도 단계로 승격되면서 **각자 커밋**하게 됐고, 뒤 단계가 실패해도 앞 단계는
이미 커밋돼 있다.

## 2. 오라클 — **원본 DDL 이다(비순환)**

기준값을 명세서에서 읽지 않는다. 명세서의 「트랜잭션 경계 표」도 같은 사실을 담지만
**모델이 전사한 것**이라 순환 위험이 있고, 재생성이 지우면 검사가 조용해진다.
**N5 가 §10 에서 정한 방향을 그대로 따른다** — 검사 때 `ddlByProcedure` 로 재파생한다.
그 통로는 **이미 뚫려 있다**(N5 가 만들었고 두 호출부가 넘긴다).
관련: [[check-oracle-provenance]]

## 3. 판정 — 구조만 본다. 산문을 읽지 않는다

호출자 SP `X` 와 그 단계에 대해:

1. `X` 의 DDL 이 **단일 `BEGIN TRAN` … `COMMIT TRAN`** 인가. 아니면 **침묵**(귀속 불가).
2. 그 구간 **안**에 `EXEC Y` 가 있는가. 없으면 **침묵**.
3. `Y` 의 DDL 에 **자기 트랜잭션이 없고** DML 이 있는가. 있으면 **침묵**
   (원래 독립 트랜잭션이었으니 갈라도 원자성이 안 바뀐다).
4. `allSteps` 에서 `Y` 가 **`X` 와 다른 단계**인가. 같으면 **침묵**(보존됐다).

넷이 다 참이면 **호출자 단계에 발화한다** — 원자성을 잃은 것은 호출자의 트랜잭션이므로
귀속도 호출자다. 발화 단위는 **피호출자 하나당 하나**.

**⚠ 산문은 오라클이 아니다.** `Batch1/S13:5` 가 「원본은 명시적 트랜잭션 없이 문장별
자동 커밋이었지만」이라 적는데 **이것은 거짓**이다(호출자 트랜잭션 안에서 돌았다).
이 거짓 문장은 결함이 진짜임을 **방증**할 뿐 판정 재료로 쓰지 않는다 — 분류표가
「공통 (다)를 기계로 잡으려 들지 마라」로 못박은 자리다(실측 오탐 15 중 14).

## 5. 되돌림 조건 — 하나라도 어긋나면 되돌린다

- **R1**: 코퍼스 발화가 **0** 이면 되돌린다. 재료가 안 닿은 것이다.
- **R2**: 발화가 **6 을 넘고 그 초과분이 오탐**이면 되돌린다.
- **R3**: **다른 검사(A~E·미분류)의 카운트가 변하면** 되돌린다. 재료 확장이 옆으로 번진 것이다.
  기준선은 `sweeps/2026-09-07-step-sweep-b.md` — **A 0 · B 2 · C 1 · D 0 · E 0 · 미분류 17
  (측정 쌍 50 · Job 3)**.
- **R4**: 검사를 되돌렸을 때 **사라지는 발화가 정확히 새 발화뿐**이 아니면 되돌린다.

## 6. ⚠ 가장 큰 위험 — 「분할이 의도일 수 있다」

규칙 3-1 이 제어 흐름을 앱으로 옮겼으므로, **앱이 세 단계를 하나의 트랜잭션으로 감쌌다면
결함이 아니다.** 그러면 검사가 봐야 하는 것은 「분할」이 아니라 **「감싸는 선언이 없다」**다.

**착수 전 관측(판정이 아니다)**: `Batch1` 의 S11·S12·S13 은 각각
**「Single-Transaction Shadow Swap」으로 자기 트랜잭션을 선언**하고, 세 단계를 잇는 상위
트랜잭션 선언은 본문에서 못 찾았다. S13 은 오히려 「4개 테이블 쌍 각각을 자신만의
트랜잭션으로 원자화한다」고 적는다.

**그러나 이것으로 판정하지 않는다** — 상위 감쌈이 단계 문서가 아니라 **공통 규약이나 앱
골격**에 선언돼 있을 수 있다. **⑤ 심사에서 `agent/common/`·`agent/src/` 를 먼저 열어
확인한다.** 거기에 감쌈이 있으면 **이 검사는 그대로 오탐이고 R2 로 되돌린다.**

## 7. 안 하는 것 (명시)

- **산문 판정 안 한다**(§3).
- **명세서의 트랜잭션 경계 표를 오라클로 쓰지 않는다**(§2). 다만 DDL 과 그 표가 어긋나면
  그것 자체가 별건의 전사 결함이므로 **관측만 하고 적는다.**
- **`EXEC` 를 동적 SQL 문자열 안에서 찾지 않는다.** 이번 재료에 실물이 없고, 넓히면
  N12 가 부딪힌 「텍스트 대조뿐」 문제를 그대로 들인다.
- **캐시 버전은 안 올린다** — 프롬프트 계약이 안 바뀐다(L1 만 조인다). 대신 스킬이 요구한 대로
  **코퍼스 전수 스윕의 전후 차분을 보고에 적는다.**

# §6 위험을 착수 전에 닫았다 (2026-09-07, 코드 전)

**「앱이 감쌌으면 결함이 아니다」를 실측으로 기각했다.** 사전 선언은 이 확인을 ⑤ 심사로
미뤄 뒀으나, 이것이 참이면 만들 이유 자체가 없으므로 **앞으로 당겨 쟀다.**

`output/Jobs/POQSettleBatch1/agent/src/AbstractSettleTasklet.cs` 가 답을 갖고 있다.

```csharp
public abstract class AbstractSettleTasklet : ISettleStep   // 단계 하나 = 태스크릿 하나
{
    public abstract string StepName { get; }
    protected abstract string SourceProcName { get; }        // 레거시 SP 하나에 대응
    public StepResult Execute(SettleContext context)
    {
        using var conn = context.MainDb.CreateConnection();  // 자기 커넥션
        …
        using var tran = conn.BeginTransaction();            // 자기 트랜잭션
        RunBusinessSteps(conn, tran, context, ref stateCode);
        tran.Commit();
        context.Checkpoint.MarkStepCompleted(StepName, context.Ymd);   // 단계 단위 체크포인트
```

**감쌈이 없다.** 세 단계는 각자 커넥션·트랜잭션·커밋을 갖는다. 공통 규약
(`01-step-contract.md`)도 트랜잭션을 **단계 안**에서만 다루고(`:38`·`:105`) 단계를 잇는
상위 경계를 정의하지 않는다.

**그리고 한 겹 더 나빠지는 것을 봤다** — `MarkStepCompleted` 가 **단계 단위**라,
S11 커밋 후 S12 가 실패하면 재시작이 **S11 을 건너뛰고 S12 부터** 재개한다. 원본은
그 지점에서 전체를 롤백했다. 이것은 발화 사유에 적을 것이 아니라 **결함의 크기**를
말해 주는 관측이다.

**그러므로 R2(오탐이 다수면 되돌린다)의 가장 큰 후보가 착수 전에 제거됐다.**
남은 오탐 축은 「구조 조건 넷이 참인데 실제로는 무해한 자리」이고, 그것은 만든 뒤
발화 전건을 열어 심사한다.
