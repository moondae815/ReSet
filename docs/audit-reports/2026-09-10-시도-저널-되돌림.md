# 배치 계획 시도 저널 — 통합 상태에서의 되돌림 (2026-09-10)

**계획서** `docs/superpowers/plans/2026-09-10-배치계획-시도-저널.md` §Task 6
**설계서** `docs/superpowers/specs/2026-09-10-배치계획-시도-저널-design.md` §7·§9(c)

Task 1~5(`PlanAttemptJournal` 클래스와 오케스트레이터 배선)는 각 태스크의 tip에서
개별적으로 되돌림을 했다. 이 문서는 **통합된 최종 상태에서 한 번 더** 배선 세 자리를
지워 실제로 빨개지는지 확인한 기록이다 — 「발화를 재는 자와 배선을 재는 자는 다른
축」이므로, 태스크마다 따로 잰 초록이 병합 뒤에도 유지되는지는 별개 질문이다.

## 0. 방법

`dotnet test --filter FullyQualifiedName~VerificationPipelineOrchestratorTests` 를
기준선으로 두고(213개), 배선 세 자리를 **하나씩** 주석 처리한 뒤 같은 필터로 재실행,
실패한 시험 이름과 단언 메시지를 그대로 기록했다. 각 실험 뒤에는 주석을 원복하고
`git diff --stat -- src/ tests/` 가 빈 출력임을 확인한 다음 다시 초록을 확인하고
다음 실험으로 넘어갔다.

기준선(제거 전):

```
통과!  - 실패:     0, 통과:   213, 건너뜀:     0, 전체:   213
```

## 1. (a) `RunStepAsync` 반환 직전의 `journal.RecordStepSection(...)`

`GenerateBySplitAsync`의 로컬 함수 `RunStepAsync` 안, `return new StepSectionResult(...)`
직전의 한 줄을 주석 처리했다.

**관측 — 예상과 다르다.** 계획서 Step 1은 "FAIL 1개"를 기대했지만, 실제로는 **시험
2개**가 실패했다.

```
실패!  - 실패:     2, 통과:   211, 건너뜀:     0, 전체:   213

[FAIL] RunConsolidatedPipeline_WhenTheOuterAttemptAdvances_ThePriorAttemptsSectionsSurviveOnDisk
  오류 메시지: Assert.NotNull() Failure: Value is null
  (line 2803: Assert.NotNull(s01AtOuterAttemptTwo);)

[FAIL] RunConsolidatedPipeline_WhenAStepFailsItsInnerFloorRetry_ThePriorDraftIsOnDiskBeforeTheNextTry
  오류 메시지:
   Assert.DoesNotContain() Failure: Sub-string found
                                  ↓ (pos 23)
   String: "## S01. 첫 단계\n\n(본문 없음 - 하한 미달)"
   Found:  "하한 미달"
  (line 2697: Assert.DoesNotContain("하한 미달", s01Final);)
```

**왜 둘인가.** 이 자리는 두 가지를 동시에 보장한다 — ① 외부 `attempt` 루프가 2로
넘어가기 *전에* 직전 회차의 단계 섹션이 디스크에 있어야 한다는 것(첫 번째 시험이
잰다), ② 하한 재시도가 남긴 「하한 미달」 중간 기록을 *최종 채택 본문이 덮어써야*
한다는 것(두 번째 시험의 마지막 단언이 잰다 — 주석에 "그 마지막 기록을 지워도 위
어서션들은 여전히 통과한다"고 미리 적혀 있던 바로 그 단언). 두 시험이 서로 다른
계약을 재고 있었을 뿐, 하나가 다른 하나를 대신 잡아 준 것은 아니다 — 실패 메시지의
성격이 다르다(하나는 "값이 없다", 하나는 "옛 값이 안 덮였다").

**이 자리만 재는가.** 예, 다른 시험 211개는 전부 그대로 통과했다. `dotnet test`
출력에 다른 클래스·다른 시험은 등장하지 않았다.

복구 후:

```
git diff --stat -- src/ tests/   →  (빈 출력)
통과!  - 실패:     0, 통과:   213, 건너뜀:     0, 전체:   213
```

## 2. (b) `GenerateStepSectionWithFloorRetryAsync` 안, 하한 미달로 다음 시도 직전의
   `RecordStepSection(...)`

**관측.** 계획서 Step 1의 기대(FAIL 1개)와 정확히 일치했다.

```
실패!  - 실패:     1, 통과:   212, 건너뜀:     0, 전체:   213

[FAIL] RunConsolidatedPipeline_WhenAStepFailsItsInnerFloorRetry_ThePriorDraftIsOnDiskBeforeTheNextTry
  오류 메시지: Assert.NotNull() Failure: Value is null
  (line 2682: Assert.NotNull(s01AtSecondAttempt);)
```

이 시험이 하한 재시도 도중(외부 `attempt`가 아직 1인 채로 내부 `maxTries` 루프가
두 번째 생성 호출을 시작하는 시점)에 디스크의 `steps/S01.md`를 들여다보는데, 이 자리를
지우면 그 시점엔 파일이 아예 없다.

**이 자리만 재는가.** 예. 위 (a)를 되돌렸을 때 함께 빨개졌던
`RunConsolidatedPipeline_WhenTheOuterAttemptAdvances_...`는 이번엔 통과했다 — 그
시험은 외부 회차 전환 시점만 보므로 내부 재시도 자리의 유무와 무관하다는 것이
확인된다.

복구 후:

```
git diff --stat -- src/ tests/   →  (빈 출력)
통과!  - 실패:     0, 통과:   213, 건너뜀:     0, 전체:   213
```

## 3. (c) `EnforceScoreThreshold` 직후의 `attemptJournal.RecordReview(attempt, l2Result)`

**관측.** 기대(FAIL 1개)와 일치했다.

```
실패!  - 실패:     1, 통과:   212, 건너뜀:     0, 전체:   213

[FAIL] RunConsolidatedPipeline_WhenAnAttemptIsRejected_ItsReviewIsOnDiskBeforeTheNextAttempt
  오류 메시지: Assert.NotNull() Failure: Value is null
  (line 2893: Assert.NotNull(firstReviewAtSecondAttempt);)

회차 2의 (이 폴백 경로에서는 유일한) AI 호출 시점에 `reviews/attempt-01.json`을
읽으려 하는데, 이 자리를 지우면 그 파일이 생기지 않는다.

**이 자리만 재는가.** 예. 다른 212개는 전부 통과했다.

복구 후:

```
git diff --stat -- src/ tests/   →  (빈 출력)
통과!  - 실패:     0, 통과:   213, 건너뜀:     0, 전체:   213

## 4. 결론

| 지운 자리 | 실제로 빨개진 시험 | 수 | 예상과 일치 |
| :--- | :--- | ---: | :--- |
| (a) `RunStepAsync` 반환 직전 | `…SectionsSurviveOnDisk` · `…ThePriorDraftIsOnDiskBeforeTheNextTry`(마지막 단언) | **2** | **아니오 — 계획서는 1개를 기대했다** |
| (b) 하한 재시도 안 | `…ThePriorDraftIsOnDiskBeforeTheNextTry`(첫 단언) | 1 | 예 |
| (c) 리뷰 기록 | `…ItsReviewIsOnDiskBeforeTheNextAttempt` | 1 | 예 |

세 자리 모두 지웠을 때 실동작이 빨개졌고, 각 실험에서 다른 시험이 대신 잡아 주는
사각지대는 없었다(가지마다 자기 시험이 있다). 다만 (a)는 계획서가 적어 둔 "FAIL 1개"
예상과 달리 **시험 2개**가 반응했다 — 그 자리가 서로 다른 두 계약(회차 전환 전
생존·재시도 중간 기록의 최종 덮어쓰기)을 동시에 지고 있기 때문이며, 이는 배선이
과소가 아니라 오히려 그 자리에 걸린 계약이 하나가 아니라는 뜻이다. 예상과 실측이
갈린 자리를 그대로 남긴다 — 이 저장소는 되돌려 보지 않은 초록을 믿지 않는다.

되돌림 실험 도중 임시로 주석 처리했던 세 줄은 모두 원복했고, 각 실험 직후
`git diff --stat -- src/ tests/`로 빈 출력을 확인했다. 이 보고서를 쓰는 시점의
전체 게이트는 §5(별도로 실행한) `dotnet test` 전체 스위트 결과를 참고하라 — 이
저장소의 유일한 허용 예외는 `AnchorKindOrdinalPairTests.EveryUAnchorPointsAtAStatementTheSpecActuallyDeclares`
(이 작업과 무관, 착수 전부터 실패 중인 베이스라인)뿐이다.
