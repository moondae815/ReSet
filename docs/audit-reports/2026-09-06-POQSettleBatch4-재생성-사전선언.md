## 1. 이 회차가 하는 일 — **비교가 아니라 산출물이다**

사용자 결정: 「결함 대장을 다듬는 것보다 **산출물을 새로 만드는 게 먼저**다. 산출물 생성이
너무 딜레이되고 있다.」 그러므로 **1급 산출은 세대 비교가 아니라 「새 산출물에 결함이 없는가」**다.

새 Job 이름으로 돌므로 **`POQSettleBatch1` 을 덮어쓰지 않는다** — 감사 기준선이 그대로 남고
`InstructionBundleWriter` 의 디렉터리 삭제 위험도 없다.

### ⚠ 혼입 하나가 실행 중에 실제로 들어갔다 (2026-09-06 13:5x 실측)

병행 세션이 **공유 체크아웃에서 `dotnet build` 를 여러 번 돌렸고**, 재생성이 바로 그 트리의
바이너리로 돌고 있었다. 프로세스는 살아남았으나(.NET 이 로드된 어셈블리를 버텼다)
**`bin/Debug/net10.0/appsettings.json` 이 프로세스 시작(≈12:47) 이후인 12:59:28 에 덮였다.**

그리고 `Program.cs:218-219` 가 두 설정 파일을 **`reloadOnChange: true`** 로 읽는다 —
덮인 설정이 **실행 중에 반영된다.**

| | 실측 |
| :--- | :--- |
| 모델 설정(`appsettings.local.json`) | **무사하다.** md5 가 소스와 같고 Actor·Consolidator `tencent/hy4-preview` · Critic `z-ai/glm-5.3` 그대로다 |
| `appsettings.json` | **그 세션 브랜치의 판으로 바뀌었다.** `3cb26a6d`(「tencent/hy4-preview 추가 및 Order 설정」) **이전**이라 `"tencent/hy4-preview": { "Order": [ "tencent" ] }` 가 **없다** |

**귀결**: OpenRouter 의 **공급자 고정이 풀린 채로 돈다.** 같은 모델 이름이라도 어느 공급자가
서빙하느냐에 따라 양자화·컨텍스트 한도·응답 성향이 다를 수 있다. 실행은 정상이다 —

것이다. **그러므로 이 회차의 산출물은 「공급자 미지정 라우팅」으로 만들어진 것이고, 재현하려면
그 사실이 필요하다.**

## 4. 사전 선언 — 무엇을 기대하고 무엇이 그것을 뒤집는가

**(1) 완주 [1급]** — 로그 마지막이 「번들 내보내기 완료」이고 `agent/steps/` 가 채워진다.
→ 거짓이면 쿼터·오류로 중단된 것이다. **중단본은 판정에 쓰지 않는다**(Batch3 처럼).

**(2) 알려진 결함 넷이 새 산출물에 없어야 한다 [1급]** — 자리는 Batch1 기준이고 새 산출물의
줄 번호는 다르다. **이름으로 찾는다.**

| | Batch1 의 실물 | 새 산출물에서 볼 것 |
| :--- | :--- | :--- |
| N12 | `S05` 캡처는 `TxAmt = 0` 을 포함하는데 `SQL_RESTORE_DELETE` 에 없다 | 섀도우 캡처 술어 = 복구 `DELETE` 술어인가 |
| T02 | `SELECT SUM(A.CLTotal) AS PostChkAmt1` — 원본의 `ISNULL(SUM(CAST(… AS MONEY)),0)` 에서 방어 둘 소실 | `PROC_ETC` 대사 두 자리에 `CAST`·`ISNULL` 이 있는가 |
| 회귀 A | 조인 키 `A.OrgYMD` → `A.YMD` | `INS_EXTRA` 계열 조인 키 |
| 회귀 B | `TClientCMRate` 조인에서 `MallID` 누락 | 같은 자리 |

→ **하나라도 남으면 「검사가 있는데 안 밀었다」이고, 그것이 이 회차의 부정 신호다.**

**(3) 기계 발화 [2급]** — 새 Job 의 검사 A~E 발화. **낮을수록 좋다는 뜻이 아니다** —
Batch1 이 발화 12 → 0 이면서 Critic 88 → 46 으로 갈린 전례가 있다.
**발화 0 을 품질로 읽지 않는다.**

**(4) 판정하지 않는 것**
- **`POQSettleBatch1` 과의 우열.** 모델이 셋 다 다르므로 차이를 규칙·검사 변화로 귀속할 수 없다.
- **축 B 46 건의 해소.** 그 셈은 Batch1 의 것이고 새 Job 에는 사람 감사 기준선이 없다.
- **`POQSettleBatch3`(중단본)의 무엇도.**

## 5. 판독 순서

1. **완주** — 로그 마지막 줄. `grep '생성 실패'` 는 계획서 본문의 오류코드 설명에 오탐한다.
2. **회차와 채점** — `(시도 N/6)` · L1 소진 회차가 있었나.
3. **알려진 결함 넷** — §4-(2) 를 이름으로 찾는다.
4. **스윕** — 새 Job 의 A~E·미분류. **재생성 전 보고서와 비교하지 않는다**(분모가 다르다).
5. **정합성 감사** — 축 A · 축 A 교차 · 축 B. 단위는 객체 하나·단계 하나다.
