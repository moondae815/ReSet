- **단계 안 하한 재생성**: `[INF]   * Sxx 단계가 하한 검사를 통과하지 못해 다시 생성합니다: …` — B20 로그 1904 행으로 확인했다.

어느 출처든 재생(`replay/`) 결과와 발화 집합을 대조한다 — 재생이 판 안에 없던 발화를 내거나 그 반대면 하네스부터 의심한다.

## 발견

### 1. 문서 단위 하한 위반의 사유가 지목 재생성 요청에 실리지 않는다 — 두 단계가 서로를 향해 엇갈렸다

**흐름**(로그 시각):

| 시각 | 사건 |
| :-- | :-- |
| 19:07~19:10 | S12 생성(첫 초안 모양 D → 단계 안 하한 재생성) · S19 생성 — S12 는 `Base*`/`Extra*` 10 이름으로 쓰고, S19 와 첫 골격의 검증 세트는 S12 몫을 `Ledger.*` 로 읽는다 |
| (1 회차 조립) | **단계 K2 ⑤ 가 S19 에 발화** → `stepFloorViolations[S19]`(배송본 하한 미달 배너의 원문과 같다) — **이 회차 안에서는 재생성하지 않는다** |
| 19:31:47 | 통합 L1: 세트 K2 ⑤ 2 → 골격 패치 → 세트가 `Base*` 로 맞춰져 **닫힘** |
| 19:44:27 | L2(glm) 결함 둘. (1) S12↔S19 통제명 — 처방은 「두 섹션 중 하나를 재작성하여 이름을 통일하라(예: S12가 Ledger.* 이름으로 기록하도록 수정하거나, S19가 Base*/Extra* 이름을 읽도록 수정)」 |
| 19:44:27 → 19:45:07 | **S12 재생성**(응답 19:45:07.031) — `Ledger.*` 5 이름으로 옮겨 감 |
| 19:45:07.064 → 19:46:04 | **S19 재생성** — `Base*`/`Extra*` 10 이름으로 옮겨 감 |
| 19:46:06 | 2 회차 L1: 세트 K2 ⑤ 2(이제 세트 `Base*` · S12 `Ledger.*`) → 골격 백지 재작성 → 제어표 컬럼 결함 → 보완 실패 → **1 차 채택** |

**원인 — 측정으로 확정한 것**:

1. **S12·S19 재생성은 순차였고 병렬이 아니었다**(S12 응답 수신 33 ms 뒤 S19 요청). 1 차 판독 보고에서 「동시 재생성」이라 적은 것은 **틀렸다** — 요청·응답 시각을 보기 전의 추정이었다.
2. **S19 재생성 요청은 새 S12 본문을 담지 않았다** — 새 S12 응답의 `Ledger.*` INSERT 줄 다섯이 S19 요청 본문(496,393 자)에 **0 회**. 단계 재생성 요청에 다른 단계 섹션 본문이 실리지 않는다(`### S` 헤딩 1 회는 목차).
3. **단계 K2 의 사유(「읽는 이름을 S12이(가) 쓰는 이름으로 맞추십시오」)가 S19·S12 재생성 요청 어디에도 없다**(「겹치는 이름이 하나도 없어」·「쓰는 이름으로 맞추십시오」 둘 다 0 회). 코드: `GenerateBySplitAsync` 가 지목 단계의 기록을 재생성 전에 지우고(`floorViolations.Remove(step.Code)`), 첫 시도 하한 피드백(`initialFloorFeedback`)으로는 **정의 안 된 SQL 블록 사유만** 넘긴다. 두 요청에 실린 것은 Critic 누적 피드백(양방향 처방) 하나다.

**뜻**: K2 의 설계 원칙은 「읽는 쪽이 쓰는 쪽에 맞춘다」(쓰는 쪽을 고정)인데, 그 방향이 재생성에 전달되지 않는다. Critic 처방은 두 방향을 모두 허락하고 두 단계를 다 열며, 각 단계는 상대의 새 본문을 못 본다 — **두 단계가 서로를 향해 한 칸씩 움직이면 어긋남이 뒤집힐 뿐이다.** 같은 경로를 타는 문서 단위 하한 검사는 K2 만이 아니다(분할 SP 의무 · T25 상태값 · K2 ⑥).

**처방 후보(사전 선언 후 착수)**: ① 지목 재생성 첫 시도 피드백에 그 단계의 **문서 단위 하한 사유**를 싣는다(지금은 지운다) ② 두 단계가 한 결함의 짝으로 함께 열리면 **K2 가 정한 쪽(읽는 쪽)만 열고 쓰는 쪽은 동결**하거나, 쓰는 쪽을 먼저 만든 뒤 그 본문을 읽는 쪽 요청에 싣는다. 합격선 후보: 이 판의 1 회차 상태(로그에 전부 있다)를 재료로 **요청 재생 실험**(판을 다시 돌리지 않고 S19 요청만 사유를 실어 다시 보내기) — 반복 N 회에서 S19 가 `Base*` 로 맞추는 비율.

### 2. 모양 D(`RowCount` 예약어) 가 같은 단계 번호에서 재발했다

B19 S12 에 이어 B21 S12 첫 초안도 `COUNT_BIG(*) AS RowCount` 로 써서 T-SQL 파싱이 실패했다(K2 는 「모름」으로 침묵). 이번에는 **단계 안 하한 재생성**(다른 사유 — `BatchStepJournal`)이 우연히 그 초안을 버려 배송되지 않았다. 표본 2 — 모델이 이 SP 의 집계 별칭에 `RowCount` 를 반복해 고른다. SQL Server 에서도 구문 오류라 **K2 가 아니라 구문 층의 결함**이다. 이를 보는 L1 검사가 있는지는 이 판독에서 확인하지 않았다.

### 3. 판본 쌍 전수 분류는 공존하지 않은 쌍을 만든다 — 이번엔 셋

G20 의 교집합 0 아홉 중 셋은 **서로 다른 회차의 판본끼리** 맞대진 인공물이었다(예: 2 회차 백지 골격 세트 `Ledger.*` × 1 회차 S12 `Base*` — 그 골격은 2 회차 S12 와는 맞았다). **판독 초안에서 이 분류를 한 번 틀렸다** — 「배송 세트 × 2 회차 S12」를 인공물로 셌는데, 패치된 세트는 2 회차에 그 S12 와 실제로 공존했고 2 회차 L1 이 그 쌍으로 발화했다. 판본의 `sources` 만 보고 가르면 틀리고, **회차 시각(로그 줄)으로 공존을 정해야 한다.** 이 도구의 수를 그 판정 없이 인용하면 결함을 부풀린다.

### 4. Critic 결함 (2) — 범위(스코프) 불일치는 L1 관할 밖

V12 가 동결값(`YMD = @p_businessYmd`)과 현재값(`YMD OR ProcYMD`)을 다른 범위로 비교해 추가정산 행이 있으면 거짓 불일치를 낸다. 이름은 맞으므로 K2 가 볼 수 없고, 이 모양(같은 지표의 두 계산 범위 대조)을 보는 L1 검사는 없다. 표본 1 — 기록만 한다.
