## 1. 실행 조건 — B20 과 같다

```
PLANONLY_MAX_L2_ATTEMPTS=1 PLANONLY_CONSOLIDATOR_PROVIDER=OpenRouter \
PLANONLY_CONSOLIDATOR_MODEL=openai/gpt-5.6-sol PLANONLY_OPENROUTER_ONLY_BACKEND=openai \
scripts/run-plan-only-job.sh POQSettleBatch21
```

실행 전 확인: `output/Jobs/POQSettleBatch21` 없음 ✔(2026-09-17 확인) · 실행 워크트리 깨끗함 · `appsettings.local.json` 연결 · 워크트리 HEAD 가 이 문서 커밋을 담은 main.

## 2. 측정 도구 — 판 전에 고정한다

K2 측정 하네스는 `.runs/2026-09-17-k2-probes/`(git 무시, README 포함)에 있다. 2026-09-17 두 회차에서 쓴 것을 파일로 옮겼고, **옮긴 스크립트가 그 회차 결과를 재현함을 확인했다**(B20 판본 23 해시 일치 · 판본 쌍 분류 교집합 0 8 · 부분집합 5 · 모름 5 · 일부 겹침 3).

| 도구 | 이 판에서 쓰는 곳 |
| :-- | :-- |
| `extract_versions.py … POQSettleBatch21` → `facts/` → `pairs.py` | Q1·Q2·Q5 — B21 의 배송본·디스크 시도본·**로그 응답 판본 전부**를 쌍으로 분류 |
| `snaps.py` → `replay/` | Q1 — 로그 시점 조립 스냅숏마다 단계 K2(⑤·⑥)를 돌려 판 안에서 **실제로 L1 에 보였을 발화**와 첫 등장 줄 |
| `k2sweep/` | G10 — 배송본·시도 조립본 K2 두 판 · 다른 Job 행 변화 0 |

판 안 L1 발화의 **원문**은 로그의 L1 오류문(`시도 N` 회차 메시지)에서 읽고, 재생 결과와 대조한다(재생이 로그에 없는 발화를 내거나 그 반대면 하네스부터 의심한다).

## 3. 예측

| # | 예측 | 틀리면 |
| :-- | :-- | :-- |
| P1 | 30~70 분 · $6~10 | 국면별로 적는다 |
| P2 | **⑥ 이 판 안에서 발화하면 전부 진짜다**(오탐 0) — 이 판의 핵심 물음. 발화 수는 예측하지 않는다(B20 1 회차 같은 모양이 다시 나올지는 모델 몫) | 오탐 하나라도 → 그 입력을 실물 픽스처로 옮기고 규칙을 좁힌다. **정당한 일부 겹침의 코퍼스 표본이 1 이었으므로 이 예측이 틀릴 가능성은 실재한다** |

## 4. 합격선

B19 의 G1~G14 를 그대로 쓴다(게이트 경고 0 은 `dotnet build --no-incremental` 로 따로 · K2 두 변종은 따로 부른다 · 시도 조립본은 제품 조립기로). B20 의 G15(순서 오라클 원문 판정)·G16(귀속 수렴)도 잇는다. 추가:

| # | 항목 | 합격 |
| :-- | :-- | :-- |
| G17 | ⑥ 판 안 발화 | 로그 L1 오류문의 ⑥ 문구(「그중 … 은(는) 어떤 단계도 쓰지 않는 이름」) **전수를 원문 판정** · 오탐 0 · 재생 결과와 발화 집합 일치 |
| G18 | ⑥ 수렴 | 발화마다 다음 회차에서 사라졌는가 · 사라지지 않았으면 같은 문구로 다시 났는가(루프) |
| G19 | CTE-UNION 도달 | 이 판의 제어 합계 쓰기 단계 전수 앎/모름 · 모름 전부 모양 분류(A~D) |
| G20 | 배송본 사후 감사 | B21 판본 쌍 전수 분류 · 교집합 0·일부 겹침 **전부 원문 판정** · 배송본에 남은 진짜 통제명 결함 0 |
| G21 | Critic 교차 | Critic 이 지적한 통제명·제어 합계 결함마다 「K2(⑤·⑥)가 같은 회차에서 잡았나 · 못 잡았으면 왜」 |

**표본이 없으면 표본 없음이라고 적는다** — 처방이 안 걸린 판을 「들었다」로 세지 않는다(B20 G15·G16 과 같은 규칙).
