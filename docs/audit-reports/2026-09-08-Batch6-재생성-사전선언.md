# `POQSettleBatch6` 재생성 — 실행 전 사전 선언 (비교 어휘를 먼저 못박는다)

**작성 2026-09-08.** 기준 커밋 `379e2b39`(main). **사람이 CLI 로 직접 돌린다.**
Job 이름을 새로 주어 **기존 산출물을 덮어쓰지 않는다** — 이 결정이 이 회차의 안전을 만든다.

## 0. ★ 왜 이 방식이 옳은가

2026-09-05 결정이 재생성을 미룬 가장 큰 이유가 **「재생성은 검사의 표본을 지우고 회수 불가」**
였다. 오늘 명세서 재생성에서 그것이 **실제로 일어났다** — 사라진 발화 7 의 신원을 못 밝혔다
(`2026-09-08-명세서재생성-발화감소-판독.md` §2).

**새 Job 이름은 그 문제를 통째로 없앤다.** `POQSettleBatch1`(2026-09-04 판)과
`POQSettleBatch6`(오늘 판)이 **나란히 남으므로**, 사라진 것도 새로 난 것도 **양쪽을 열어
확인할 수 있다.** 스냅샷이 필요 없다.

## 1. 실행

```bash
dotnet run --project src/ReSet.Cli -- \
  --sp dbo.UP_Util_PG_Client_CMRate_Ins,dbo.UP_UTIL_SETTLE_INS,dbo.UP_UTIL_SETTLE_CANCEL_INS,dbo.UP_UTIL_SETTLE_INS_EXTRA,dbo.UP_UTIL_SETTLE_INS_EXTRA4PLCARD,dbo.UP_UTIL_SETTLE_COMM_UPD,dbo.UP_UTIL_SETTLE_EXCEPTION_PROC,dbo.UP_UTIL_SETTLE_PROC_ETC,dbo.UP_UTIL_SETTLE_EXPECT_PROC,dbo.UP_Util_Settle_Summary,dbo.UP_UTIL_SETTLE_SUMMARY_ETC,dbo.UP_UTIL_STAT_PGCOLLECT_INS \
  --job-name POQSettleBatch6
```

**SP 는 12 개이고 순서가 Batch1 과 같다** — 그 순서가 단계 순서를 만들므로, 다르게 주면
단계 번호가 어긋나 비교가 어려워진다. `Summary_AcqManual`·`SUMMARY_EXTRA` 둘은
**폐포로 자동으로 따라온다**(`AnalyzeReferencedCodeObjects`) — 목록에 넣지 않는다.

## 2. 덮어쓰지 않는다는 근거

- **`InstructionBundleWriter` 의 디렉터리 삭제는 그 Job 자기 디렉터리 안에서만 일어난다.**
  `Jobs/POQSettleBatch6/` 는 새 디렉터리라 지울 것이 없다.
- **명세서는 캐시 적중이라 다시 안 써진다.** 오늘 동료 세션의 재생성에서 8 개 객체가
  캐시 적중으로 **2026-09-07 판을 그대로 유지한 것**이 그 증거다(`EXCEPTION_PROC` 포함).
  캐시 `FormatVersion` 은 이미 **{19} 단일**이다.

## 3. 지켜볼 것 — 오늘까지의 판독이 남긴 함정

| 함정 | 무엇을 보나 |
| :--- | :--- |
| **재시도 소진** | 로그의 `(시도 N/6)`. 6 회를 다 태우면 **검증 못 통과한 판이 배송된다** |
| **mermaid** | 동료 세션이 정화기를 고쳤다(엣지 라벨 따옴표). 그래도 발화가 나면 **오류 앞 세 줄(파스 에러+캐럿)** 을 본다 |
| **로그 섞임** | 다른 CLI 를 동시에 돌리면 로그가 한 파일에 끼어든다. 동료 세션이 `README` 에 그룹별 로그 디렉터리를 붙이는 중이니 **그 편집 뒤에 돌리는 편이 낫다** |
| **「완료」를 로그로 판정하지 마라** | 동료 세션이 오늘 그것으로 틀렸다. **산출물 자신의 `문서 작성일시`** 를 보라 |

## 4. ★ 비교 어휘 — **보기 전에 정한다**

끝난 뒤 내가 `Batch1`(09-04) 대 `Batch6`(09-08)을 비교한다. 어휘를 미리 갈라 둔다.

| | 뜻 |
| :--- | :--- |
| **닫힘** | Batch1 에 있던 결함이 Batch6 에서 **고쳐졌다** |
| **잔존** | Batch6 에도 **그대로 있다** |
| **소멸** | 그 자리(문장·절)가 Batch6 에 **없다** — 고친 것이 아니다 |
| **신규** | Batch6 에서 **새로 생겼다**(재생성이 만든 회귀) |

**「소멸」을 「닫힘」에 합치지 마라.** 2026-09-05 재감사에서 46 중 32 를 잘못 셀 뻔한 자리다.
**「신규」를 빠뜨리지 마라** — 그때 재생성이 결함 셋을 새로 만들었고 원본 DDL 로만 잡혔다.

## 5. 무엇이 닫혀야 하는가 — **예측을 미리 적는다**

오늘까지 고친 것 중 Batch6 에서 **닫혀야 마땅한 것**들이다. 안 닫히면 그 자체가 발견이다.

| 예측 | 근거 |
| :--- | :--- |
| **조인 키 회귀 둘** — `S05` 의 `OrgYMD`, `S06` 의 `MallID` | 검사 B 가 발화하고 `SuggestedPromptFix` 를 탄다 |
| **중복 투영 둘** — `S05` 의 `PGINCVTAX`·`CLINCVTAX` | `CheckDuplicateProjectionNames` 가 잡는다 |
| **청크 종료 조건** — `S02~S06` 의 `chunkRanges` | Few-Shot 을 `7feb3c54` 가 고쳤다 |
| **지역 변수 타입 계약** — `S05` 의 `@v_valIncVat` | 규칙 5-1 + Critic 짝 + L1 (`f1b653ab`) |
| **N6 트랜잭션 분할** | `PlanDefects` 로 지시가 간다. **다만 단계 경계 설계라 안 닫힐 수도 있다** |
| **T36 목차 누락** — `S16` 의 두 표 | 같은 이유로 `PlanDefects` |

**T25(`RunStatus='Failed'`)는 예측에 안 넣는다** — 문서 층 검사라 계획서 생성 경로에서
안 돌 수 있다. 닫히면 덤이다.

## 6. 게이트에 미치는 영향 — 미리 적어 둔다

Job 이 넷 → 다섯이 된다. **크기를 박은 단언은 없다**(확인함):
`LocalVariableTypeContractCorpusTests` 는 `jobsOnDisk == jobsMeasured`(모양)와
알려진 네 자리 `Contains`(존재)뿐이다.

- `PlanParseFailures == 0` — Batch6 의 목차를 못 읽으면 빨개진다.
- **`AnchorKindOrdinalPairTests`** — Batch6 이 앵커를 엉뚱한 `(Kind,서수)` 에 붙이면 빨개진다.
