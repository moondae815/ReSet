# 축 B — 재시도가 못 고치는 검사 B 발화 (사전 선언)

**작성 시점**: 2026-09-13, **측정 전**. 합격선과 예측을 결과보다 먼저 못박는다.
**기준 커밋**: `1ab28e9f` (main) · 격리 워크트리 `.worktrees/axis-b-measure` · `output/` 은 주 체크아웃 심링크.

## 0. 물음

검사 B(조인 키·술어 컬럼 대조)가 코퍼스 모든 Job 에서 2~3 건씩 발화하고, 판 안에서
재시도 예산(6회)을 다 써도 안 닫힌다(Batch9 S03 은 같은 자리에서 13 회). 이 문서는
**고치지 않는다.** 세 가지를 잰다.

1. 지금 발화 좌표 (`--sweep`)
2. 그 발화가 진짜 결함인가 검사의 오탐인가 — **비순환 오라클 = 원본 DDL**
3. 「재시도가 못 고친다」가 참이면, 결함이 들어오는 층은 어디인가
   (프롬프트 규칙 / Few-Shot 예시 / 명세서 추출기·재료 전달)

## 1. 순환 질문 — 「이 자가 보는 파일을 이 자가 만들었나?」

검사 B(`MechanicalValidator.CheckAnchoredStatementFacts`)가 읽는 파일은 둘이다.

| 입력 | 누가 만들었나 | 순환인가 |
| :--- | :--- | :--- |
| 단계 SQL `agent/steps/Sxx.md` | 생성 모델 | 피검 대상 — 순환 아님 |
| 명세서 `### DML 범위` 표의 「조인 키」 칸 | `DmlScopeExtractor.Extract(DDL)` 가 만들고 모델이 **전사**, L1 이 등호로 강제 | **검사가 만든 파일은 아니다.** 그러나 **형제 도구(추출기)의 산출물**이라, 추출기가 틀리면 검사는 **없는 결함을 고발한다**(check-oracle-provenance: 「추출기가 놓치면 고발한다」) |

그래서 판정의 기준을 명세서 표로 삼지 않는다. **원본 DDL 을 직접 열어** 그 조인 키가
그 문장의 **어느 스코프**(최상위 ON / 파생 테이블 안 / WHERE)에 있는지 줄 번호로 적는다.
명세서 표는 「검사가 무엇을 요구했나」의 기록으로만 쓴다.

재시도 층도 같은 질문을 받는다 — **재시도 피드백은 검사 B 자신의 메시지**다. 검사가
오탐이면 재시도가 「못 고치는」 것이 아니라 **고칠 것이 없는** 것이다. 그래서 2 를 3 앞에 둔다.

## 2. 단위 — 발화 수 옆에 항상 적는다

- **스윕 행**: 검사 × 조건(A 오늘 · B 캐시17 모사) × 좌표. 조건 둘이 같은 좌표를 두 번 센다.
- **좌표**: (Job, 단계, 문장 앵커, 누락 컬럼 집합). **단계 번호는 판마다 재배열되므로**
  (Batch6 판독) 판을 넘어 비교할 땐 **(SP, 문장 앵커, 누락 컬럼)** 을 키로 쓴다.
- **가족**: 같은 (SP, 문장 앵커, 누락 컬럼) 을 공유하는 좌표 묶음.
- **판 안 발화**: 파이프라인 로그의 시도별 발화. 배송본 결함 수가 아니다.

## 3. 예측 (측정 전)

| # | 예측 | 틀리면 뜻하는 것 |
| :-- | :--- | :--- |
| P1 | 스윕의 검사 B 좌표를 (SP, 문장, 컬럼) 으로 접으면 **가족 ≤ 4** 이고 각 가족이 **Job 셋 이상**에 걸친다. 「판마다 다른 단계로 옮겨 다닌다」는 **단계 번호 재배열**이지 결함 이동이 아니다 | 결함이 판마다 정말로 다른 자리에 난다 — 생성의 분산 문제다 |
| P2 | 발화 항목이 전부 `외부 조인 … LEFT OUTER` 를 동반한다(09-12 스윕 관측) | 가족마다 기제가 다르다 |
| P3 | 판정은 **안 적는다** — 오라클을 열기 전에 진짜/오탐을 예측하면 그 예측이 판독을 끈다 | — |

## 4. 합격선

### 4-1. 측정 1 — 좌표

| # | 합격 |
| :-- | :--- |
| M1-a | 스윕을 `1ab28e9f` 에서 돌리고 커밋·코퍼스 Job 목록·검사별 발화를 **단위와 함께** 적는다 |

| M1-c | 좌표를 (SP, 문장, 컬럼) 가족으로 접은 표 — P1 판정 |

### 4-2. 측정 2 — 진짜인가 오탐인가

| # | 합격 |
| :-- | :--- |
| M2-a | **가족마다** 원본 DDL 의 해당 문장을 줄 번호로 인용하고, 누락 컬럼이 원본의 **어느 스코프**에 있는지 적는다 |
| M2-b | 가족마다 이행 SQL 의 대응 문장을 인용하고, 그 컬럼이 **있는가 · 어디 있는가 · 없는가** 를 적는다 |
| M2-c | 판정은 넷 중 하나: **진짜 결함** / **오탐-추출기**(명세서 표가 원본과 다른 스코프를 요구) / **오탐-검사**(표는 맞는데 검사가 이행의 동치 모양을 못 읽음) / **판정 불가**(무엇을 재야 푸는지 함께 적음) |
| M2-d | 판정 근거가 명세서 표뿐인 행은 **0** 이어야 한다 |

### 4-3. 측정 3 — 재시도가 정말 못 고치는가, 어느 층인가

M2 가 「진짜 결함」인 가족에만 한다. **오탐 가족은 여기서 멈추고 검사·추출기 층으로 넘긴다.**

| # | 합격 |
| :-- | :--- |
| M3-a | 판 로그(Batch8·Batch9)에서 그 가족의 **시도별 궤적**을 뽑는다 — 발화 여부 · 피드백 문구 · 다음 시도에서 그 문장이 바뀌었나 |
| M3-b | **첫 생성 축**을 만든다: `--probe-anchors` 와 같은 모양으로, 해당 단계만 `floorFeedback=null`·`previousBody=null` 로 **한 번씩** 생성하고 검사 B 를 그 산출물에 돌린다. 판 하나(3~4 시간) 대신 단계 수 × 1 호출 |
| M3-c | 첫 생성에서 이미 결함이면 층은 재시도 앞이다. 층을 가르는 대조군을 **재료 층부터** 잰다 — ① 모델 입력(실제 프롬프트)에 그 조인 키가 **실렸나**(명세서 표·`PromptContextScope Narrow` 절단) ② 실렸다면 규칙 블록에 조인 키 보존 조항이 **양 경로**(`GenerateBatchStepSectionAsync`·`ConsolidatedPlanRules`)에 있나 ③ Few-Shot 에 **그 모양**(파생 테이블 + 최상위 `LEFT OUTER JOIN`)의 예시가 있고 그 예시가 키를 보존하나 |
| M3-d | 층 판정은 **입력을 한 가지씩 바꾼 첫 생성 비교**로만 확정한다. 코드 판독으로 「이 층이다」라고 적지 않는다 — 판독은 가설까지다 |
| M3-e | 표본이 작으면 작다고 적는다. 첫 생성 1 회로 「안 듣는다」는 말하지 않는다 — 분산을 가를 만큼(최소 단계당 3 회) 돌리거나 보류로 적는다 |
