# 계약 밖 batch 표의 컬럼 계약 분열 검사 (사전 선언)

**작성 시점**: 2026-09-16, **구현 전**. **코드**: main `9c6bb10b`.
**계기**: GPT 판 교차 분류가 「판 안에서 못 고치고 배송된 진짜 결함」으로 남긴 마지막 가족이다 — 제어 테이블 계약 분열(B11 · B13, 실행 불가, 기계 검사 없음, Critic 만 잡았다).

## 0. 실물

`POQSettleBatch13` 배송본: S18 이 `batch.BatchReconciliation` 을 만들고 V15 가 그 표를 읽는데 **컬럼 집합이 겹치지 않는다.**

```sql
-- 8835 행(S18)  CREATE TABLE batch.BatchReconciliation
--   RunId, StepCode, ReconciliationName, ExpectedValue, ActualValue, DifferenceValue, IsMatched, CheckedAtUtc
-- 10390 행(검증 SQL 세트 V15)
SELECT CheckCode, CheckName, ResultStatus, DifferenceCount, DetailMessage
  FROM batch.BatchReconciliation WHERE RunId = @p_runId AND ResultStatus = N'FAIL';
```

다섯 컬럼 중 **하나도 정의에 없다** — 배포하면 컬럼 없음 오류이고, S19 의 게시 전제(`FAIL 없음`)를 평가할 수 없다. 1 차 Critic 이 잡았는데 2 차가 골격을 통째로 다시 써 점수가 떨어져 **채택이 그 수정을 버렸다**(`2026-09-13-GPT-2회판-Batch13-사전선언.md` G10).

## 2. 설계

- **자리**: `ValidateConsolidated`(문서 층). 정의(S18 섹션)와 참조(검증 SQL 세트)가 **다른 절**에 살기 때문에 단계 검사로는 볼 수 없다. `SafeCheck` 로 감싸고 감싼 자리 수 10 → 11 로 올린다.
- **오라클**: 문서 자신의 `CREATE TABLE`(자기일관성). 계약 표(`BatchControlContract`)는 제외한다 — 그 컬럼은 계약이 정하고 K1·어휘 검사의 관할이다.
- **판정**: 계약 밖 `batch.*` 표에 `CREATE TABLE` 이 **하나 이상 있을 때만** 본다. 정의 컬럼은 그 표의 모든 `CREATE TABLE` 과 `ALTER TABLE … ADD` 의 **합집합**(보수적).
  참조는 (가) 단일 테이블 `FROM` 질의의 컬럼 참조 (나) `INSERT … (컬럼 목록)`. 테이블이 둘 이상인 질의는 비한정 컬럼의 소속을 말할 수 없어 **침묵**한다(작성 계약 7).
- **발화**: 표마다 한 번, 정의에 없는 컬럼을 모아 적는다. 문구는 사실만 — 「`batch.X` 를 읽는 문장이 그 표 정의에 없는 컬럼 `…` 을 씁니다. 이 문서가 정의한 컬럼은 `…` 입니다 — 배포하면 컬럼 없음 오류입니다.」
- **귀속**: 참조가 단계 절 안이면 `OwnerStepCode`, 절 밖(검증 SQL 세트·골격)이면 `Lexemes` 에 **그 컬럼이 있는 원문 줄**(작성 계약 9 — 고정 문구의 백틱이 멀쩡한 단계를 열지 않게).
- **범위 밖(기록)**: 같은 표를 서로 다른 두 `CREATE TABLE` 로 정의하는 것(코퍼스 0 — 합집합으로 삼켜진다) · 정의 없이 참조(위 §1) · 동적 SQL 안의 문장(리더가 못 본다) · `SELECT *`.
- **캐시**: 프롬프트 불변 · L1 만 조인다 → 캐시 버전은 올리지 않고 **스윕 차분**으로 기존 산출물이 새 기준을 통과하는지 보인다(그 차분이 B13 1 건이어야 한다).

**오탐 방향**: 새 발화를 만드는 변경이므로 오탐이 곧 재생성 낭비다. 그래서 침묵 조건 넷(계약 표 · 정의 없음 · 다중 테이블 · 동적 SQL)을 시험으로 먼저 못박고, 배송본 도달을 1 로 제한한 상태에서 붙인다.
**거부된 시도 코퍼스**: 이 검사는 처방문(「…하십시오」)을 담으므로, 그 처방을 따른 텍스트가 새 오탐을 만들 수 있다. 처방은 「정의를 고치거나 조회 컬럼을 정의에 맞추라」이고 둘 다 SQL 변경이라 산문 오탐 경로가 없다 — 그래도 재생성 뒤 로그의 발화를 다음 판에서 읽는다.
