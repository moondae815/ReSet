## 3. 오탐 0 을 어떻게 확인했나 — 검사 판정 = SQL Server 판정

코퍼스 전수 스윕(계획서 **19 편**)에서 **지목된 낱말이 둘뿐**이다: `RowCount` · `Exists`.

그 둘과, 코퍼스에 흔한 정상 별칭 일곱을 **실물 SQL Server 에 물었다**:

| 낱말 | SQL Server |
| :-- | :-- |
| `RowCount` · `Exists` | **거부** — `Incorrect syntax near the keyword …` |
| `RowCnt` · `TotalAmount` · `SnapshotName` · `ControlName` · `TableName` · `Amount` · `Ymd` | **전부 통과** |

**검사가 지목한 것은 실물이 거부하고, 지목하지 않은 것은 실물이 받는다.** 오탐 0 은 추정이 아니라 교차 확인된 값이다.

## 4. 예상 밖이 셋 — 전부 「오라클을 파서로 삼은」 결정에서 나왔다

### 4-1. B23 만의 문제가 아니었다 — 19 편 중 14 편

선언은 B23 의 48 자리를 겨냥해 썼다. 스윕을 돌리니 **발화 문서 14/19 · 고유 줄 74** 다.

**이것은 「모델이 최근에 나빠졌다」가 아니라 「이 가족이 내내 있었는데 아무도 안 봤다」다.** 지금까지 어느 층도 SQL 의 문법 유효성을 묻지 않았다 — 기계 확정 표 검사들은 **표의 셀**을 보고, SQL 거처 검사들은 **SQL 이 앱으로 옮겨졌는가**를 본다. **「그 SQL 이 컴파일되는가」를 묻는 자가 없었다.**

### 4-2. `AS Exists` — 손으로 적은 목록이었으면 놓쳤다

`POQSettleBatch5` 가 `) THEN 1 ELSE 0 END AS Exists;` 를 담고 있었다. 나는 `RowCount` 만 보고 설계에 들어갔고, **예약어 목록을 손으로 적었다면 `Exists` 를 넣을 생각을 못 했을 것이다.**

선언 §3 이 「손으로 적은 목록은 빠뜨려 못 잡거나 넓어서 오탐한다」고 적고 파서를 고른 이유가 여기서 실물로 증명됐다. **값은 검사가 더 잡은 것이 아니라, 내가 몰랐던 것을 잡았다는 데 있다.**

### 4-3. 타입 문맥 제외 장치가 필요 없었다

선언 §3 에 「`CAST(x AS INT)` 의 `INT` 는 별칭이 아니므로 `CAST`·`CONVERT` 문맥을 제외한다」고 적고, 구현에서 그 제외를 넣으려 했다. **재 보니 불필요했다** — `INT`·`VARCHAR`·`DECIMAL` 은 T-SQL 예약어가 아니라 파서가 알아서 거른다.

**오라클을 파서로 두면 내가 예외를 손으로 관리할 자리가 줄어든다.** 문서 주석에 없는 헬퍼(`IsTypePositionAs`)를 참조해 둔 것을 구현 중에 걷어냈다 — 쓰지도 않을 장치를 계약처럼 적어 둘 뻔했다.

## 5. 배선 — 선언의 걱정은 기우였고, 그래도 재길 잘했다

선언 §8 이 「48 줄이 어느 경로를 타는지 모른다 · 없으면 경로마다 걸어야 한다」로 열어 두었다. 실측 결과:

- **계획서가 전부를 담는다.** `agent/` 아래 24 자리의 줄이 **24/24 계획서에도** 있고 계획서의 개수도 정확히 24 다. **배송본 48 = 계획서 24 + 잘라 쓴 사본 24.**
- **분할 경로와 단일 호출 폴백이 같은 변수에 대입된 뒤 한 자리를 탄다** — `consolidatedPlan = splitMarkdown ?? aiResult.Content` → `ValidateConsolidated`. 2026-09-08 의 「분할 경로를 죽였는데 잠금 12/12 가 초록」 함정이 **이 자리에는 없다.**

⇒ **호출 자리 하나로 48 전부가 덮인다.** 기우였지만, 적어 두었기에 **확인하고 넘어갔다** — 적지 않았으면 「아마 다 덮이겠지」로 지나갔을 자리다.

## 6. 되돌림 — 효력과 배선을 따로 쟀다

| 층 | 되돌린 것 | 결과 |
| :-- | :-- | :-- |
| **효력** | 검사 본문을 `if (hits.Count >= 0) return;` 로 무력화 | **3 실패** |
| **배선** | `SafeCheck(() => CheckReservedWordAliasInSql(...))` 호출 줄 삭제 | **3 실패** |
| 원복 | `cp` 뒤 **`touch` 까지** | **9/9 초록** |

**둘을 따로 잰 이유**: 발화를 재는 시험은 검사가 **아예 안 불려도** 같은 값을 낼 수 있다. 이 저장소가 2026-09-10 에 「`if` 블록을 통째로 지워도 빌드와 나머지 시험이 전부 초록」인 사각지대를 겪었다. 이번엔 배선 되돌림이 따로 빨개진다.

**`touch` 를 빼먹지 않은 이유**: `cp` 가 mtime 을 되돌려 낡은 `bin/` 이 도는 것을 이 저장소가 2026-09-18 에 겪었다.

## 8. 이 검사가 잡지 않는 것

- **`AS` 없는 별칭** — `SELECT COUNT(*) RowCount` 도 같은 오류인데 이 규칙이 못 본다. **코퍼스에 그런 자리가 있는지 아직 안 쟀다.**
- **다른 구문 오류 일반** — 펜스 단위 전체 파싱 검사는 **의도적 조각**(교정본 WHERE 스니펫)에 오탐하므로 만들지 않았다. 실측에서 진짜 구문 오류는 예약어 별칭 하나뿐이었다(14 중 12, 나머지 2 가 그 조각이다).
- **이미 배송된 74 줄** — 이 검사는 **다음 판부터** 막는다. 기존 산출물은 재생성으로만 닫히고 그것은 별도 결정이다.
- **명세서 경로(`Validate`)** — 축 A 산출물에는 안 걸었다. 명세서의 SQL 은 원본 DDL 인용이라 예약어 별칭이 나올 자리가 다르다. **재지 않았다.**

## 9. 다음

1. **`AS` 없는 별칭을 코퍼스에서 센다.** 있으면 같은 검사의 규칙을 넓힌다 — 새 검사가 아니다.
2. **기존 74 줄의 처리는 사람 결정이다.** 재생성은 전건 비용이고, 이 검사는 재생성 없이도 다음 판을 막는다.
3. **이 자리는 「SQL 유효성」 축의 첫 검사다.** 같은 축에 올 수 있는 것: 존재하지 않는 컬럼 참조, 타입 불일치 — 둘 다 스키마 재료가 필요하고 이번 검사와 달리 재료 층이 생긴다.
