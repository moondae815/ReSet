## 2. 착수 전 측정이 판독의 처방 후보를 기각했다

축 A 판독 §6-② 가 적어 둔 것:

> (나) L1 검사로 「실행 의미 표에 NULL 잔존 행이 있는데 반환 계약 절에 NULL 이 0 회인가」. **(나)가 되돌림으로 검증 가능하다** — `UF_GET_ROUND4VAT` 이 그 검사의 양성 대조군이다(지금 0 회다).

**두 군데가 틀렸고, 둘 다 실물을 열어야 보였다.**

| 적힌 것 | 실측 |
| :-- | :-- |
| `UF_GET_ROUND4VAT` 이 양성 대조군 | 그 편은 실행 의미 표에 **대입 행이 0**(DB 배치 한 줄뿐)이라 **전건이 거짓**이다. 그 편의 NULL 문제는 대입 경로가 아니라 **인자 NULL → 반환 NULL** 이라 재료가 다르다 |
| NULL 0 회로 재면 된다 | 🔴 `UF_GET_EXTRACOMM4CLIENT` 는 산문에 NULL 을 **5 회** 쓴다. 안 쓴 곳이 반환 계약 절이다. 게다가 **실행 의미 표 자신이 「무결과 시 NULL이 그대로 남습니다」를 담으므로** 문서 전수 대조는 **구조적으로 0** 을 낸다 |

대입 행이 있으면서 산문 NULL 0 회인 편은 **3**, 문서 전체 0 회는 **2** — **🔴 셋 중 0 개**다.

⇒ **처방 후보를 그대로 구현했으면 게이트도 스윕도 초록인 채 겨냥을 통째로 놓쳤다.**

## 4. 16 ≠ 14 — **자가 아니라 예측의 근거가 틀렸다**

선언 §4 의 결정 규칙은 「적으면 전건이 좁다 — 구현을 멈추고 자를 고친다」였다. 멈추고 열어 보니 **빠진 두 편이 정당하게 침묵**했다.

| 편 | 왜 침묵했나 |
| :-- | :-- |
| `UF_GET_COMM4CLIENT4INTEREST` | 「조회 대상 행이 없어 대입이 일어나지 않으면 **초기값 `0`이 그대로 반환됩니다**」 — **이 검사가 원하는 바로 그 문장이다** |
| `UIF_SettleYMD` | 「`OutYMD` — `varchar(8)`, **NULL 허용**」 — 컬럼 속성 서술이 어휘에 걸렸다 |

**전자는 내 예측의 전제가 틀린 것이다.** 선언은 「지금 계약을 지킨 편이 0 이므로 16」이라 적었는데, **한 편이 이미 지키고 있었다.** 재지 않고 「0 일 것」이라 썼다.

**후자는 검사가 놓친 자리다.** 「NULL 허용」은 **컬럼의 nullable 속성**이지 **무결과 귀착**이 아니다. 어휘 매칭의 한계이고, **오탐이 아니라 미탐**이다 — §7 에 적는다.

> 결정 규칙이 「자를 고쳐라」였는데 실제로 고칠 것은 **예측의 근거**였다. 규칙이 가리킨 곳과 원인이 있던 곳이 달랐고, **멈춰서 열어 봤기 때문에** 그것이 보였다.

## 5. 캐시 버전 — **같은 날 반대 결정을 두 번 했고, 둘 다 맞다**

| 회차 | 바꾼 프롬프트 | 그 경로가 이 캐시를 타는가 | 결정 |
| :-- | :-- | :-- | :-- |
| 검증 세트 역할 표기 (`350a8912`) | **계획서** | **안 탄다** — `RunConsolidatedPipelineAsync` 1747 줄에서 `_cacheManager` 사용 **0 회** | **안 올린다** |
| 반환 귀착 계약 (이번) | **명세서** | **탄다** — `IsCacheValid` 가 명세서를 건너뛴다 | **22 → 23** |

스킬 규정은 「프롬프트가 바뀌면 올려라」 하나다. **그 규정이 전제하는 것은 「바뀐 프롬프트가 그 캐시를 탄다」이고, 그 전제는 회차마다 다르다.**

두 주석(`CacheManager.cs` v23 · `CacheManagerTests`)에 **서로를 가리키게** 적었다 — 다음 사람이 한쪽만 보고 기계적으로 적용하지 않도록.

## 6. 되돌림 네 층

| 층 | 되돌린 것 | 빨개진 시험 |
| :-- | :-- | :-- |
| **효력** | 본문 조기 반환 무력화 | **5** — 양성 넷 + 귀속 |
| **배선** | `SafeCheck` 줄 삭제 | **8** — 위 5 + 개수 게이트 셋 |
| **전건** | 「대입 행이면」을 「빈 칸이 아니면」으로 | **2** — 순수 연산 함수 침묵 시험 + **`InputDefects_ShouldNotBecomeValidationErrors`** |
| **스코프** | 반환 계약 절 대신 문서 전체 | **2** — 「산문엔 NULL 이 있으나 반환 계약엔 없는」 시험 둘 |

### 전건 층의 예상 밖

`SpecExpectationsTests.InputDefects_ShouldNotBecomeValidationErrors` 가 함께 빨개졌다. 전건을 넓히면 순수 연산 함수 전량이 고발되고, **「입력 결함이 검증 오류가 되면 안 된다」는 반경 밖 탐지기가 그것을 잡는다.**

### 스코프 층이 잡은 것이 🔴 의 실제 모양이다

스코프를 문서 전체로 벌리자 빨개진 둘이 정확히 `ReportsAReturnContractThatStopsAtTheHappyPath` 와 `ReportsEvenThoughTheDocumentMentionsNullElsewhere` 다 — **§2 에서 기각한 처방 후보가 바로 이 상태**다. 되돌림이 그 기각을 시험으로 고정했다.

## 7. 이 검사가 못 하는 것

- **어휘 매칭의 한계 — `UIF_SettleYMD` 가 「NULL 허용」으로 통과했다.** 컬럼 속성 서술과 무결과 귀착을 기계가 못 가른다. **미탐이고, 좁히면 오탐이 된다.** 결합을 넓게 잡은 대가다(선언 §4-1).
- **결론의 참·거짓은 안 본다.** 「무결과 시 0 을 반환합니다」라고 적으면 통과한다. 그것이 참인지는 **원본 DDL 만이** 안다.
- **가족 (A) 23 을 닫지 않는다.** 🔴 셋 중 직접 닿는 것은 **하나**(`UF_GET_EXTRACOMM4CLIENT`)다. `EXPECT_PROC` 둘은 **호출자 쪽 서술**이라 3-2 절 서술 금지 축이고, 이 검사 밖이다.
- **`UF_GET_ROUND4VAT` 의 NULL 은 이 검사 밖이다.** 대입 행이 0 이고 문제는 **인자 NULL → 반환 NULL**(실행 프로브로 확정)이다. 전건을 넓혀 잡으려 하면 §6 의 두 시험이 빨개진다.
- **모델이 새로 쓸 문장에 대한 오탐은 못 쟀다.** 재생성 로그의 `(시도 N/6)` 오류가 유일한 후속 증거다.
- **이미 배송된 14 편을 고치지 않는다.** 캐시 인상에 따른 재생성이 닫고, **그 실행은 사람 결정이다.**

## 8. 다음

1. **명세서 31 편 전건 재생성** — 캐시 v23 이 강제한다. 앞 실측 기준 **54분** 내외. **사람 승인 뒤에 돌린다.**
2. **그 판에서 반드시 읽을 것**: 시도별 L1 오류. 이 검사가 오탐하면 그 자리에서 6 회를 태운다.
3. **재생성 뒤 축 A 를 다시 돌려 (A) 가족을 재라.** 23 중 몇이 닫혔는지가 이 처방의 효력이고, **지금 주장할 수 있는 것은 「14 편이 고발된다」뿐이다.**
4. **`UIF_SettleYMD` 의 약한 통과**를 그 판에서 다시 봐라 — 재생성 뒤에도 같은 문장이면 검사가 아니라 **계약이 그 자리를 안 덮는 것**이다.

## 9. 이 회차에서 배운 것 하나

앞 회차의 배움이 「규정이 덮는 범위가 내 변경을 포함하는가를 적어라」였다. 이번은 그 이웃이다.

**판독에 적어 둔 처방 후보도 「아직 안 잰 것」이다.** §6-② 의 두 문장은 감사 당시의 **추정**이었고, 실물을 열자 둘 다 틀렸다. 그것을 그대로 구현했으면 **게이트도 스윕도 초록인 채 겨냥을 놓친 검사**를 배송했다.
