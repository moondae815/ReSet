# T25 가 INSERT 의 위치 값을 못 본다 — 측정·설계·합격선 (구현 전)

**작성 시점**: 2026-09-14, **구현 전**. 코드: 브랜치 `fix/t25-positional-insert`(main `0e2fafd6` + Batch14 판독).

## 0. 계기

POQSettleBatch14 배송본 S01 에 「하한 미달」 배너: 「`batch.BatchRun` 의 `RunStatus` 에 계약이 확정한 상태값 `Running` 을 이 Job 어느 단계도 기록하지 않습니다」.
S01 은 `INSERT INTO batch.BatchRun (JobName, BatchYmd, RunStatus, …) VALUES (N'POQSettleBatch14', @p_batchYmd, N'Running', …)` 로 **위치로** 기록한다.
`ValidateControlStatusTerminalWrites`(T25)는 쓰기를 `CountStatusAssignments` — `RunStatus = N'Running'` 대입 모양 — 로만 센다. **오탐이다.**

## 1. 측정 — 코퍼스 10 Job 배송본(`agent/steps`)

| Job | T25 발화 | 진위 |
| :-- | :-- | :-- |
| B1 · B4 | S01 `Failed` | 참(이 검사를 만든 결함 — `RunStatus` 에 `Failed` 를 쓰는 곳이 대입·INSERT 어디에도 없다) |
| B5 | S00 `Failed` | 참(같은 이유) |
| **B14** | **S01 `Running`** | **오탐** — 위치 INSERT 로 쓴다 |
| B7 · B8 · B10 · B11 · B12 · B13 | 0 | — |

B1·B4·B5 의 `RunStatus`·`StepStatus`·`CheckpointStatus` 위치 INSERT 를 전수로 보니 넣는 값은 `Running`·`Pending` 뿐이고 **`Failed` 는 0** — 고친 뒤에도 참 발화 셋은 남는다.

## 2. 설계

- 상태값 「씀」 = 기존 대입(`컬럼 = N'값'`) **또는** `INSERT … (컬럼 목록) VALUES (…)` · `INSERT … SELECT …` · `MERGE … WHEN NOT MATCHED THEN INSERT (…) VALUES (…)` 에서 **그 컬럼 위치의 문자열 리터럴**.
- 펜스마다 최상위 세미콜론 문장으로 자르고 ScriptDom 으로 읽는다(`RunGateFacts.WrittenStepCodes` 와 같은 방식). 조각이 파싱되지 않으면 그 조각의 위치 값은 세지 않는다.
- **같은 세는 법이 발화 조건(「같은 값을 다른 상태 컬럼에는 쓴다」)에도 쓰인다** — 넓히면 새 발화가 생길 수 있다. 전후 코퍼스 차분으로 잰다.
