# `IF EXISTS` 가드 술어 표류 — 측정 (구현 전)

**작성**: 2026-09-13 · 기준 main `f101b80d` · 코퍼스 8 Job(Batch1·4·5·7·8·10·11·12). 코드는 한 줄도 바꾸지 않았다.

## 0. 계기

`POQSettleBatch12/S03` 이 원본 `UP_Util_PG_Client_CMRate_Ins` 20~24 행의 기지급 사전 차단

```
IF EXISTS(SELECT PLTID FROM TSettleMst WITH(NOLOCK)
          WHERE YMD = @pi_strYMD AND OutState IN (1,5) AND OutYMD IS NOT NULL)
```

을 `… WHERE PLTID = 1 AND YMD = @p_ymd AND OutState IN (1, 5) AND OutYMD IS NOT NULL` 로 옮겨 **차단이 사실상 꺼진 채** 배송됐다.
Critic 만 잡았다. 물은 것: **우연인가 가족인가, 그리고 어느 층인가.**

## 1. 분모 — 원본 가드 전부

원본 DDL 14 편의 `IF [NOT] EXISTS (…)` 를 괄호 짝으로 뽑았다. **SP 4 편 · 가드 5 개**, 전부 `SELECT PLTID FROM TSettleMst`.

| SP | 행 | 원본 WHERE |
| :--- | ---: | :--- |
| `CMRate_Ins` | 20 | `YMD = @pi_strYMD AND OutState IN (1,5) AND OutYMD IS NOT NULL` |
| `SETTLE_INS` | 25 | 같은 모양 |
| `SETTLE_INS` | 39 | `YMD = @pi_strYMD` |
| `INS_EXTRA` | 30 | `ProcYMD = … AND YMD >= @v_strReqYMD AND OutState IN (1,5) AND OutYMD IS NOT NULL AND PGName IN (…) AND ISNULL(CompanySalesType,4) IN (0,1,2,3) AND ExtraSettleFlag = 1` |
| `INS_EXTRA4PLCARD` | 19 | `ProcYMD = … AND YMD = … AND OutState IN (1,5) AND OutYMD IS NOT NULL AND ISNULL(CompanySalesType,4) IN (0,1,2,3) AND ExtraSettleFlag = 1` |

## 3. 다른 가드 — GPT 두 판

| 판 | 가드 | 이행 | 판정 |
| :--- | :--- | :--- | :--- |
| B11·B12 | `SETTLE_INS` 25·39 | 원본대로 | — |
| B11·B12 | `INS_EXTRA4PLCARD` 19 | 원본대로 | — |
| B11 | `INS_EXTRA` 30 | `ISNULL(OutYMD, '') <> ''` (원본 `OutYMD IS NOT NULL`) | **뜻 변경** — `''` 을 원본은 포함하고 이행은 뺀다. 결함인지는 데이터 의존 |
| **B12** | **`INS_EXTRA` 30 (S10)** | **`OutYMD <= @p_currYmd`** (원본 `OutYMD IS NOT NULL`) | **표류 — 조건 뜻 변경**(미래 지급일 행을 뺀다). 컬럼 집합은 같아 컬럼 대조로는 안 보인다 |

정규식 대조기가 낸 나머지 차이(B1·B7 `SETTLE_INS` 39 의 「추가 OUTSTATE·OUTYMD」)는 한 SP 의 두 가드가 같은 번역에 짝지어진 **대조기 한계**다.

## 4. 층 — 무엇을 재서 알았나

| 후보 | 관측 | 판단 |
| :--- | :--- | :--- |
| **명세서 산문** | 로직 흐름(312 행)·mermaid(412 행) 모두 조건 셋을 정확히 적었다. PLTID 는 조건에 없다 | 원인 아님 |
| **명세서 CRUD 표** | `CMRate_Ins` 는 `PLTID, YMD, OutState, OutYMD` 를 **역할 없이** 한 칸에 적었다. GPT 가 옳게 옮긴 `INS_EXTRA4PLCARD` 는 컬럼마다 행을 두고 `PLTID` 를 「존재 여부 확인용 **SELECT 목록 컬럼**」이라 적었다. 다만 `SETTLE_INS`·`INS_EXTRA` 도 역할 없이 적었는데 표류가 없었다(그 SP 본문은 PLTID 를 청크 키 등으로 널리 쓴다) | **정황** — 단독 원인이라고 못 한다 |
| **기계 확정 표** | 가드 있는 명세서 4 편 **전부** `### DML 범위`·`### 집합 술어` 에 `IF` 행이 **0**(잠금 힌트 표에만 있다). 그런데 CRUD 절 머리말은 「각 행의 WHERE 술어 상세는 `### DML 범위`, `### 집합 술어` 표에 문장 단위로 확정」이라 적는다 — **가드 조건을 확정한 표가 없는데 있다고 가리킨다** | **재료 공백** — 모델에게는 산문뿐이다 |
| **생성 모델** | 같은 재료로 claude-cli 3/3 원본대로, GPT 2/2 표류 | **모델 민감성** — GPT 가 이 공백에 약하다 |
| **기계 검사** | 검사 C(원본에 없는 최상위 술어)는 명세서 행이 없는 문장을 대조하지 못한다. 앵커 술어 대조도 가드를 모른다. 판 안 발화 0 | **사각** |

## 5. 착수 조건 (가드 술어 대조 검사를 만든다면)

| | 값 |
| :--- | :--- |
| ① 행 수 | 원본 가드 5 · 코퍼스 대조 쌍 42(단계×가드) · 확인된 표류 **3**(B11/S05 · B12/S03 · B12/S10) + 판정 보류 1(B11 `ISNULL(OutYMD,'')`) |
| ② 도달 | 가드 번역 모양이 셋이다 — `EXISTS (SELECT …)` · `SELECT TOP 1 …` · `SELECT COUNT(1) …`. 셋 다 `FROM TSettleMst` + 원본 가드와 겹치는 항으로 짝을 찾아야 한다 |
| ③ 오라클 | **원본 DDL** — `ValidateBatchStep` 이 이미 `ddlByProcedure` 를 받는다(`CheckLocalVariableTypeContract`·`CheckTransactionSpanSplit`). 정규화는 `DmlScopeExtractor.PredicateTermsOf`(R1~R6: 한정자·변수 `@V`·IN 정렬)를 **원본과 이행이 함께** 쓴다 — 앵커 술어 대조와 같은 규칙 |

**단계 검사라 1 회 판에서도 판 안 재시도로 고쳐진다** — Critic 지적과 달리.

## 6. 보증하지 않는 것

- 표본이 작다(GPT 판 2). 「GPT 가 이 가드에서 늘 표류한다」가 아니라 「두 번 다 났다」다.
- `B11` 의 `ISNULL(OutYMD, '') <> ''` 는 데이터(`OutYMD` 에 `''` 이 들어가는가)에 달려 판정하지 않았다.
- 명세서 CRUD 표의 역할 없는 나열이 원인인지는 **재지 않았다** — 재려면 같은 재료로 칸만 바꾼 첫 생성 비교가 필요하다.

# 설계와 합격선 (구현 전)

## 검사 `CheckGuardPredicateTerms` — 단계 층, `SafeCheck`

**오라클**: 원본 DDL(`ddlByProcedure`, 파이프라인·스윕 둘 다 넘긴다). 단계의 `LegacyProcedures` 각각의 DDL 을 파싱해
`IF [NOT] EXISTS (SELECT … FROM <표> WHERE …)` 가드를 모은다.

**이행 쪽 후보**: 단계 SQL 펜스를 토큰 기반으로 문장 분할(`StepSqlStatementReader.SplitAtTopLevelSemicolons`)·파싱해,
**존재 확인 모양**의 질의만 본다 — ① `EXISTS (…)` 부질의 ② `SELECT TOP (1) …` ③ `SELECT COUNT(…)` 한 열. FROM 이 **표 하나**이고 가드와 같은 표.

**맞대기**: 원본과 이행 WHERE 를 **같은 함수** `DmlScopeExtractor.PredicateTermsOf` 로 항 정규화(R1~R6). 원본 `컬럼 = 리터럴` 은
이행 `컬럼 = @V` 와도 맞는다(R7). 조인 등식·오케스트레이션 변수 항은 뺀다(형제 `CheckAnchoredStatementPredicateTerms` 와 같다).
후보마다 같은 표 가드 중 **공통 항이 가장 많은** 것과 짝짓고, 짝으로 인정하는 조건은 **공통 항 ≥ max(2, 가드 항 수 − 1)** —
다른 목적의 질의(사후 검증 등)를 가드로 오인하지 않게 좁힌다. 그 대가로 **항이 하나뿐인 가드(`SETTLE_INS` 39 행)는 보지 않는다.**

**발화**: 짝의 **추가 항** 또는 **빠진 항**이 있으면. 한 단계에 가드마다 오류 하나. 추가 항의 컬럼이 원본 가드의 SELECT 목록 컬럼이면
「SELECT 목록 컬럼은 조건이 아니다」를 덧붙인다. 원본 조건으로 되돌리라는 처방이라 **따르면 항상 원본과 같아진다.**
