# 무결과·NULL 경로의 최종 귀착을 계약으로 — 사전 선언

**작성**: 2026-09-19 · **코드**: `main` `ec83d106`
**겨냥**: 축 A 의 가장 넓은 가족 (A) — **23 자리**(함수 11 · SP 8 · 교차 4), **🔴 3 이 전부 여기**
**판독**: `docs/audit-reports/2026-09-19-B23-정합성감사-축A-판독.md` §6-②

---

## 0. 물음

**명세서가 「무결과일 때 이 변수는 무엇이 되는가」를 말하게 할 수 있는가. 그리고 그것을 기계가 잴 수 있는가.**

---

## 1. 착수 전 측정 — **판독의 처방 후보가 겨냥한 것을 못 잡는다**

분모는 **명세서 31 편**이다. 자를 두 번 고쳤다(§1-4).

### 1-1. 재료는 있다

| 실행 의미 표(기계 확정)의 「종류」 | 행 수 |
| :-- | --: |
| **비집계 대입** | **52** |
| DB 배치 | 31 |
| 식 타입 경로 | 26 |
| **집계 대입** | **10** |
| 커서 수명 · 루프 내 재설정 · `@@ROWCOUNT` | 3 · 3 · 1 |

**대입 행을 가진 편은 16 / 31.** 판독 §6-② 의 「재료는 이미 실행 의미 표에 있다」는 **맞다.**

### 1-2. 그런데 거처가 없고, 이름이 갈려 있다

대입 행을 가진 16 편의 「반환」 절:

| | 편 |
| :-- | --: |
| 반환 절이 **아예 없다** | **7** |
| 있다 | 9 |

그 9 편의 절 이름이 **여섯 가지**다 — `반환 계약` 3 · `반환값` 5 · `반환 값` 1 · `반환코드(@po_intRetVal) 매핑` 1 · `3. 결과 반환 (라인 160)` 1. 문서 전체로 넓혀도 「반환 계약」 문구가 나오는 편은 **6 / 31** 이다.

### 1-3. **판독의 처방 후보 (나)를 그대로 만들면 🔴 셋을 하나도 못 잡는다**

판독 §6-② 가 적은 것:

> (나) L1 검사로 「실행 의미 표에 NULL 잔존 행이 있는데 반환 계약 절에 NULL 이 0 회인가」. **(나)가 되돌림으로 검증 가능하다** — `UF_GET_ROUND4VAT` 이 그 검사의 양성 대조군이다(지금 0 회다).

**두 군데가 틀렸다.**

| 틀린 것 | 실측 |
| :-- | :-- |
| 「`UF_GET_ROUND4VAT` 이 양성 대조군」 | 그 편은 실행 의미 표에 **대입 행이 0** 이다(DB 배치 한 줄뿐). **전건이 성립하지 않아 그 검사에 안 걸린다.** 그 편의 NULL 문제는 대입 경로가 아니라 **인자 NULL → 반환 NULL** 이라 재료가 다르다 |
| 「NULL 0 회로 재면 된다」 | 🔴 `UF_GET_EXTRACOMM4CLIENT` 는 산문에 **NULL 을 5 회** 쓴다. 안 쓴 곳은 **반환 계약 절**이다. 문서 전수로 재면 안 걸린다 |

대입 행이 있으면서 산문에 NULL 이 0 회인 편은 **3**, 문서 전체로 0 회는 **2** — **🔴 셋 중 0 개**다.

### 1-4. 자를 두 번 고쳤다

1. `UF_GET_ROUND4VAT` 와 `EXPECT_PROC` 둘을 열고 「실행 의미 표는 DB 배치만 담는다」고 단정할 뻔했다. 31 편으로 재니 **비집계 대입 52 · 집계 대입 10** 이 있었다. **두 편으로 31 편을 말할 뻔했다.**
2. 「NULL 언급」을 문서 전수로 셌다. 그 자로는 🔴 이 안 걸린다 — **절을 좁혀야** 한다.

---

## 2. 그래서 설계를 바꾼다 — **절을 만들라가 아니라 절이 무엇을 말하라**

`UF_GET_EXTRACOMM4CLIENT` 는 **반환 계약 절이 이미 있다.** 그런데 거기에 NULL 이 없다. 「절을 신설하라」만으로는 안 닫힌다.

### 세 층

| 층 | 자리 | 무엇을 |
| :-- | :-- | :-- |
| **생성 ①** | 명세서 프롬프트 | 반환 절의 이름을 **`### 반환 계약`** 하나로 못박는다(지금 여섯 가지) |
| **생성 ②** | 같은 프롬프트 | **실행 의미 표에 대입 행이 있으면** 그 절이 **각 변수의 무결과·NULL 귀착을 한 문장으로** 적게 한다. 「계산된 금액을 반환합니다」에서 멈추지 말 것 |
| **강제** | `MechanicalValidator.Validate` | 대입 행이 있는데 **`### 반환 계약` 절이 없거나, 있는데 그 절이 무결과·NULL 귀착을 말하지 않으면** 고발한다 |

**전건이 「대입 행이 있다」인 것이 중요하다.** 순수 연산 함수(`UF_GET_ROUND4VAT`)는 대입 행이 없어 전건이 거짓이고, 그 편의 문제는 이 검사의 축이 아니다 — **§7 에 적는다.**

## 3. 도달 범위 — 23 중 어디까지인지 먼저 적는다

| 가족 (A) 의 자리 | 이 처방이 닿는가 |
| :-- | :-- |
| 🔴 `UF_GET_EXTRACOMM4CLIENT` — 무결과 NULL 이 반환 계약에 없다 | **닿는다.** 이 검사의 정중앙이다 |
| 🔴 `UP_UTIL_SETTLE_EXPECT_PROC` ×2 — 호출자가 함수 반환을 「공백」이라 서술 | **직접은 안 닿는다.** 호출자 문서의 서술 문제이고 3-2 절 서술 금지 축이다. 다만 `UF_GET_OUTYMD4REFUND` 의 반환 계약이 「무결과 시 NULL」을 명시하면 **호출자를 쓸 때 참조할 재료가 생긴다** — 간접 효과이고 **이번에 측정하지 않는다** |
| 🟠 `UP_UTIL_SETTLE_INS` · `STAT_PGCOLLECT_INS` | **미정.** 대입 행 보유 여부가 갈린다(전자 0 · 후자 0) — **안 닿을 가능성이 높다** |
| 함수 11 쪽 🟡·⚪ | 대입 행 보유 16 편과 겹치는 만큼 닿는다 |

⇒ **「23 을 닫는다」고 주장하지 않는다.** 주장하는 것은 **🔴 하나 + 함수 쪽 다수**이고, 나머지는 축이 다르다.

## 4. 예측과 결정 규칙 — 결과를 보기 전에 적는다

| 지표 | 예측 | 이것이 아니면 |
| :-- | :-- | :-- |
| 코퍼스 **발화 편수** | **16**(대입 행 보유 전량 — 지금 계약을 지킨 편이 0 이므로) | 적으면 전건이 좁다 · 많으면 대입 행 판정이 틀렸다. **둘 다 구현을 멈추고 자를 고친다** |
| 발화 편에 **`UF_GET_EXTRACOMM4CLIENT` 포함** | **포함** | 빠지면 이 처방이 자기 겨냥을 놓친 것이다 |
| **`UF_GET_ROUND4VAT` 은 침묵** | **침묵**(대입 행 0) | 발화하면 전건이 헐겁다 |
| 다른 검사 발화 수 | **전부 그대로** | 하나라도 움직이면 남의 자리를 건드린 것이다 |
| 게이트 | 실패 0 · 건너뜀 0 · 경고 0 | 하나라도 어기면 병합하지 않는다 |

### 4-1. 오탐을 잴 수 있는가 — **이번에는 부분적으로 가능하다**

앞 회차(검증 세트 역할)는 음성 표본이 코퍼스에 **없었다**. 이번은 다르다 — **반환 계약 절을 이미 가진 편이 3** 이고, 그중 `UF_GET_COMM4CLIENT4INTEREST` 는 **NULL 을 한 번도 안 쓴다**. 즉 **「절은 있는데 귀착을 안 말한 편」이 실재**한다.

그래도 **「모델이 새로 쓸 문장」에 대한 오탐은 못 잰다.** 처방문을 따른 문장이 거부된 시도 코퍼스에 아직 없기 때문이다(작성 계약·스킬의 경고). 결합을 넓게 잡는다.

| 층 | 무엇을 | 합격 |

| **절 탐색** | `### 반환 계약` 대신 문서 전체에서 NULL 을 찾게 | **「산문에는 NULL 이 있으나 반환 계약에는 없는」 시험**이 빨갛다 — §1-3 이 실측한 🔴 의 모양이다 |

## 6. 캐시 버전 — **이번에는 올린다. 관할을 확인했다**

앞 회차에서 「프롬프트가 바뀌면 올려라」를 **관할을 안 보고** 적용할 뻔했고, 그때는 계획서 경로라 캐시를 안 타서 **안 올렸다.**

**이번은 명세서 프롬프트이고 `CacheManager` 가 바로 그 캐시다.** `VerificationPipelineOrchestrator` 가 `IsCacheValid` 로 명세서를 건너뛰므로, **안 올리면 캐시 적중 편에서 이 검사가 영영 안 돈다.**

`main` 이 **22** 이므로 **23** — 인상 **직전에 `main` 을 다시 본다.** 그리고 **스윕을 인상 전에** 돌린다.

**인상은 명세서 31 편 전건 재생성을 부른다. 그 실행은 사람 결정이다.**

## 7. 이 선언이 보증하지 않는 것

- **가족 (A) 23 을 닫는다고 주장하지 않는다**(§3). 🔴 셋 중 직접 닿는 것은 **하나**다.
- **`UF_GET_ROUND4VAT` 의 NULL 문제는 이 검사 밖이다.** 그 편은 대입 행이 0 이고, 문제는 **인자 NULL → 반환 NULL**(실행 프로브로 확정)이다. **전건을 넓혀 그것까지 잡으려 하면 순수 연산 함수 전량이 고발된다** — 별도 축이고 재료가 다르다.
- **호출자 쪽 서술은 안 본다.** `EXPECT_PROC` 의 🔴 둘은 3-2 절 서술 금지 축이다.
- **귀착의 옳고 그름은 안 본다.** 「무결과 시 0 을 반환합니다」라고 적으면 검사는 통과시킨다. **그것이 참인지는 원본 DDL 만이 안다.**
- **모델이 새로 쓸 문장에 대한 오탐은 못 쟀다**(§4-1). 재생성 로그의 `(시도 N/6)` 오류를 읽는 것이 유일한 후속 증거다.
- **이미 배송된 명세서를 고치지 않는다.** 캐시 인상에 따른 재생성이 닫고, 그 실행은 사람 결정이다.
