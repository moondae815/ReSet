## 3. 채택 결정

### 3-0. 축 1·2 만으로는 셋이 동시에 통과한다 — 진짜 동점

「채택 축 셋」의 앞 둘(현행판 오탐 == 0, 결함판 발화 > base(현행)×any = 7)을 표의 열두 행에
그대로 적용하면 **다음 셋이 동시에 통과한다.**

| 후보 × 규칙 | 결함판 발화 | 현행판 오탐 | 축 1·2 |
| :--- | ---: | ---: | :--- |
| base(현행) × majority | 9 | 0 | 통과 |
| base + 부호반전 × majority | 9 | 0 | 통과 |
| base + 별칭.컬럼 × majority | 10 | 0 | 통과 |

축 1·2는 이 셋을 갈라내지 못한다 — **형식 게이트만 보면 진짜 동점**이다. 계획서 원문(Fix Round 0
시점)은 두 갈래(발화 미증가 / 오탐 발생)만 기각 사유로 인정했고, 이 동점을 가를 셋째 축을
명시하지 않았다. Fix Round 1에서 계획서가 축 3(토큰0 잔량 최소)을 추가해 이 동점을 공식 판단
기준 안으로 들여왔다.

### 3-1. 축 3 적용 — 토큰0 잔량이 가장 작은 것을 고른다

| 후보 × 규칙 | 토큰0 잔량 | 축 3 |
| :--- | ---: | :--- |
| base(현행) × majority | 27 (그대로) | 최대 — 탈락 |
| base + 부호반전 × majority | 24 | 중간 — 탈락 |
| base + 별칭.컬럼 × majority | **18** | **최소 — 채택** |

**채택: `base + 별칭.컬럼` 후보 + `majority`(과반) 규칙.** 축 1·2를 통과한 셋 중 토큰0
잔량이 가장 작다(18 < 24 < 27) — 축 3이 유일하게 가른다(동률 아님, 재상정 불필요).

- 결함판 발화 10 > base(any)=7, 현행판 오탐 0 — 축 1·2를 만족한다.
- 대조가능이 25 → 34로 늘고 토큰0이 27 → 18로 줄어든다. 즉 새 후보가 순수 컬럼 산술
  갱신 9건을 "토큰이 아예 없어 비교 불가"에서 "토큰이 있어 판정 가능"으로 옮긴다 —
  이 태스크가 노리는 사각지대(토큰 0, 설계서 §2 ②)를 실제로 줄이는 후보다.
- 규칙을 `any`에서 `majority`로 바꾸는 것은 새 토큰(별칭.컬럼)이 단계 문서 어디에나
  흔하게 등장하기 때문이다(설계서 §3 A-2가 미리 경고한 위험). `any`로는 이 후보가 오히려
  발화를 죽인다(아래 표 참고) — `majority`로 바꿔야 처음으로 결함판 발화가 늘면서
  현행판 오탐이 0으로 유지된다.

### 기각한 후보와 사유 (행 전부)

| 후보 × 규칙 | 결함판 발화 | 현행판 오탐 | 기각 사유 (해당 축) |
| :--- | ---: | ---: | :--- |
| base(현행) × all | 13 | **1** | 축 1 — 현행 판에 오탐이 남 |
| base(현행) × majority | 9 | 0 | 축 1·2 통과(3-0의 동점 셋 중 하나) → **축 3 탈락**: 토큰0 27(그대로, 최대) — 별칭.컬럼×majority(18)에 밀림 |
| base + 별칭.컬럼 × any | **4 < 7** | 0 | 축 2 — 발화가 안 늘어서(오히려 줄었다: 설계서가 경고한 그대로, `any` 규칙에서 흔한 토큰을 보태면 "토큰 하나라도 있으면 통과"가 더 쉽게 성립해 발화가 죽는다) |
| base + 별칭.컬럼 × all | 17 | **1** | 축 1 — 현행 판에 오탐이 남 |
| base + 구조토큰 × any | **0 < 7** | 0 | 축 2 — 발화가 안 늘어서(`any` 규칙에서 구조토큰이 섞이며 발화가 0으로 붕괴) |
| base + 구조토큰 × all | 13 | **1** | 축 1 — 현행 판에 오탐이 남 |
| base + 구조토큰 × majority | **2 < 7** | 0 | 축 2 — 발화가 안 늘어서(과반 규칙이어도 구조토큰 자체가 대상 표현식과 잘 안 겹쳐 발화를 못 늘림) |
| base + 부호반전 × any | **7 = 7 (증가 아님)** | 0 | 축 2 — 발화가 안 늘어서(기존 base(any)와 동률이라 "발화 증가" 조건을 만족하지 못함) |
| base + 부호반전 × all | 13 | **1** | 축 1 — 현행 판에 오탐이 남 |
| base + 부호반전 × majority | 9 | 0 | 축 1·2 통과(3-0의 동점 셋 중 하나) → **축 3 탈락**: 토큰0 24 — 별칭.컬럼×majority(18)보다 사각지대 해소 폭이 작음 |

정리하면 기각 사유는 세 갈래로 갈린다.

- **축 1(현행 판에 오탐이 나서)** 기각: base(현행)×all, 별칭.컬럼×all, 구조토큰×all, 부호반전×all — 넷 다 예외 없이 현행판 오탐 1
- **축 2(발화가 안 늘어서)** 기각: 별칭.컬럼×any, 구조토큰×any, 구조토큰×majority, 부호반전×any
- **축 1·2는 통과했으나 축 3(토큰0 잔량)에서 밀려서** 기각: base(현행)×majority(토큰0 27), 부호반전×majority(토큰0 24) — 이 둘과 채택된 별칭.컬럼×majority(토큰0 18)가 **§3-0의 진짜 동점**을 이룬다

`all`(전량) 규칙은 네 후보 전부에서 예외 없이 현행판 오탐 1을 낸다 — 규칙 자체가 이 코퍼스와 안 맞는다.

## 4. 채택 후보의 토큰0 잔량

채택한 `base + 별칭.컬럼`의 토큰0은 **18건**이다(결함 판 52건 중, 대조가능 34 + 토큰0 18 = 52).
현행 `base(현행)`의 토큰0 27건 대비 9건을 닫았지만, **18건은 이번 회차로도 못 닫는 사각지대로 남는다.**
남은 18건은 별칭.컬럼도, 인용 리터럴·UF_·2자리 숫자도 안 걸리는 표현식이다(예: 순수 상수 대입,
단항 컬럼 값 복사 등으로 추정 — 이 판독에서는 개별 표현식까지 분해하지 않았다). 다음 회차가 이 잔량을
다루려면 어떤 표현식이 남는지 표본을 다시 뽑아야 한다.
