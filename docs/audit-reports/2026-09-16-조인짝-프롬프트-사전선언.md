# 원본 조인 짝을 단계 프롬프트에 싣는다 (사전 선언)

**작성 시점**: 2026-09-16, **구현 전**. **코드**: main `503a98c7`.

## 0. 잰 것 — 원인은 「칸이 없다」다

교차 분류(`2026-09-14-GPT판-B11-B16-교차분류-사전선언.md` §라)에서 **다섯 판**(B11 S10 · B12 S08 · B13 S08 · B14 S08 · B16 S09)이 같은 자리에 같은 조건을 더했다 — `UP_UTIL_SETTLE_EXPECT_PROC` UPDATE 11.

```
원본 DDL 245~          FROM TSettleMst A JOIN TSettleMst B ON A.MPLTID = B.PLTID
                       JOIN TClientCMRate C ON B.ClientID = C.ClientID AND B.PGName = C.PGName AND B.MallID = C.MallID
B16 S09 첫 초안        JOIN TSettleMst AS B ON A.ClientID = B.ClientID AND A.MPLTID = B.PLTID   ← `A.ClientID = B.ClientID` 를 더했다
B16 S09 둘째 초안      JOIN TSettleMst AS B ON A.MPLTID = B.PLTID                               ← 재생성이 닫았다
```

**프롬프트에는 짝이 없다.** 명세서 「DML 범위」 표의 「조인 키」 칸은 **컬럼 이름만** 담는다 —
`| UPDATE 11 | 245 | A | … | ClientID, PGName, MallID, MPLTID, PLTID | … |`.
어느 테이블의 어느 컬럼이 어느 테이블과 짝인지가 없으니, 모델은 이름 다섯을 보고 짝을 **재구성**한다. 가드 PLTID 날조(`2026-09-14-가드PLTID-날조-원인-측정.md`)와 같은 모양이다 — 칸이 없으면 모델이 지어낸다.

**재료는 이미 있다.** 검사 N5 가 쓰는 `MechanicalValidator.BuildOriginalJoinPairs(step, ddlByProcedure)` 가 원본 DDL 에서 `(종류, 서수, 대상) → 짝 목록`을 낸다(오라클이 원본 DDL 이라 비순환). 실측(B16): 짝이 있는 문장 **35** · 짝 **116** · 렌더 **5,856 자**(S09 만 1.3KB) — 가드 표와 같은 자리에 실을 만한 크기다.

**판 비용**: 판마다 재생성 1 회(다섯 판 5/5). 배송본에는 남지 않는다 — 재생성이 닫았다.

## 1. 설계 — 가드 조건 표와 같은 길

1. `StepInterface` 에 문장별 조인 짝을 더한다(가드를 더한 것과 같은 자리). `StepInterfaceFacts.Build(steps, parametersByProcedure, ddlByProcedure)` 가 `BuildOriginalJoinPairs` 로 채운다 — 재료·키 규약(서수는 `BuildStatementOrdinals` 가 유일 출처)을 **재구현하지 않는다**.
2. `StepInterfaceFacts.RenderJoinPairTable(interfaces)` — 단계 · 문장(종류·서수·대상) · 짝(`A.Col=B.Col` 을 `AND` 로 이음). 짝이 없으면 빈 문자열.
3. `AiService.AppendSharedStepContext` 가 표가 있을 때만 `[Original Join Pairs]` 절을 싣는다(가드 블록 바로 뒤). 짝이 없는 Job 의 프롬프트는 **바이트 그대로**다.
4. 지시문은 검사가 아는 것만 말한다 — 「이 짝 그대로 옮겨라. 원본에 없는 짝을 더하지 말고(예: 자기 조인에 `ClientID` 를 더하면 갱신되는 행 집합이 달라진다) 빼지도 마라. 별칭은 단계가 자유로이 정한다」.
5. 세 프롬프트 경로(단계 섹션 · 골격 · 단일 호출 폴백)가 같은 함수를 지나므로 경로마다 잠금을 건다(가드 표에서 배운 것 — 조항이 한 곳이어도 호출이 셋이다).

**캐시·재사용 키**: 명세서 복합 해시(`CacheManager.ComputeCompositeHash`)는 단계 프롬프트를 담지 않으므로 캐시 버전은 올리지 않는다. 계획 재사용 키(`PlanAttemptJournal` `ReuseKey`)도 프롬프트 바이트를 담지 않는다 — 다만 **이미 만들어진 판을 재개하면 옛 프롬프트로 만든 섹션을 재사용한다**(가드 표 때와 같고, 새 판에는 영향 없다). 기록만 한다.

## 2. 합격선

| # | 항목 | 합격 |
| :-- | :-- | :-- |
| J1 | 재료 | B16 목차 + 실물 DDL 로 S09 의 UPDATE 11 행이 `TClientCMRate.ClientID=TSettleMst.ClientID AND … AND TSettleMst.MPLTID=TSettleMst.PLTID` 를 낸다 |
| J2 | 경로마다 잠금 | 단계 섹션 · 골격 · 단일 호출 폴백 프롬프트가 각각 `[Original Join Pairs]` 와 그 행을 싣는다 |
| J3 | 짝 없음 | 조인 짝이 없는 목차면 절이 없다(프롬프트 바이트 불변) |
| J4 | 배선 | 오케스트레이터가 `ddlByProcedure` 를 `StepInterfaceFacts.Build` 에 넘긴다(이미 그렇다 — 회귀 잠금) · 렌더가 검사와 같은 키 규약을 쓴다 |
| J5 | 되돌림 | 재료 수집 · 렌더 · 세 경로의 싣기를 하나씩 걷어내면 해당 시험 빨강 |
| J6 | **재생 실험** | B16 S09 요청(로그 원문)을 그대로 3 회 · `[Original Join Pairs]` 를 붙여 3 회 재전송하고 **실제 검사**(`CheckAnchoredStatementJoinPairs`)로 판정한다. 그대로는 표류가 재현되고(다섯 판 5/5 이므로 2~3/3 예상), 붙이면 0/3 을 목표로 한다. 붙였는데도 표류하면 **처방을 병합하지 않고** 원인을 다시 잰다 |
| J7 | 스윕 | 배송본 스윕 차분 0(프롬프트 변경은 배송본을 바꾸지 않는다 — 판별력이 없음을 명시하고 무변화 확인으로만 쓴다) |
| J8 | 게이트 | 경고 0 · 실패 0 · 건너뜀 0 |

**오탐 방향**: 검사는 건드리지 않는다 — 프롬프트만 바뀐다. 위험은 (가) 표가 틀린 짝을 실어 모델을 잘못 이끄는 것(J1 이 실물로 막는다) (나) 프롬프트가 길어져 캐시 접두사 크기가 커지는 것(5.9KB · 접두사 안이라 캐시에 실린다) (다) 모델이 표의 테이블 이름 표기를 자기 별칭으로 못 옮기는 것 — J6 재생 실험이 (다)를 실물로 본다.
**효과 판정**: J6 이 1 차 판정이고, 다음 GPT 판의 재생성 수가 2 차다.
