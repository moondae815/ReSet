# 명세서 재생성 뒤 발화 −7 — **위험한 두 범주는 0 이다**

**작성 2026-09-08.** 기준 커밋 `451f08cd`(main = `origin/main`).

## 0. 어휘를 먼저 정했다 (보기 전에)

| | 뜻 |

| **침묵** | 결함은 그대로인데 **검사가 재료를 잃어** 조용해졌다 |
| **소멸** | 그 자리(문장·절)가 통째로 없어졌다 — **고친 것이 아니다** |

## 2. ⚠ 발화 목록 차분은 **불가능하다** — 재생성이 표본을 지웠다

스냅샷이 없고(`output.bak-*` 0개) 명세서가 제자리에서 덮어써졌다. **사라진 7 의 신원은
회수할 수 없다.** 2026-09-05 사람 결정이 「재생성은 검사의 표본을 지우고 그것은 회수 불가」라
적은 그 자리이고, **이번에 실제로 그렇게 됐다.**

**그래서 신원 대신 범주를 배제하는 방식으로 판정했다.**

## 3. 판정 — **소멸 0 · 침묵 0**. 둘 다 증명된다

### 소멸 0 — 피고발자가 안 바뀌었다

```

명세서                                            2026-09-08 12:38 · 12:46

**Job 번들은 손도 안 댔다.** 발화가 가리키던 단계 문장이 그대로 있으므로 **「그 자리가
없어졌다」는 원리적으로 불가능하다.**

### 침묵 0 — 재료 분모가 완전히 동일하다

```

**한 줄도 안 움직였다.** 검사가 재료를 잃어 조용해진 것이 아니다.

## 4. 그래서 −7 은 무엇인가 — **「닫힘 또는 기준값 이동」이고 더 좁히지 못했다**

소멸도 침묵도 아니면 남는 설명은 하나다 — **기준값(명세서)이 바뀌어 이제 단계와 맞는다.**
그런데 그것이 좋은 일인지는 한 겹 더 갈린다.

| | |
| :--- | :--- |
| **(a) 닫힘** | 명세서가 **더 정확해져** 단계가 원래 옳았음이 드러났다 — 오탐이 걷힌 것 |
| **(b) 기준값 이동** | 명세서가 **틀리게 바뀌어** 진짜 결함을 더는 못 본다 — 거짓 침묵 |

**(a)와 (b)를 가르는 것은 「명세서가 원본 DDL 과 맞는가」뿐이고, 이 회차는 그것을 안 쟀다.**
동료 세션의 측정(**실행 의미 미전사 18 → 0**)은 (a) 쪽을 가리키지만 **그것은 다른 축의 수**다 —
내 −7 이 난 축과 같다는 근거가 없다.

**그러므로 −7 을 「7 건 닫힘」으로 인용하지 마라.** 오늘 확정된 것은 **「위험한 두 범주가 0」**까지다.

## 5. 이 판독이 재생성 결정에 주는 것

**명세서 재생성이 소멸도 침묵도 만들지 않았다.** 이 저장소가 재생성을 두려워한 두 가지가
이번 판에서는 **둘 다 실현되지 않았다** — 검사 D 가 18 → 0 으로 꺼진 2026-08-28 판과 다르다.

**다만 그것이 Job 번들 재생성의 안전을 뜻하지는 않는다.** 이번에 안 바뀐 것이 정확히 Job
번들이고, 2026-09-05 재감사가 「소멸 7」을 실제로 겪은 것도 **Job 번들 재생성**에서였다.
**Job 을 돌릴 때는 이 어휘와 스냅샷을 먼저 세워야 한다** — 이번에 스냅샷이 없어 신원을
못 밝힌 것이 그 예고다.
