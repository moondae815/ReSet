# RunId 발급 전 단계가 잠금 행을 쓴다 — 계약과 검사 (사전 선언)

**작성 시점**: 2026-09-16, **구현 전**. **코드**: main `259a0be3`(B17 판독) + 이 문서 커밋.

## 0. 잰 것

B17 판독 §발견 1 에서 나온 자리다. 배송본 **13 편 전수**로 「발급 절보다 앞선 절이 `batch.BatchRunLock` 에 쓰는가」를 쟀다(발급 절 = 문서 순서로 `batch.BatchRun` 에 처음 INSERT 하는 절 — `CheckGateRequiresStepsBeforeRunId` 와 같은 오라클).

| Job | 발급 절 | 잠금 쓰기 절 | 발급 전 잠금 | 비고 |
| :-- | :-- | :-- | :-- | :-- |
| B1 · B4 · B7 · B8 · B10 | S01 | S01 · 뒤쪽 해제 | 없음 | 발급 절이 잠금도 잡는다 |
| B5 | S00 | S00 · S15 | 없음 | 같음 |
| B12 · B13 · B15 | S02 | S02 · 뒤쪽 | 없음 | 같음 |
| B11 | S02 | S03 · S22 | 없음 | 발급 뒤에 잡는다 |
| B14 | S01 | S02 | 없음 | 발급 뒤에 잡는다 |
| **B16** | S03 | **S02** · S03 · S21 | **있음** | `OwnerRunId` 에 **예약값 0** 을 지어냈고 Critic 이 S03 에 승계 UPDATE 를 넣게 했다 |
| **B17** | S03 | **S02** · S22 | **있음** | 지어내지 않고 「선행 설계 차단 사항」으로 선언 → **S02 가 항상 -9020 으로 죽는 계획서를 배송** |

즉 **도달 2/13**, 그리고 **11/13 은 이미 발급 단계 또는 그 뒤에서 잠금을 잡는다** — 계약으로 못박는 것은 다수가 이미 하는 모양이라 회귀 위험이 작다.

계약이 잠금을 앞으로 끌어당기는 자리는 `ControlRowOrigin.FirstStepInserts` 의 프롬프트 문구다: 「이 표를 대상으로 선언한 **첫** 단계가 이 행을 INSERT 한다」. 그런데 계약의 `batch.BatchRunLock.OwnerRunId` 는 `bigint NOT NULL` 이고 이 표에는 IDENTITY 컬럼이 없다 — 발급 전 단계가 **합법적으로 쓸 수 없다.** L1 은 둘 다 통과시켰다: RunId 게이트 검사(`CheckGateRequiresStepsBeforeRunId`)는 발급 전 단계의 **저널·체크포인트 쓰기와 게이트 요구 단계**만 본다.

**선례**: 「RunId 수명」 문단(2026-09-14, 같은 가족의 첫 자리)이 이미 계약에 있고 저널·체크포인트를 이름으로 막는다. 이번 것은 **같은 문단이 못 막은 통로**다.

## 1. 설계 — 사람 결정: 잠금을 발급 뒤로

두 층으로 고친다.

### ① 계약(프롬프트)

「RunId 수명」 문단에 한 문장을 잇는다(새 칸을 만들지 않는다 — 이 문단이 이미 이 축의 정본이고, `ControlRowOrigin` 열거값은 검사 셋이 읽는 축이라 의미를 바꾸지 않는다):

> 실행 잠금 행(`batch.BatchRunLock`)은 **발급 절 또는 그 뒤** 절이 INSERT 한다. `OwnerRunId` 는 발급된 run id 이며 **예약값·자리표시값(0 같은 것)을 만들지 않는다**. 중복 실행 판정은 잠금을 잡는 자리에서 하고, 그 시점에 이미 만들어진 실행 행은 실패로 닫는다.

### ② 검사(통합 L1)

발급 절보다 **앞선** 절이 제어 계약의 **run id 를 담는 `NOT NULL` 컬럼**(`batch.BatchRunLock.OwnerRunId` · 다른 표의 `RunId`)에 INSERT·UPDATE·MERGE 하면 발화한다. 컬럼 목록은 이름으로 짐작하지 않고 **계약에서 읽는다**(`BatchControlContract`: `Nullable == false` 이고 IDENTITY 가 아니며 이름이 run id 를 가리키는 컬럼) — 이 저장소가 이름 추정으로 두 번 실패한 자리라 계약 조회로 고정한다.

- **귀속**: 그 단계 절(`OwnerStepCode`), 어휘는 그 쓰기가 있는 원문 줄.
- **처방**: 「잠금 획득을 발급 절이나 그 뒤로 옮기십시오」 — 계약이 합법 모양을 하나 주므로 재시도가 따를 수 있다(처방을 따를 수 없는 고발이 재시도를 태우는 것을 B13 에서 봤다).
- **침묵 규칙**: 발급 절 자신의 쓰기 · 발급 뒤 절의 쓰기 · 발급 절을 못 찾은 문서(`batch.BatchRun` INSERT 가 없으면 무엇이 앞인지 모른다) · 읽기만 하는 문장.

### 캐시

명세서 프롬프트는 안 바뀌므로 `CacheManager.CurrentCacheFormatVersion` 은 **그대로 둔다**(22). 계획 시도 재사용 키인 `PlanAttemptJournal.ContractVersion` 을 **1 → 2** 로 올린다 — 안 올리면 옛 시도가 재사용돼 새 계약이 안 돈다.
