# 검증 배너의 스택 트레이스 절단 — 판독

`2026-09-07-PGCommOption-축A-감사.md` §4-2(🟡 A-2)가 남긴 자리다. 동료 세션(reset-2a)이
실측으로 **세 편**임을 재 왔다.

**답: 자를 자리가 배너가 아니라 발원지였다.** 배너는 오류 문자열을 잇기만 하고, 스택
트레이스는 `MechanicalValidator.ValidateMermaid` 가 `stderr` 를 통째로 메시지에 이어 붙이는
데서 온다. 그 메시지는 **배너·재시도 프롬프트·오류 목록 셋**으로 갈라지므로 한 자리 위에서
자르면 셋이 한 번에 정리된다.

## 1. 무엇을 잃지 않았나

전체 `stderr` 는 **바로 옆 `Log.Warning("… Stderr: {Stderr}", stderr)` 가 그대로 남긴다.**
사람이 볼 자리는 로그다. 이 변경으로 사라지는 것은 **배송 문서와 프롬프트에 실리던 사본**뿐이다.

## 2. 효력 — 실물 픽스처로 쟀다

픽스처는 **실행 로그에서 오려 왔다**(`Fixtures/MermaidCliStderrExcerpt.txt`,
2026-09-07 19:17:27 판). 규격 기억으로 지어내면 내 오해를 시험이 확인해 준다.

| | 줄 | 바이트 |
| :--- | ---: | ---: |
| 전체 `stderr` | 15 | 2,471 |
| 남는 진단부 | **4** | **318** |
| 줄어든 것 | 11 | 2,153 (**87%**) |

남는 넷은 진단 자체다 — `Error: Parse error on line 5:` · 문맥 줄 · **캐럿(^) 줄** ·
`Expecting … got 'X'`. 첫 잘림은 `Parser.parseError (https://mermaid-cli-intercept.invalid/…` 다.

## 3. 왜 「앞 N 줄」로 안 잘랐나

줄 수로 박으면 mmdc 출력 형식이 바뀔 때 **조용히 낡는다** — 오늘 네 번 밟은 그 축이다.
스택 프레임 줄의 **모양**으로 자른다. 프레임에 두 형태가 있다:

    at async CdpPage.$eval (file:///…)          ← `at` 으로 시작
    Parser.parseError (https://…)               ← 심볼 뒤에 바로 URL

**후자가 실물에서 첫 프레임이라, `at` 만 보면 한 줄이 새어 나간다.**

**프레임이 하나도 안 잡히면 전체를 그대로 둔다.** 「이 형식에는 X 가 없다」는 단정을 쓰지
않는 쪽으로 실패시킨다 — 안전한 실패는 「덜 자른다」이지 「다 자른다」가 아니다. 그때를 위해
줄 수 상한(12)을 마지막 안전망으로 뒤에 둔다.

## 4. 곁들여 닫은 것 — 인용 블록이 새고 있었다

`VerificationBanner.RenderBulletList` 가 항목 전체를 `">   - {item}"` **한 줄로만** 감쌌다.
항목에 줄바꿈이 있으면 **둘째 줄부터 인용 블록 밖으로 샌다** — 배송본 `Spec.md:16~31` 이
그 모양이고, 컴파일 로그가 문서 본문에 그대로 풀려 나왔다.

**자르기만으로는 짧아질 뿐 여전히 샌다.** 이어지는 줄에 `">     "` 를 붙여 함께 닫았다.

## 5. 동료가 짚어 준 축 하나를 시험으로 받았다

**「자르기가 재시도 프롬프트의 캐럿까지 베면 아무도 모르게 진단이 0 이 된다.」**
오늘 확인한 것이 「여섯 시도가 그 캐럿을 보고도 못 고쳤다」였는데, 정화기가 원인을 없앤
지금 **캐럿이 다음 재생성의 유일한 진단 통로**다. 발화 0 오독과 같은 모양으로 조용해질 수
있다. 그래서 요구 7 을 더했다 — `SuggestedPromptFix` 에 파스 오류·캐럿·`Expecting` 이
남고 `/opt/homebrew/` 는 없다.

## 7. 이 변경이 보증하지 않는 것

- **이미 배송된 세 편은 안 고쳐진다.** 다음 재생성 때 새 배너가 실린다.
- **다른 외부 도구의 stderr 는 안 봤다.** 이 절단은 mermaid-cli 경로에만 걸려 있다.
- **자르기 규칙을 mmdc 다른 버전에서 안 재 봤다.** 11.16.0 한 판의 출력이 근거다.
  형식이 바뀌면 프레임이 안 잡혀 **전체가 남는다** — 조용히 다 자르는 쪽으로는 안 깨진다.
- **줄 수 상한 12 는 실물 근거가 없다.** 프레임이 안 잡히는 경우를 아직 못 봤다.
