# SQL 펜스를 파서에 통과시킨다 — 사전 선언 (예약어 별칭 검사의 확장)

**작성**: 2026-09-19 · **코드**: `fix/reserved-word-alias-check` `e71b4201`
**선행**: `2026-09-19-예약어-별칭-L1검사-사전선언.md` · `…-판독.md` · 구현 `b4d38672`
**이 선언이 왜 새로 필요한가**: **앞 선언의 전제가 틀렸다.** 아래 §1 이 그것이다.

---

## 0. 물음

**SQL 펜스를 통째로 파서에 통과시키는 검사가, 의도적 조각·자리표시자에 오탐하지 않고 돌 수 있는가.**

---

## 1. 앞 선언이 틀린 자리 — 전제를 넓혀 재니 무너졌다

앞 선언 §7 은 이렇게 적고 파싱 검사를 **기각**했다:

> **다른 구문 오류는 안 잡는다.** §1-2 에서 실측한 진짜 구문 오류는 `RowCount` 하나뿐이었다. 펜스 단위 전체 파싱 검사는 **의도적 조각 2 자리에 오탐**하므로 이번에 만들지 않는다.

**그 실측은 B23 한 편 325 펜스였다.** 계획서 **19 편 2628 펜스**로 넓혀 다시 재니 가족이 **넷**이다. 「진짜 구문 오류가 예약어 별칭 하나뿐」은 **표본이 작아서 나온 결론**이었다.

| 모양 | 실패 펜스 | 지금 검사가 | 실물 SQL Server |
| :-- | --: | :-- | :-- |
| `AS <예약어>` | **67** | 잡는다 | 거부 |
| 예약어를 **컬럼 참조**로 — `SELECT TableName, RowCount` | 1 | **못 잡는다** | 거부 |
| 예약어를 **CTE 이름**으로 — `Current AS (` | 1 | **못 잡는다**(설계상 제외했다) | 거부 |
| **`EXEC` 인자에 식** — `@Resource = CONCAT(…)` | 2 | 축이 다르다 | 거부 |
| **미닫힌 문자열** — `N'Restarting)` | 1 | 축이 다르다 | 거부 |
| **소계 — 진짜** | **72** | | |
| 자리표시자 `<ChunkKey>`·`<LiteralTargetTable>` | 2 | — | **오탐** |
| 의도적 조각 — 교정본 WHERE 스니펫 · 「참조용」 CASE 발췌 | 2 | — | **오탐** |
| **합계** | **76** | | |

다섯 모양 전부를 **실물 SQL Server 에 물어 확인했고, 고친 형태는 전부 통과했다**:
`[RowCount]`·`[Current]` 대괄호 ✔ · `EXEC` 인자를 변수로 뺀 것 ✔.

**「`AS` 없는 별칭」은 0 이었다.** 물음의 출발점이었던 `SELECT COUNT(*) RowCount` 모양은 코퍼스에 없다. 대신 **그 이웃 넷**이 나왔다.

## 2. 무엇이 바뀌는가 — 검사를 바꾸는 게 아니라 **한 겹 위에 둔다**

`CheckReservedWordAliasInSql`(`b4d38672`)을 **지우지 않는다.** 두 자가 축이 다르다.

| | 예약어 별칭 검사(기존) | 파싱 검사(새것) |
| :-- | :-- | :-- |
| 판정 | `AS` 뒤 토큰이 예약어인가 | 펜스 전체가 파싱되는가 |
| 도달 | 67 | **72** |
| 오탐 | **0**(구조적으로) | 0 — **제외 둘이 붙어야** (§3) |
| 시정 문구 | 「대괄호로 감싸거나 이름을 바꾸십시오」 — **무엇을 고칠지 말한다** | 「이 SQL 이 파싱되지 않습니다」 — **어디가 깨졌는지만 말한다** |

**둘을 다 두는 이유는 시정 문구다.** 파싱 검사는 파서 메시지(`'AS' 근처의 구문이 잘못되었습니다`)를 그대로 실을 수밖에 없는데, 그것만 받은 모델은 **무엇을 고쳐야 하는지 모른다.** 예약어 별칭은 코퍼스 실패의 **67/72** 이고 그 자리만큼은 **정확한 시정 문구**가 있어야 한다.

⇒ **같은 펜스가 둘 다에 걸리면 둘 다 발화한다.** 중복이 아니라 한쪽은 진단, 한쪽은 처방이다. 이 중복을 **결함으로 세지 않는다**고 여기 못박는다.

## 3. 제외 둘 — 자를 실측으로 정했다

파싱 검사의 유일한 위험은 **정당하게 파싱되지 않는 펜스**다. 코퍼스에 넷 있고, 둘로 갈린다.

### 3-1. 자리표시자 — `<…>` 꺾쇠를 담은 펜스

```
SELECT MIN(<ChunkKey>), MAX(<ChunkKey>) FROM <SourceTable>
DELETE FROM SETTLE_POQ_DB.dbo.<LiteralTargetTable>
```

**판정식**: 펜스가 `<식별자>` 모양을 담으면 제외한다(`<[A-Za-z_][A-Za-z0-9_ ]*>`).
**도달**: 2. **위험**: T-SQL 에 `<` 는 비교 연산자로도 쓰인다 — `a < b` 는 공백 때문에 이 식에 안 걸리지만 `a<b` 는 걸린다. **§5 에서 그 모양이 코퍼스에 있는지 세고, 있으면 식을 좁힌다.**

### 3-2. 조각 — 문장을 시작할 수 없는 토큰으로 열리는 펜스

```
AND ControlName IN (…)          ← 「SQL-09 의 Stored CTE 에 추가할 필터」
CASE WHEN Y.CommMethod = 0 …    ← 「원본 발췌: 참조용 — 이 단계는 실행하지 않음」
```

**판정식**: 주석을 건너뛴 **첫 토큰**이 문장을 시작할 수 없으면 제외한다.
목록: `AND OR CASE WHEN THEN ELSE END ) , ON JOIN INNER LEFT RIGHT FULL CROSS GROUP ORDER HAVING WHERE FROM`

**산문을 읽지 않는 이유**: 둘 다 산문에 「교정본」·「참조용」이라 적혀 있지만 그 어휘로 판정하면 **문구가 바뀌는 순간 조용히 꺼진다**(작성 계약 8 — 트리거 문구는 코퍼스로 정하라). 첫 토큰은 문법이 정하는 것이라 문구에 안 흔들린다.

### 실측 — 이 둘이 정확히 넷을 걷는다

```
펜스 2628 · 파싱 실패 76
  자리표시자 제외 2 · 조각 제외 2 · 남는 진짜 72
```

**제외가 진짜를 하나도 안 먹는다**는 것도 같이 확인했다 — 72 는 전부 §1 의 다섯 가족이다.

## 4. 예측과 결정 규칙 — 결과를 보기 전에 적는다

| 지표 | 예측 | 이것이 아니면 |
| :-- | :-- | :-- |
| 코퍼스 19 편 발화 펜스 | **72** | 적으면 제외가 넓다 · 많으면 제외가 좁다. **둘 다 구현을 멈추고 자를 고친다** |
| 코퍼스 **오탐** | **0** | 1 건이라도 나오면 그 자리를 읽고 **「왜 정당한가」를 먼저 적는다**. 오탐은 재시도 소진으로 번진다 |
| 제외로 걸러진 펜스 | **4**(자리표시자 2 · 조각 2) | 다르면 §3 의 자가 틀렸다 |
| 기존 예약어 별칭 검사 | **67 그대로** | 줄면 내가 그 검사를 건드린 것이다 |
| 게이트 | 실패 0 · 건너뜀 0 · 경고 0 | 하나라도 어기면 병합하지 않는다 |

## 5. 구현 전에 마저 잴 것

1. **`a<b` 모양(공백 없는 비교)이 코퍼스에 있는가.** 있으면 §3-1 의 식이 정당한 펜스를 먹는다 — 식을 `<[A-Za-z_][A-Za-z0-9_ ]*>` 에서 더 좁히거나, 자리표시자 표기 규약을 문서화한다.
2. **명세서 경로(`Validate`)에도 SQL 펜스가 있는가.** 이번 검사는 계획서(`ValidateConsolidated`)만 건다 — 명세서 쪽은 **재고** 결정한다. 앞 판독 §8 이 「재지 않았다」로 남긴 자리다.
3. **파서 버전.** `TSql160Parser` 를 쓴다(기존 코드와 같다). 대상 서버가 그보다 낮으면 판정이 관대해진다 — **어느 버전으로 배포되는지 모른다.** §7 에 적는다.

## 6. 되돌림과 대조군

| 층 | 무엇을 | 합격 |
| :-- | :-- | :-- |
| **효력** | 검사 본문 무력화 | 그 시험만 빨갛다 |
| **배선** | `SafeCheck` 호출 줄 삭제 | **별도 시험이** 빨갛다 |
| **제외 둘** | 자리표시자 제외를 끄고 · 조각 제외를 끄고 각각 | **각각 그 제외 시험만** 빨갛다. 한 시험이 둘을 덮으면 하나가 죽어도 초록이다 |
| **양성** | 코퍼스에서 오려 온 다섯 가족 각각 | 전부 발화 |
| **음성** | 정상 펜스 · 자리표시자 · 조각 | 발화 0 |

**픽스처는 배송본에서 오려 온다.** 다섯 가족의 좌표를 시험 주석에 적는다.

## 7. 이 선언이 보증하지 않는 것

- **파서가 SQL Server 와 100% 같지 않을 수 있다.** 이번 다섯 가족은 실물로 교차 확인했지만, ScriptDom 이 받고 SQL Server 가 거부하는(또는 반대) 모양이 남아 있을 수 있다. **대상 서버 버전도 모른다.**
- **파싱은 문법만 본다.** 없는 컬럼·타입 불일치·권한은 이 검사 밖이다.
- **이미 배송된 72 자리를 고치지 않는다.** 다음 판부터 막는다.
- **기존 예약어 별칭 검사를 대체하지 않는다.** §2 의 이유로 둘 다 둔다.
- **명세서 경로는 아직 범위 밖이다**(§5-2).
- **조각 판정은 목록이다.** 문장을 시작할 수 있는 토큰이 더 있으면(`MERGE`·`THROW` 등은 시작 가능하므로 목록에 없다) 반대로 **조각인데 안 걸러지는** 자리가 생길 수 있다. 코퍼스 실측으로는 0 이다.
- **캐시 버전은 올리지 않는다** — 프롬프트도 출력 계약도 안 바뀐다. 검사만 더한다.

---

## 8. 앞 선언에서 배운 것 하나

앞 선언은 **B23 한 편**을 재고 「다른 구문 오류는 없다」로 닫았다. 코퍼스를 넓히니 **가족이 넷 더** 있었다.

**한 편으로 「없다」를 말하지 마라 — 「이 한 편에는 없다」가 잴 수 있는 전부다.** 이번 선언의 수는 전부 **19 편 2628 펜스** 기준이고, 그 분모를 문장마다 적는다.
