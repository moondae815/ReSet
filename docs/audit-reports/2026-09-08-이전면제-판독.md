## 2. ★ 오늘 효력이 0 인 것을 어떻게 다뤘나

**이것은 발화를 늘리는 검사가 아니라 줄이는 면제**이고, 면제할 대상 둘은
**오늘 존재하지 않는다** — `Batch1/S12/INSERT 1` 이 앵커를 못 받아 검사 B·C 가 아예 안 돈다.
그대로 두면 「값 0 을 게이트 통과시킨다」에 그대로 들어간다.

**사전 선언이 대응 셋을 미리 못박았고 셋 다 이행했다.**

1. **효력은 ②(U-앵커 한 줄)를 켠 상태에서 쟀다** — 던지는 변경으로 켜고 스윕을 돌린 뒤 되돌렸다.
2. **단위 시험 일곱이 면제를 직접 못박는다** — 이 면제의 **유일한 탐지기**다.
3. 오늘 스윕은 **완전 불변**이어야 하고 그것을 R2 로 확인했다.

## 3. 조건 ⑥ — 두 층에서 되돌려 쟀다

**커밋한 뒤에 껐다.**

**층 1 — ②를 켠 상태에서 면제만 끄면**:

```
② ON · 면제 ON    A 0 · B 2 · C 1 · D 0 · E 0 · 미분류 27   ← 기준선과 같다
② ON · 면제 OFF   A 0 · B 3 · C 2 · D 0 · E 0 · 미분류 27   ← 정확히 그 둘이 켜진다
```

**면제가 막는 것이 정확히 그 둘이고 다른 것은 하나도 안 건드린다.**

**층 2 — 면제를 끄면 단위 시험 7 중 2 가 빨개진다**(면제를 확인하는 둘). 나머지 다섯은
**엄격 방향 잠금**이라 면제가 없어도 초록이다 — **「일곱이 지킨다」고 적으면 거짓이다.**

## 4. 거짓 침묵을 어떻게 막았나 — 이쪽의 오탐이 그것이다

면제는 검사를 **끄는** 변경이라 위험이 반대 방향이다. 「커서 SP 면 다 봐준다」로 만들었으면
오늘 살아 있는 검사 C 발화(`Batch4/S15` = `SUMMARY_ETC`)를 지웠을 것이다.

**서명이 그것을 가른다.**

| SP | 커서 | 쓰기 술어 ↔ SELECT GROUP BY | 결과 |
| :--- | :--- | :--- | :--- |
| `Summary_AcqManual` | 있다 | **같다** | 면제 |
| `SUMMARY_ETC` | 있다 | `SELECT 1` 에 **GROUP BY 없음**(술어는 행 전체 키 13) | **발화 유지** |
| `PROC_ETC` | 있다 | 다름 | **발화 유지** |

**의미가 있는 구분이다** — 집계 그룹을 순회하는 커서만 집합 치환에서 술어가 정당하게 사라진다.
**행을 순회하는 커서는 술어가 사라지면 진짜 결함이다.** R3 이 그것을 잰 자다(스윕의 B·C 발화
목록이 전후 완전 일치).

## 5. 커서 조건은 오늘 아무것도 안 거른다 — 그래도 넣었다

**정직하게 적는다.** `GROUP BY` 일치가 코퍼스 전체 2 건이고 그 둘이 이미 커서 SP 안이라,
`DECLARE … CURSOR` 조건을 빼도 오늘 결과가 같다.

**그래도 넣은 이유**: 이것은 **침묵시키는 변경**이고 침묵은 **좁은 쪽이 안전한 방향**이다.
커서가 없는 SP 에서 「술어 == 어떤 SELECT 의 GROUP BY」는 관용구가 아니라 **우연**이고,
우연을 면제하면 진짜 결함이 조용해진다. 이 저장소의 「오늘 값을 하지 않는 변경은 하지
않는다」(2026-09-06 S15 회차)의 **의도된 예외**이고, 그 이유를 코드 주석에도 적었다.

## 7. 이 판독이 보증하지 않는 것

- **오늘 코퍼스에서 이 면제가 실제로 침묵시킨 발화는 0 이다.** 효력은 ②를 켠 가상 상태에서만
  관측된다 — **그 상태를 코퍼스가 아니라 던지는 변경으로 만들었다.**
- **`SELECT` 이 여럿인 SP 에서 둘 이상이 같은 `GROUP BY` 를 가지면 침묵한다**(설계된 갈래).
  오늘 실물은 없고 단위 시험으로만 잠갔다.
- **면제의 정당성은 「커서가 집계 그룹을 순회한다」까지다.** 그 치환이 의미상 동등한지는
  로컬에서 검증할 수 없다 — 검사 B 의 `relocated` 가 같은 한계를 갖는 것과 같다.
