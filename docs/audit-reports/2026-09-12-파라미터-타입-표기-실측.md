## 3. 하네스 B — 프로덕션 재료 기반 (`step.LegacyProcedures`, Task 4 가 맞대는 기준)

`ValidateBatchStep` 이 실제로 받는 재료는 `StepInterfaceFacts.Build(steps,
parametersByProcedure)` 다(`src/ReSet.Core/Services/StepInterfaceFacts.cs:221`). 그
함수는 `step.LegacyProcedures` — 목차 승인 표의 칸, `PlanStructure.md` 안에 있는 JSON
블록 `Steps[].LegacyProcedures` 로 파싱되는 바로 그 필드 — 에 실린 프로시저만 순회하고
그 프로시저들의 `StaticAnalysis.ProcedureParameters` 만 합집합한다. 하네스 A 처럼
단계 산문에 이름이 「언급」됐다는 사실은 안 본다. 아래 스크립트는 그 재료 조달 경로를
그대로 옮긴다(같은 줄-대조 규칙 — 같은 줄에 이름과 타입이 함께 있어야 「적음」).

```bash
cd <워크트리 루트>
python3 - <<'PY'
import json,re,os,glob

def params(sp):
    p=f'output/Procedures/{sp}/raw/metadata.json'
    if not os.path.exists(p): return []
    return json.load(open(p,encoding='utf-8-sig')).get('StaticAnalysis',{}).get('ProcedureParameters',[])

def col(s): return re.sub(r'\s+','',s).lower()

def load_steps(job):
    path=f'output/Jobs/{job}/raw/PlanStructure.md'
    text=open(path,encoding='utf-8').read()
    m=re.search(r'```json\n(.*?)\n```', text, re.S)
    data=json.loads(m.group(1))
    return data['Steps']

for job in sorted(os.path.basename(p) for p in glob.glob('output/Jobs/*')):
    steps=load_steps(job)
    step_md_dir=f'output/Jobs/{job}/agent/steps'
    yes,no,skip=[],[],[]
    for st in steps:
        code=st['Code']
        legacy=st.get('LegacyProcedures') or []
        ps=sorted({d for sp in legacy for d in params(sp)})
        f=f'{step_md_dir}/{code}.md'
        if not ps or not os.path.exists(f):
            skip.append(code); continue
        t=open(f,encoding='utf-8').read()
        lines=[col(l) for l in t.split('\n')]
        miss=[d for d in ps
              if not any(col(d.split(' ')[0]) in l and col(d.partition(' ')[2]) in l for l in lines)]
        (no if miss else yes).append((code,miss))
    print(f'{job}: 적음 {len(yes)} {[c for c,_ in yes]} · 안 적음 {len(no)} {[c for c,_ in no]} · 재료없음 {len(skip)} {skip}')
    for c,m in no: print(f'    {c} 누락 {m}')
PY
```

## 4. Step 3 판정 — 「입력만」과 「전부」가 같은 발화를 내는가 (설계서 §3-1)

설계서 §3-1 은 「입력만」 기준(누락 목록에 `@pi` 로 시작하는 선언이 있어야 발화)과
「전부」 기준(입력이든 출력이든 누락이면 발화)이 코퍼스에서 같은 발화 집합을 낸다고
주장한다. 그 동률이 깨지는 실물은 **누락 목록 전부가 `@po` 로 시작하는(즉 `@pi` 로

발화하지만 「입력만」 기준으로는 발화하지 않는다.

### 6-2. 프로브 — 재료 조달을 제품 코드에 맡긴다

**계획서 Step 1 의 프로브를 그대로 쓰지 않았다.** 그 프로브는 단계 산문을

- `BatchStepPlanParser.TryParse` — `raw/PlanStructure.md` 의 목차 JSON 블록을 제품과
  **같은 선택 규칙**으로 고른다(블록이 여럿일 때 어느 것을 쓰는지까지 같다).
- `StepInterfaceFacts.Build` — `step.LegacyProcedures` 만 순회해 `StepInterface` 를 만든다.
- `MechanicalValidator.ValidateBatchStep` — 검사를 부르는 제품 진입점 그대로.

프로브가 새로 짠 것은 `parametersByProcedure` 맵 하나뿐이고, 그것도

```csharp
using System;
using System.Collections.Generic;
using System.IO;
using System.Linq;
using System.Text.Json;
using ReSet.Core.Services;
using Xunit;
using Xunit.Abstractions;

namespace ReSet.Core.Tests
{
    public class TempParameterTypeCorpusProbe
    {
        private readonly ITestOutputHelper _out;
        public TempParameterTypeCorpusProbe(ITestOutputHelper o) => _out = o;

        [Fact]
        public void Probe()
        {
            var root = CorpusPaths.RepoRoot();
            _out.WriteLine($"RepoRoot={root}");

            // CollectParameters 와 같은 키잉(한정명, 대소문자 무시).
            var parametersByProcedure = new Dictionary<string, IReadOnlyList<string>>(
                StringComparer.OrdinalIgnoreCase);
            foreach (var dir in Directory.GetDirectories(Path.Combine(root, "output", "Procedures")))
            {
                var meta = Path.Combine(dir, "raw", "metadata.json");
                if (!File.Exists(meta)) continue;
                using var doc = JsonDocument.Parse(File.ReadAllText(meta).TrimStart('﻿'));
                if (!doc.RootElement.TryGetProperty("StaticAnalysis", out var sa)) continue;
                if (!sa.TryGetProperty("ProcedureParameters", out var ps)) continue;
                var list = ps.EnumerateArray().Select(p => p.GetString()!).ToList();
                if (list.Count == 0) continue;
                parametersByProcedure[Path.GetFileName(dir)] = list;
            }
            _out.WriteLine($"parametersByProcedure={parametersByProcedure.Count}");

            var grandTotal = 0;
            foreach (var job in Directory.GetDirectories(Path.Combine(root, "output", "Jobs")).OrderBy(p => p))
            {
                var jobName = Path.GetFileName(job);
                var structure = File.ReadAllText(Path.Combine(job, "raw", "PlanStructure.md"));
                var steps = BatchStepPlanParser.TryParse(structure);
                if (steps == null) { _out.WriteLine($"{jobName}\tPARSE-FAILED"); continue; }

                var interfaces = StepInterfaceFacts.Build(steps, parametersByProcedure);
                var fired = new List<string>();

                foreach (var step in steps)
                {
                    var stepFile = Path.Combine(job, "agent", "steps", $"{step.Code}.md");
                    if (!File.Exists(stepFile)) continue;
                    var markdown = File.ReadAllText(stepFile);

                    var result = new MechanicalValidator().ValidateBatchStep(
                        markdown, step, Array.Empty<string>(),
                        new Dictionary<string, SpecConditions>(),
                        interfaces);

                    foreach (var e in result.Errors.Where(e => e.Contains("선언 타입")))
                    {
                        fired.Add(step.Code);
                        _out.WriteLine($"FIRE\t{jobName}\t{step.Code}\t{e}");
                    }
                }

                grandTotal += fired.Count;
                _out.WriteLine($"SUMMARY\t{jobName}\t발화 {fired.Count}\t{string.Join(" ", fired)}");
            }

            _out.WriteLine($"TOTAL\t{grandTotal}");
        }
    }
}
```

### 6-6. 정확한 것은 단계 수 27, 하한인 것은 파라미터 수 36

전수 열람 중에 한 가지가 보였다. `@po_intRetVal INT` 는 타입 토큰 `INT` 가 **이름
자신의 부분 문자열**(`@po_**int**RetVal`)이라, 이름이 적힌 줄은 타입도 적힌 것으로
읽힌다. 실물이 있다 — Batch6/S13 은 13행에 `// 원본 파라미터: @pi_strYMD (batchYmd),
@po_strErrMsg, @po_intRetVal (출력 전용)` 이라고 **이름만** 적는데, 검사의 누락 목록에
`@po_intRetVal INT` 가 없다(`@pi_strYMD`·`@po_strErrMsg` 둘만 들었다).

**최초본은 이것을 「27 은 하한」이라고만 적고 단위도 크기도 안 밝혔다 — Fix Round 1
리뷰가 그 자리를 실제로 쟀다.** 경계 기준 자(이름을 지운 뒤 `\bINT\b`)로 재면 —
부분 문자열 자는 `INTO`·`PRINT` 가 `int` 를 품어 **과대 인정**하므로 경계가 필요하다 —
관할 안 `@po_intRetVal INT` **단계×선언 쌍 70 중 16 이 가려져 있고, 통째로 가려진
단계는 0 이다.** 가려진 16 은 전부 이미 `@pi_strYMD` 때문에 발화하는 단계에 얹혀 있어
그 단계를 침묵시키지 못한다.

그래서 단위를 갈라 적는다:

| 수 | 지위 | 근거 |
|---|---|---|
| **단계 수 27** | **정확하다** | 가려진 쌍 16 이 전부 이미 발화하는 단계 위에 있다 — 숨은 항목이 단계를 침묵시킨 자리가 0 이다 |
| **파라미터 수 36** | **하한이다** — 경계 기준 실제 **≥ 52** | 36 + 가려진 16 = 52 |

이것은 **덜 고발하는** 방향이라 거짓 양성이 아니고 되돌림 조건도 건드리지 않는다.
이미 유보된 Minor(부분 문자열 과소 보고)라 이번에 손대지 않았다. 되돌림 판정이 서는
자리는 **단계 수**이고 그 수는 정확하므로, 이 Minor 는 §6-4 의 대조를 흔들지 않는다.
