## 2. 하네스 (재현용, 전문)

조율자가 `main 5192cb53` 에서 돌려 Batch6 에서 6:8 을 재현한 스크립트다. 그대로 옮겨
같은 워크트리에서 다시 돌렸다.

```bash
cd <워크트리 루트>
python3 - <<'PY'
import json,re,os,glob
def params(sp):
    p=f'output/Procedures/{sp}/raw/metadata.json'
    if not os.path.exists(p): return []
    return json.load(open(p,encoding='utf-8-sig')).get('StaticAnalysis',{}).get('ProcedureParameters',[])
def col(s): return re.sub(r'\s+','',s).lower()
for job in sorted(os.path.basename(p) for p in glob.glob('output/Jobs/*')):
    yes,no,skip=[],[],[]
    for f in sorted(glob.glob(f'output/Jobs/{job}/agent/steps/S*.md')):
        t=open(f,encoding='utf-8').read(); code=os.path.basename(f)[:-3]
        sps=sorted(set(re.findall(r'dbo\.UP_[A-Za-z0-9_]+',t)))
        ps=sorted({d for sp in sps for d in params(sp)})
        if not ps: skip.append(code); continue
        lines=[col(l) for l in t.split('\n')]
        miss=[d for d in ps
              if not any(col(d.split(' ')[0]) in l and col(d.partition(' ')[2]) in l for l in lines)]
        (no if miss else yes).append((code,miss))
    print(f'{job}: 적음 {len(yes)} {[c for c,_ in yes]} · 안 적음 {len(no)} {[c for c,_ in no]} · 재료없음 {len(skip)} {skip}')
    for c,m in no: print(f'    {c} 누락 {m}')
PY
```

## 4. Step 3 판정 — 「입력만」과 「전부」가 같은 발화를 내는가 (설계서 §3-1)

설계서 §3-1 은 「입력만」 기준(누락 목록에 `@pi` 로 시작하는 선언이 있어야 발화)과
「전부」 기준(입력이든 출력이든 누락이면 발화)이 코퍼스에서 같은 발화 집합을 낸다고
주장한다. 그 동률이 깨지는 첫 실물은 **누락 목록 전부가 `@po` 로 시작하는(즉 `@pi`
로 시작하는 항목이 하나도 없는) 「안 적음」 단계**다 — 그런 단계는 「전부」 기준으로는
발화하지만 「입력만」 기준으로는 발화하지 않는다.
