# 부록 — §4 가 남긴 S14·S15 를 읽었다 (2026-09-18)

§4 는 「§3-1 에서 S14·S15 가 **해당 없음**(업무 tx 나 `TRY` 가 없다)으로 나온 것을 따로 읽어야 한다」고 적었다. 읽었다. **둘 다 결함이 아니다.**

## B-1. S14·S15 는 공유 트랜잭션 그룹이다 — 「자체 tx 없음」이 설계다

B22 는 **S13~S15 가 하나의 공유 트랜잭션**이다(B21 의 S15~S17 과 같은 구조).

- **S14**(`S14.md:15`) 「`AcqManualSummaryStep`은 S13에서 연 연결과 SNAPSHOT 트랜잭션을 그대로 사용한다. **S14 자체에서는 새 트랜잭션을 시작하거나 커밋하지 않는다.**」 `TRY:`(29 줄)는 있고, 실패 시 `tx.rollbackIfOpen()` 뒤 별도 `failureTx` 로 기록한다.
- **S15**(`S15.md:18`) 「S15는 S13, S14가 사용한 **동일 연결과 동일 트랜잭션**을 이어받으며 자체 트랜잭션을 시작하거나 네 테이블을 개별 커밋하지 않는다.」 `sharedTx.commit()`(175 줄)이 셋을 함께 확정한다.

내 탐침이 「업무 tx 없음」으로 낸 것이 **그 자체로 설계**였다. S15 가 `TRY` 없음으로 나온 것도 그 절이 「C# 배치 실행 의사코드」라 표기가 달라서다.

## B-2. 거짓 경보를 냈고 두 번 걸러 냈다 — 「시작 삽입 수」는 결함의 자가 아니다

전 단계를 재니 **11 단계가 시작 저널·체크포인트 0** 이고 그중 8 이 성공 갱신(`WHERE StepStatus = N'Running'`)을 가져 **B21 S15 🟠 와 같은 모양**으로 보였다. 두 번 걸렀다.

1. **이름이 판마다 다르다.** `JOURNAL_START`·`CHECKPOINT_START` 는 **B21 계약의 이름**이고 B22 는 `SQL_INSERT_STEP_JOURNAL`·`SQL_INSERT_STEP_CHECKPOINT` 다. 계약은 판마다 모델이 쓰므로(§ 가드·트랜잭션 순서 사전 선언 §1-1) **계약 어휘도 판마다 다시 읽어야 한다.**
2. **관할이 단계가 아니다.** 이름을 고쳐도 11 이 0 이었는데, 공통 계약 전문을 읽으니 시작 삽입이 `TRY:` **앞** `controlTx` 에서 **모든 단계에 무조건** 돈다(`01-step-contract.md:27-36`). 게다가 단계 섹션 시스템 프롬프트가 「공통 규약은 이미 문서에 있다 — **따르되 다시 적지 마라**」를 못박는다.

**그러므로 「단계 본문의 시작 삽입 수」는 결함의 자가 아니다.** 오히려 다시 적은 9 단계가 계약에서 벗어난 쪽이고(무해), **B21 S15 를 🟠 로 만든 구멍은 B22 계약에서 닫혀 있다** — 시작이 공유 트랜잭션 **밖에서 무조건** 돌기 때문이다.

> zsh 에서 `${steps//,/ }` 가 안 갈려 첫 측정이 **빈 출력**을 냈다. 빈 칸을 0 으로 읽었으면 「둘 다 시작이 없다」는 거짓 결론이 그대로 섰다 — 메모리가 경고한 「빈 출력 = 0」 자리다. 파이썬으로 다시 쟀다.

## B-3. 예상 밖 — 처방이 **계약 본문에 새겨졌다**

B22 의 공통 계약이 이렇게 적혀 있다.

```
TRY:
    // 원본상 트랜잭션 밖에 있던 가드는 이 지점보다 먼저 실행한다.
    // 원본상 트랜잭션 안에 있던 가드는 tx 시작 후 실행한다.
    tx = conn.beginTransaction()
```

B21 의 같은 자리는 `TRY:` 뒤 `businessTx = step.requiresTransaction ? conn.beginTransaction() : noTransaction` 한 줄뿐이었다. **모델이 P1 조항을 계약 문장으로 옮겨 적었고 `begin` 을 `TRY` 안에 뒀다.**

**이것이 19 단계 전부가 그 모양을 물려받은 기전이다** — 단계마다 따로 설득된 것이 아니라 **공통 규약 한 곳이 바뀌었고** 그것이 `sharedConventions` 로 모든 단계 요청에 실렸다. B21 판독 §6 의 「골격 한 줄이 여덟 자리를 만든다」는 지렛대가 이번엔 **옳은 방향으로** 도는 것을 실물에서 봤다.

**따라서 §3-1 의 `begin<TRY` 0/17 은 「단계 열일곱이 각각 고쳐졌다」가 아니라 「계약이 한 번 고쳐졌다」로 읽어야 한다** — 표본 수가 17 이 아니라 사실상 **1** 이다. 분산은 여전히 안 쟀다.
