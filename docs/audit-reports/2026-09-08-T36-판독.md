## 4. ⚠ 내가 밟은 것 — 빨간 게이트를 커밋했다

`dotnet test 2>&1 | tail -3 && git commit …` 으로 돌려서 **파이프의 종료 코드가 `tail` 의
것(0)** 이라 실패 1 인 채로 커밋이 나갔다(`fc571431`). **같은 함정을 동료 세션이 그날
경고했는데 그대로 밟았다.** 다음 커밋(`3eb2f565`)에서 고쳤고, 이제 게이트는 **파일로 받고
`$?` 를 직접 찍는다.**

**깨진 것은 하나였고 오탐이 아니었다.** `ValidateBatchStep_ShouldAcceptTheBatchSchemaObjectsThePlanCreates`
가 「이 이름을 담은 오류가 하나도 없다」라 **축을 안 가리는 단언**이었고, 목차에
`batch.POQSettleCheckpoint` 를 안 적은 **픽스처가 새 축에 대해 부족**했다.
**단언을 좁히지 않고 픽스처를 고쳤다** — 그 시험의 본래 의도(「카탈로그에 없어도 받아들인다」)는
`Catalog` 가 여전히 그 이름을 모르므로 그대로 검증된다. **숫자를 맞추려 단언을 손보는 것과
픽스처의 부족을 고치는 것은 다르다** — 전자였으면 되돌렸어야 한다.

## 5. 「어느 쪽이 기준인가」를 안 풀고 닫았다

승인 표의 `Tables:` 는 목차의 기계 렌더이고 그 목차도 모델 산출이라 **양쪽이 순환**이다.
진리는 못 정한다. **해가 나는 방향**만 썼다 — 본문 ⊄ 목차는 실행 실패, 역방향은 과다 부여.
외부 오라클 없이 서는 자기일관성 검사다.

**방향이 맞다는 방증**(판정엔 안 썼다): `Batch5/S00.md:5` 가 스스로
「`batch.Journal`(**계약서 상 정식 명칭** `batch.BatchStepJournal`)」이라 적는다 —
모델이 목차가 틀렸다는 것을 알고 본문에서 교정해 쓴다.
