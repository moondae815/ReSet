## 0. 왜 B23 이었나

2026-09-19 에 처방 하나를 병합했다 — **골격이 이미 쓴 검증 SQL 세트를 단계 요청의 공유 접두사에 싣는다**(main `d3cf9993`). B22 축 B 감사의 도달 1 위 가족(검증 SQL 이름 공간 분열)을 닫으려는 것이고, 배선까지만 보증된 상태였다. **효력은 실물 판의 축 B 감사만이 확정한다.** B22 와 SP 14·모델·라우팅을 고정해 통제 비교로 잡았다.

## 4. 🔴 2 → 18 을 「처방이 나쁘다」로 읽으면 안 되는 이유와, **그래도 처방의 대가인 이유**

**B22 의 🔴 둘은 「단계가 검증을 지어냈다」였고 그 계열은 재현되지 않았다.** B23 의 🔴 18 은 **다른 원인**이다 — 세트를 부르게 만들었더니 단계들이 그것을 **게이트로 썼고**, 세트 술어가 원본의 허용 범위를 담지 못한다.

세트 공통 규약은 **「검증 실패는 S18 이 `batch.BatchValidationIssue` 에 기록한다」**(`integrity-sql.md:10`)인데, 단계 10 곳이 같은 블록을 자기 트랜잭션 안에서 커밋 전에 돌리고 `ViolationCount != 0` 이면 전량 롤백한다. **그래서 술어의 헐거움이 「이슈 한 줄」이 아니라 「배치 전면 중단」이 된다.**

| 단계 | 정상 데이터를 거부하는 이유 |
| :-- | :-- |
| **S02 🔴** | SQL-01 의 `ORPHAN_LOCK` 분기에 `@RunId`·`JobName`·`BatchYmd` 필터가 **하나도 없다** — 다른 Job 의 고아 잠금 하나로 배치가 시작조차 못 한다 |
| **S08 🔴🔴** | SQL-07 의 같은 술어 목록에서 `:410`·`:411` 은 `NULLIF(col,'')` 로 공백을 인식하고 `:412`·`:413` 은 맨 `IS NOT NULL` 을 쓴다 — **한 목록의 두 술어가 반대 전제**. 게다가 원본이 명시적으로 커밋하는 `OutState IN (1,2,5)` + 빈 `OutYMD` 를 위반으로 센다 |
| **S09 🔴** | SQL-08 의 `DuplicateRows` 가 `CID`(=SeqNo)·`AYMD` 를 키에서 빼 원본이 정상 적재하는 부분취소 다건을 중복으로 잡는다 |
| **S10 🔴** | 보호 멀티셋 캡처 술어가 **삭제 술어와 한 글자도 다르지 않은데** 그 행의 「완전 보존」을 요구한다 — 구조적으로 항상 발화 |
| **S05 🔴** | 게이트 술어가 원본 술어와 글자 그대로 같고 날짜 제한도 없다 — 원본이 커밋하는 조인 다중성을 중단으로 바꾼다 |
| **S07 🔴🔴** | UPDATE 7 직후에만 성립하는 등식을 15 개 UPDATE 를 다 돌린 뒤 단언하고, 파생 테이블 `K` 를 **갱신 후 테이블에서 재집계**해 불변식이 아니다 |
| **S04·S03·S17 🔴** | 기대 행 수가 최상위 `LEFT OUTER JOIN` 을 빠뜨렸다 · 대상에 `VERSION` 칸이 없는데 원천은 그것을 키로 갖는다 · 보정 단위 15열을 8열로 묶고 절대값 0 을 요구한다 |
| **S12 🔴** | **반대 방향(과소)** — 재시작 스킵 판정을 `CLSettleAmt` 한 값에 맡겨 **롤백된 실행도 「성공」으로 확정**될 수 있다 |

## 8. 이 판독이 보증하지 않는 것

- **축 A 를 안 돌렸다.** 19 판정 전부가 「명세서가 옳다」는 전제 위에 있고, 2026-09-08 재생성 뒤 명세서는 원본 DDL 과 대조된 적이 없다. **그리고 이번 처방은 축 A 로 검증된 적 없는 검증 세트를 정본으로 승격시켰다** — 사전 선언 §6 이 예고한 위험이 이제 실물이다.
- **실행 대조 없음.** 🔴 18 중 여럿이 **배포 구성 전제**를 명시한 채 높은 쪽으로 매겨졌다 — `batch` 스키마 공유 여부 · 날짜 컬럼 기본값이 `''` 인지 `NULL` 인지 · `TPGProperty.PGName` 중복 · `RefundTxType` 값역 · `ROWCOUNT` 예약어 판정.
- **후속 단계 간섭을 아무도 판정하지 않았다**(19/19 보류). 특히 요약 체인(S14·S15·S16)의 최종 작성자 관계가 미판정이다.
- **단위 간 갈린 자리를 상위가 고르지 않았다** — S13·S12 가 선언한 직렬 제약이 계획서의 병렬 분기 계약과 어긋난다.
- **교정본의 정본화를 판정하지 않았다** — 교정본이 `S07.md`·`S11.md`·`S12.md` 에 흩어져 있고 세트는 교정 전이다. 어느 파일을 정본으로 삼을지는 사람 결정이다.
- **B22 대비 🔴 2 → 18 의 분모는 같다**(19 단위 · 같은 SP 14 · 같은 모델·라우팅). 다만 **B22 는 V 절 87 요구를 S18 단위가 처음 전수로 셌고** B23 은 그 자리가 없으므로, 등급별 절대 수의 비교는 가족 단위로만 읽어라.
