# 최상위 술어 대조(P)가 함수 인자를 감싼 괄호에 걸린다 (사전 선언)

**작성 시점**: 2026-09-16, **구현 전**. **코드**: main `532ff721`.

## 0. 잰 것

교차 분류(`2026-09-14-GPT판-B11-B16-교차분류-사전선언.md` §가)에서 찾은 오탐이다. GPT 판 **여섯 판 전부**가 `UP_UTIL_SETTLE_EXCEPTION_PROC` UPDATE 3 에서 같은 메시지로 재생성됐다.

```
원본 DDL                       dbo.UF_GET_CLIENTSECTIONRATE(A.CLIENTID,A.PGNAME,A.MALLID, (A.TXAMT-ISNULL(A.NonSettleAmt,0))) <> 0
B16 S07 첫 초안(재생성됨)      dbo.UF_GET_CLIENTSECTIONRATE( A.CLIENTID, A.PGNAME, A.MALLID, A.TXAMT - ISNULL(A.NonSettleAmt, 0) ) <> 0
B16 S07 둘째 초안(통과)        dbo.UF_GET_CLIENTSECTIONRATE ( A.CLIENTID, A.PGNAME, A.MALLID, (A.TXAMT - ISNULL(A.NonSettleAmt, 0)) ) <> 0
```

차이는 **네 번째 인자를 감싼 괄호 하나**뿐이고 값은 같다. `DmlScopeExtractor.PredicateTermsOf` 의 정규화(R1~R6)는 **토큰을 한 칸으로 이어 붙이는 방식**이라(`RenderNormalizedTokens`) `(`·`)` 토큰이 그대로 대조 키에 들어간다.

| 관할 | 발화 | 그중 괄호만 다른 것 |
| :-- | --: | --: |
| 판 안(GPT 판 여섯의 로그) | 7 | **6**(B11 S08 · B12·B13·B14·B15 S06 · B16 S07 — 전부 위 식) |
| 배송본(현재 main 스윕 `2026-09-16-step-sweep-txn-split.md` 검사 P) | 2 | 0 — B4 S15 INSERT 1 · B7 S12 INSERT 4 는 다른 사유(설계서가 든 실물) |

판 비용은 판마다 재생성 1 회다(그 판의 다른 사유와 겹치지 않은 판에서는 그 호출 전부가 이 오탐 때문이다).

## 1. 설계 — 좁게 고친다

**함수 호출의 인자 자리에 있는 괄호만** 대조 키에서 지운다. 인자는 쉼표로 이미 갈려 있어 괄호가 우선순위를 바꾸지 않는다 — 지워도 잃는 정보가 없다.

- 구현 자리: `PredicateTokenEdits`(원본·이행이 함께 쓰는 정규화기) 에 `FunctionCall` 방문을 더해, 인자가 `ParenthesisExpression` 이면 그 여는·닫는 괄호 토큰을 `Dropped` 에 넣는다(중첩이면 안쪽까지).
- **넓히지 않는 이유**: 모든 `ParenthesisExpression` 의 괄호를 지우면 `(A + B) * C` 와 `A + (B * C)` 가 같은 키가 된다 — 우선순위가 사라져 **다른 식을 같다고 말한다**. 이 저장소가 「이름·모양으로 짐작」에서 두 번 실패한 것과 같은 계열의 위험이라, 코퍼스가 실제로 낸 자리(함수 인자)만 좁혀 고친다.
- 메시지·처방 문구는 그대로다. `Raw`(사람이 읽는 원문)도 건드리지 않는다 — 괄호는 원문에 남는다.

**캐시 버전**: 올리지 않는다(프롬프트 불변 · L1 만 느슨해짐 — 스윕 차분으로 대신한다).

## 2. 합격선

| # | 항목 | 합격 |

**오탐 방향**: 검사 P 는 발화를 줄이기만 한다(한 방향 `added` 만 본다). **놓침** 위험은 R2 가 막는다 — 인자 자리 밖 괄호는 손대지 않으므로 우선순위를 바꾼 이행은 계속 다른 키다.
**효과 판정**: 다음 GPT 판에서 이 사유의 재생성이 0 인지 본다(지금까지 6/6).
