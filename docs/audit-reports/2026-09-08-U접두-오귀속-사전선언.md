## 1. 무엇을 고치는가

`POQSettleBatch5/S13` 이 앵커를 **`U13-DELETE 1`·`U13-INSERT 1`** 로 적는다.
`U13` 은 **단계 범위 접두사**이고 **진짜 서수는 뒷부분**이다.

그런데 `AnchorPattern` 은 **가장 왼쪽 매치**를 잡으므로 `\bU` 가 `U13` 에 먼저 맞아
**서수 13** 을 집는다. 그 프로시저(`SUMMARY_ETC`)의 명세서에 `(DELETE, 13)` 행이 없으므로
**앵커 계열 검사가 대조할 행을 못 찾고 조용히 지나간다** — `S15` 가 앵커를 못 받아 검사가
꺼져 있던 것과 **같은 모양의 조용한 커버리지 손실**이다.

**대안 순서로는 못 고친다.** 정규식은 가장 왼쪽에서 성립하는 매치를 잡으므로, 키워드 대안을
앞에 놓아도 `U` 자리에서 `\bU` 가 성립하는 한 그것이 이긴다.

## 2. 처방 — `U<n>` 뒤에 `-` 가 오면 앵커가 아니다

```
(?:\bU|…)   →   (?:\bU(?!\d{1,2}-)|…)
```

**근거**: `U13-DELETE 1` 은 「U13」이 아니라 **복합 라벨**이고, 그 안의 진짜 앵커는 `DELETE 1` 이다.
정상 표기(`/* U13: … */`)는 숫자 뒤가 `:`·공백이라 영향이 없다.

## 3. 발화 단위 — **오귀속 문장 수. 코퍼스 전체 2 → 0.**

**착수 전 실측(던지는 변경으로 확인, 되돌렸다).**

```
오늘        앵커 262 · 명세서에 없는 (Kind,서수) 쌍 2   (Batch5/S13 의 DELETE·INSERT, 앵커 13)
처방 (c)    앵커 262 · 명세서에 없는 (Kind,서수) 쌍 0   ← 손실 0 · 스윕 완전 불변
```

**이 표기를 쓰는 것은 코퍼스에서 `Batch5/S13` 한 편뿐이다**(`U13-INSERT` 2 · `U13-DELETE` 2 ·
`U13-SELECT` 1).

## 4. 여섯 조건 — 앞 다섯을 착수 전에 실측했다

| # | 조건 | 값 |
| ---: | :--- | :--- |
| 1 | 재료 | 단계 본문의 주석 |
| 2 | 도달 | `ReadAnchor` 는 모든 단계에서 돈다 |
| 3 | 그 자 | `(Kind, 서수)` 쌍이 명세서에 있는가 — 이 회차가 세운 프로브가 그 자다 |
| 4 | 효과 | 오귀속 **2 → 0** · 앵커 **262 불변**(잃는 문장 0) |
| 5 | 오탐 | **스윕 완전 불변** — 고쳐진 두 문장이 검사를 통과한다 |
| 6 | 없앴을 때 | 오귀속이 0 → 2 로 돌아오고 시험이 빨개져야 한다 |

## 5. 되돌림 조건

- **R1**: 오귀속이 **0 이 아니면** 되돌린다.
- **R2**: 앵커가 **262 가 아니면** 되돌린다(잃는 문장이 하나라도 있으면 포함).
- **R3**: 스윕에서 **검사 A~E 나 미분류가 하나라도 변하면** 되돌린다.
  기준선 `sweeps/2026-09-08-step-sweep-b.md` — **A 0 · B 2 · C 1 · D 0 · E 0 · 미분류 27**.
- **R4**: 되돌렸을 때 되살아나는 오귀속이 **정확히 그 2** 가 아니면 되돌린다.

## 6. 안 하는 것 · 알려진 한계

- **`U<n>` 대안 자체는 그대로 둔다.** 정상 표기를 계속 읽어야 한다.
- **다른 복합 라벨 모양(`U13_DELETE`·`U13 DELETE`)은 안 다룬다** — 코퍼스에 0 건이고,
  없는 것을 상대로 정규식을 넓히면 판별력만 잃는다. **`-` 하나만 배제한다.**
- **`AnchorPattern` 이 종류를 버리는 성질은 그대로다** — 이 처방은 `U` 접두 오귀속만 고친다.
- **캐시 인상 없음** — 리더만 고친다.
