**작성 시점**: 2026-09-14. 코드: main `507cb01b`. 로그: `output/logs-planonly-POQSettleBatch8`~`13`.

## 0. 물음

K2 검증 세트판 판독(`2026-09-14-K2-검증SQL세트-사전선언.md` 발견 1)이 `L1ViolationAttribution.MapRegions` 가 단계 안의 코드 없는 `####` 하위 헤딩 아래를
`Unknown` 으로 둔다는 것을 찾았다. GPT 판 단계 대부분이 그 모양이라, **어휘로 단계에 귀속되는 통합 L1 위반이 전량 재생성으로 떨어졌는가**를 잰다.

## 1. 분모 — 통합 L1 위반이 실제로 몇 번 났나

로그 표지: 위반 `L1 기계 검증 오류 발견 (시도 N/M)` · 귀속 성공 `L1 위반을 … 자리로 좁혀 그 자리만 다시 만듭니다`.

| B8 | claude-cli | 3 | 1 |
| B9 | claude-cli | 3 | 2 |
| B10 | claude-cli(1 회 판) | 0 | 0 |
| **B11 · B12 · B13** | **GPT** | **0** | 0 |

**GPT 세 판에서는 통합 L1 위반이 한 번도 안 났다** — 하위 헤딩 한계가 GPT 판에서 비용을 낸 적은 **아직 없다**(발생 0 이라 「없었다」가 아니라 「잴 표본이 없었다」).

## 3. 원인 — 두 겹

### ① 귀속 불가: `CheckControlTotalProducer` 는 `DetailedError` 를 안 낸다

`ValidateConsolidated` 가 부르는 검사 9 개를 분류했다(메서드 본문의 `Report` · `DetailedErrors.Add` 수).

| 검사 | `Report` | `DetailedErrors.Add` |
| :-- | --: | --: |
| `ValidateMarkdownStructure` | 2 | 2 |
| `CheckVerificationCartesianComparison` | 1 | 1 |
| `CheckBatchRunRowCreation` | 1 | 1 |
| **`CheckControlTotalProducer`** | **1** | **0** |
| `CheckLegacyReturnCodeBinding` | 1 | 1 |
| `CheckNoLockHints` | 1 | 1 |
| `CheckPrescribedFrameworkType` | 1 | 1 |
| `CheckSqlSideControlFlow` | 1 | 1 |
| `CheckNewDatabaseObjectDefinition` | 1 | 1 |

`ValidationResult.Report` 는 `Errors` 와 `Firings` 에만 더한다. 오케스트레이터 귀속은 `DetailedErrors` 만 순회하므로(원본 오류 코드 누락은 별도 `codeAttribution`) **이 검사의 위반은 구조적으로 어느 자리에도 귀속되지 않고 늘 전량 재생성**이다. 9 개 중 이 하나뿐이다.

### ② 오탐: 같은 **펜스** 안에서 표 언급과 자기 제외를 짝짓는다

B8 S22(6 차본, 발화한 판)의 펜스 하나에 두 문장이 있다.

```sql
-- SQL_CHECK_PRIOR_STEPS_SUCCEEDED
SELECT COUNT(*) FROM batch.BatchStepJournal
 WHERE RunId = @p_runId
   AND StepCode <> N'S22'          ← 자기 제외는 BatchStepJournal 의 조건
   AND StepStatus <> N'Succeeded';

-- SQL_INSERT_CONTROL_TOTALS
INSERT INTO batch.BatchControlTotal (RunId, StepCode, ControlName, ControlValue, CapturedAtUtc)   ← 통제표는 INSERT 만
```

S22 는 `batch.BatchControlTotal` 을 **읽지 않는다.** 검사는 「같은 펜스에 표 이름과 `StepCode <> N'S22'` 가 함께 있다」만 보고 「다른 단계가 적재한 제어합계를 기대값으로 삼는다」고 고발했다 — **오탐이다.**
3 차의 같은 문구 발화는 그 판의 문서가 로그에 없어(리뷰 전 L1 실패라 Critic 페이로드가 없다) 판정하지 못했다.

## 4. 이것이 바꾸는 것

- **B8 의 「최고점 채택이 2 시간 51 분을 버렸다」의 원인은 채택 규칙이 아니라 이 L1 오탐 + 귀속 불가였다.** 1 회 판 Critic 방침 판독(`2026-09-13-1회판-Critic-지적-방침.md` §3)과 메모리가 B8 을 「채택 규칙이 수정을 버린 사례」로 들었는데, 버려진 직접 원인은 6 차의 거짓 L1 실패다. 채택 규칙이 수정을 버린 사례로 남는 것은 **Batch13**(Critic 골격 지적 → 골격 전면 재작성)이다.
- **하위 헤딩 한계**는 잠재 결함으로 남는다 — GPT 판에서 통합 L1 위반이 나기 시작하면 비용이 된다. 지금 고칠 근거(관측된 비용)는 없다.
- **고칠 것**: `CheckControlTotalProducer` — ① 문장 단위로 「제어 표를 **읽는** 문장 안의 제어 표 한정 `StepCode <>` 」만 자기 제외로 인정 ② `DetailedError`(자리 = 그 단계)를 내 귀속되게 한다.

## 5. 보증하지 않는 것

- B8 3 차 발화의 진위(문서 없음).
- 디스크로 B8 6 차 조립 문서를 재구성하면 L1 이 0 이다 — B8 5·6 차는 2 차로 되돌린 뒤 만든 판이라 디스크 파일(4 차 이후 마지막 판 혼합)이 그 문서와 다르다. 위 오탐 판정은 **발화한 단계 파일(S22 6 차본)** 만으로 한 것이다.

# 수정 설계와 합격선 — `CheckControlTotalProducer` (구현 전)

## 설계

- **자기 제외를 문장 단위·파서로 판정한다.** 펜스를 최상위 세미콜론 문장으로 자르고(`StepSqlStatementReader.SplitAtTopLevelSemicolons`) ScriptDom 으로 파싱해,
  **그 표를 FROM·JOIN 으로 읽는 `QuerySpecification`** 의 WHERE 에서 **그 표에 한정된(또는 한정자 없는) `StepCode <> / != N'코드'`** 만 자기 제외로 인정한다.
  INSERT 대상으로만 나오는 표, 같은 펜스·같은 문장의 **다른 표** `StepCode` 조건은 인정하지 않는다(K2 `ControlTotalNameFacts` 와 같은 원칙).
- **귀속**: `DetailedError`(새 `ErrorType.ControlTotalWithoutOtherProducer`)를 내고 `OwnerStepCode` = 그 단계. 오케스트레이터 귀속 루프는 **`OwnerStepCode` 가 있으면 유형과 무관하게 그 단계를 연다**
  (K2 검증 세트판의 유형별 `case` 를 일반 규칙으로 올린다 — 검사가 자리를 안다는 사실은 유형의 속성이 아니다).
- 생산자 판정(`CreatesRowIn`)과 처방문은 그대로 둔다.
