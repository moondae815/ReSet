## 1. 결함 — 원본이 명시적으로 쓴 방어 둘이 사라졌다

```sql
-- 원본 dbo.UP_UTIL_SETTLE_PROC_ETC (object_definition.sql:32·116·137)
DECLARE @v_intPostChkAmt1  MONEY = 0
SELECT  @v_intPostChkAmt1 = ISNULL(SUM(CAST(CLTotal AS MONEY)), 0)
IF      @v_intPostChkAmt1 <> @v_intPostChkAmt2 BEGIN   -- 대사

-- 후 단계 output/Jobs/POQSettleBatch1/agent/steps/S09.md:169
SELECT SUM(A.CLTotal) AS PostChkAmt1
```

**둘을 잃었다.**

1. **`CAST(… AS MONEY)`** — 원저자가 **명시적으로** 썼다. 즉 `CLTotal`은 `MONEY`가 아니다.
   캐스트가 없으면 원천 타입의 소수부가 절삭돼 두 집계가 다른 자리에서 반올림된다.
2. **`ISNULL(…, 0)`** — 없으면 무결과일 때 `NULL`이 된다. 그리고 대사가 `<>`라
   **한쪽이 `NULL`이면 비교가 `UNKNOWN`이 되어 `IF`가 아예 안 탄다** — 불일치가
   보고되지 않고 조용히 지나간다. 오류 코드 `-3`이 그 자리다(명세서 233행).

`S09.md:181`(`SELECT SUM(CLSettleAmt) AS PostChkAmt2`)이 같은 모양의 짝이다.

## 2. 오라클 — 명세서 지역 변수 표. **다른 둘은 실측으로 기각했다**

| 후보 | 오라클 | 판정 |
| :--- | :--- | :--- |
| **A** 명세서 지역 변수 기계 표 | `데이터 타입` + `초기값` | **채택** |
| B 원본 DDL 재파생 | `DECLARE @v MONEY = 0` | **기각** — 아래 |
| C 자기 일관성(오라클 불필요) | — | **기각** — 아래 |

**C를 기각한 이유는 산출물 자신이다.** 대사 쌍인 `SELECT 5`·`SELECT 6`이 **둘 다** 방어가 없다.
대칭이므로 「한쪽만 다르다」로는 안 걸린다.

**B를 기각한 이유는 신호 밀도다.** 「원본이 쓴 방어가 단계에서 사라졌다」로 부류를 넓히면:

```
                 원본 DDL(전체 SP)   Batch1 단계
ISNULL(                     286          301     ← 늘었다
CAST(                        88          121     ← 늘었다
PROC_ETC 단독 CAST(           2            0     ← 전량 소실
```

**단계가 원본보다 방어를 더 쓴다.** 방어 소실은 계통적 현상이 아니라 **한 자리의 사건**이다.
넓히면 분모 286에 신호 2가 되어 착수 조건 ⑤(오탐이 다수가 아니다)에 걸린다.
**좁은 자리에만 신호가 있고, 그 자리를 명세서 표가 정확히 확정한다.**

**A의 약점은 재료 소멸이다** — T02가 바로 그 사고였다(그 표가 명세서에서 사라졌다).
§3이 그것을 처방한다. 이 처방이 있으면 B의 「재료가 불멸이다」라는 유일한 우위가 상쇄된다.

### 재료 상태 — 절반은 이미 흐른다

`SpecLocalVariable(Name, TypeOrKind, IsSystemValue)`를 낸다(검사 D가 소비 중).
**`초기값` 칸만 안 읽는다.** 추출기에 한 칸을 더하는 것이 재료 작업의 전부다.

## 3. 침묵을 발화로 — **T02를 만든 실패 모드를 직접 막는다**

T02의 발생 경위는 「명세서에서 표가 사라졌는데 아무도 몰랐다」이다.
검사 D가 18 → 0으로 꺼진 것과 같은 모양이고, 이 저장소가 **세 번째로** 겪는 자리다.
**그러므로 표가 사라지면 「통과」가 아니라 발화한다.** 이것이 A의 유일한 약점에 대한
처방이고, B를 안 써도 되는 이유다.

### 다만 「표가 없으면 발화」로 쓰면 안 된다 — 오탐이 다수가 된다

**초판의 결함이다. 병행 세션 `reset-06`이 물어서 재고 고쳤다.**

```
표 있음 9 편 — 원본 DECLARE 1~15 (PROC_ETC 12 · SUMMARY_ETC 15 · EXCEPTION_PROC 3 …)
표 없음 5 편 — 원본 DECLARE **전부 0**
              CANCEL_INS · INS · STAT_PGCOLLECT_INS · CMRate_Ins · Settle_Summary
```

**「9/14」는 미달이 아니라 전량이다.** 그 다섯은 원본에 지역 변수가 없어서 쓸 표가 없다.
그대로 발화시키면 **오탐 5 대 진짜 최대 1**이 되어 착수 조건 ⑤에 걸린다.

### 그래서 못박은 명부로 «사라짐»만 본다

표를 가져야 하는 SP를 **명부 파일에 못박고**, 명부에 있는 SP에서 표가 없으면 발화한다.
명부에 없는 SP는 묻지 않는다.

- 초기 명부 = 2026-09-05 실측의 **9편**. 오탐 **0**.
- **명부를 고치는 것은 사람이다.** 그것이 이 파일의 요점이다 —
  `documentation-budget-baseline.txt`가 상한을 사람에게 맡긴 것과 같은 전례를 따른다.
- 명부는 **DDL을 검사 때 읽지 않는다.** 한 번 사람이 확인해 적은 사실이므로
  §2에서 기각한 접근 B(검사 때 DDL 재파생)로 돌아가는 것이 아니다.

**이 명부는 T02 하나보다 넓다** — 검사 D도 같은 표를 먹고 같은 방식으로 침묵한다.
그러나 **이 설계는 검사 D의 침묵까지 닫는다고 주장하지 않는다.** 명부를 여기서 세우고,
검사 D가 그것을 쓸지는 별건이다.

## 4. 판별자 — §7이 열어 둔 물음에 답한다

§7의 물음: 「«`CAST`가 있는가» 인지 «타입이 같은가» 인지」. **둘 다 아니다.**

- **「타입이 같은가」** — 못 잰다. 단계는 의사코드라 타입 표기가 없고 그게 결함의 내용이다.
- **「`CAST`가 있는가」** — 오탐한다. `CAST`는 코퍼스에서 88 → 121로 **늘었다**.
  유무만 보면 신호가 없다.
- **채택: 「명세서가 금액형·초기값으로 확정한 변수를 채우는 *집계*가 그 둘을 보존하는가」**

### 절차

1. 명세서 지역 변수 표에서 **금액형**(`MONEY`·`DECIMAL`·`NUMERIC`·`FLOAT`)이고
   **초기값 칸이 비지 않은** 행을 뽑는다.
2. 변수명의 **어근**을 얻는다 — 별칭이 변수명의 **접미**인지로 붙인다
   (`PostChkAmt1` ⊂ `@v_intPostChkAmt1`). **헝가리 접두 목록에 기대지 않는다.**
3. 단계 SQL 펜스에서 그 어근을 **별칭으로 쓰는 `SELECT` 투영**을 찾는다.
4. 그 투영식이 **집계**(`SUM`·`AVG`·`MIN`·`MAX`·`COUNT`)일 때만 본다.
   상수 대입(`@v_valIncVat = 1.1` 두 건)은 여기서 걸러진다.
5. **타입 표기**(`CAST`·`CONVERT`)와 **NULL 방어**(`ISNULL`·`COALESCE`)를 각각 본다.
   없는 쪽을 이름 붙여 발화한다.

### 왜 앵커를 안 쓰는가

이름이 **세 층에 살아남는다**.

```
명세서    @v_intPostChkAmt1 | MONEY | 0
의사코드  vPostChkAmt1 = queryScalar(SQL_CHECK_MST_AMOUNT, …)
단계 SQL  SELECT SUM(A.CLTotal) AS PostChkAmt1
```

접미 일치로 붙으므로 **서수 앵커가 필요 없다.** 그러므로 이 검사는
**검사 B의 도달률 상한(관할 1,413 중 852 = 60.3%)과 무관하다** — 분류 문서 §13 참고.

## 7. 이 설계가 보증하지 않는 것

- **코퍼스 방어망이 아니다.** 재료가 5행이고 전부 한 SP에 있다. 그 이상을 주장하지 않는다.
  넓히려면 §2의 실측(286/88)을 다시 보라 — 넓힌 판은 이미 기각됐다.
- **`CLTotal`의 실제 DB 타입을 확인하지 않았다.** 원저자가 `CAST`를 썼다는 사실로
  「`MONEY`가 아니다」를 **추론**했다. 로컬 Docker는 빈 스키마라 실행으로 못 닫는다.
  이 추론이 틀려도 검사는 성립한다(명세서가 확정한 타입을 보존하라는 것이므로).
- **대사 로직 자체는 안 본다.** `<>` 비교가 `NULL`에서 안 타는 것은 이 검사의 발화 사유이지
  검사 대상이 아니다.
- **검사 D의 침묵은 안 닫는다.** 명부를 여기서 세우지만 검사 D가 그것을 쓰게 하는 것은 별건이다.
- **명부의 초기값 9편은 오늘의 실측이다.** 명세서가 재생성되어 새 SP가 표를 얻으면
  사람이 명부에 더해야 한다 — 검사는 그것을 자동으로 알지 못한다. 의도된 설계다.
- **N4의 나머지가 이 검사로 전부 닫히는지 재지 않았다.** §7이 「같은 두 문장」이라 적었고
  그 둘은 덮이지만, N4 항목 전체의 소멸은 발화를 보고 판정한다.

### §4 판별자의 전제가 거짓이었다

```sql
-- dbo.UP_UTIL_SETTLE_PROC_ETC/raw/object_definition.sql
46:  ,SUM(A.CLTotal)             AS CLTotal     ← CAST 없음 · ISNULL 없음
47:  ,SUM(A.CLTotal-A.CLVT)*(-1) AS CLComm      ← 없음
48:  ,SUM(A.CLVT)          *(-1) AS CLVT        ← 없음
116: SELECT @v_intPostChkAmt1 = ISNULL(SUM(CAST(CLTotal      AS MONEY)),0)  ← 여기만
130: SELECT @v_intPostChkAmt2 = ISNULL(SUM(CAST(CLSettleAmt AS MONEY)),0)  ← 여기만
```

오탐 18 은 전부 `@v_intCLTotal`·`@v_intCLComm`·`@v_intCLVT` — **커서 원천 질의의 집계이고
원본 자신이 방어를 안 쓴다.** 실물: `POQSettleProc15/S15.md:89-90` 이 원본 47-48 행을
**충실히 옮긴 것**인데 결함으로 짚었다.

**§4 는 「명세서가 금액형·초기값으로 확정했으면 그 변수를 채우는 집계는 방어를 가져야 한다」로
섰는데 그 전제가 거짓이다.** 초기값 `0` 은 `DECLARE` 가 주는 것이지 **모든 대입 자리가 재현해야
하는 것이 아니다** — 커서 `FETCH` 는 방어 없이 대입하고 그것이 옳다.
**방어를 요구할 자리를 정하는 것은 명세서의 표가 아니라 원본이 실제로 방어를 쓴 자리다.**

### 그러면 오라클을 원본 DDL 로 바꾸면 되는가 — **아니다. 실측으로 기각한다**

- **잘 결합하면 재료가 2 행이다.** 원본이 「집계 + 방어」로 **선언 변수에 대입**하는 자리는
  코퍼스 전체에서 위의 `PROC_ETC:116`·`130` 둘뿐이다. **T22 와 같은 크기인데**
  검증기에 `DdlText` 오라클 통로를 새로 뚫어야 해 **T22 보다 훨씬 비싸다.**
- **넓히면 결합이 안 된다.** 「원본이 방어를 씌운 자리」는 21 건(`STAT_PGCOLLECT_INS` 11 ·
  `Settle_Summary` 3 · `SUMMARY_EXTRA` 3 · `PROC_ETC` 2 · `SUMMARY_ETC` 1 · `AcqManual` 1)인데,
  그 자리를 단계 문장에 붙이려고 거친 자를 대니 Batch1 에서만 「방어 없음 53」이 나왔다 —
  **25 배 과대계상**이고 **판별자를 죽인 것과 같은 실패 모드**다.

### T02 는 닫히지 않았다 — **크기 판정을 정정한다**

**§7 의 「남는 길은 검사뿐이고 크기는 바운디드」가 틀렸다.** 기계로 닫으려면
**「원본의 그 자리와 단계의 그 문장을 어떻게 붙이는가」**를 먼저 풀어야 하고, 그것은
**앵커 도달률(관할 1,413 중 852 = 60.3%) 문제와 같은 뿌리**다.
**T02 는 싼 항목이 아니라 결합 문제에 매달린 항목이다.**

### 이 회차가 가르친 것

이 검사는 **게이트를 통과**했고(실패 0 · 건너뜀 0 · 경고 0), **단위 시험 다섯이 전부 초록**이었고,
**독립 리뷰 둘이 임시 시험까지 돌려** 판별자의 최우선 함정(술어 `ISNULL` 오인)까지 실증으로
배제했는데도 **코퍼스에서 90% 오탐**이었다. 오늘 **세 번째**로 같은 자리다(접힘 판별자 · T22 · 이것).
**코퍼스 실측을 계획의 게이트로 둔 것만이 이것을 잡았다.**
