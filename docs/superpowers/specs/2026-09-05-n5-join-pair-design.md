# N5 — 조인 짝을 원본 DDL 에서 재파생해 대조한다 (설계·되돌림 조건)

**이 문서는 코드보다 먼저 커밋한다.** 이 회차가 두 번 되돌렸는데(접힘 판별자 · T22) **되돌릴 수
있었던 것은 「무엇이 나오면 되돌리는가」가 착수 전에 파일에 있었기 때문**이다. 대화에만 두면
숫자를 맞추려고 조건을 손보게 된다.

- 대상: 축 B 잔여 분류 §1 의 **N5**(`K¹`) — `EXPECT_PROC` 갱신 11 의 `TClientCMRate` 결합이
  `B.*` → `A.*` 로 옮겨갔다. 원본은 **주결제수단**의 정산주기를 쓰는데 이행은 **포인트결제 자신**의
  것을 쓴다.
- 방식: §10 이 정한 **B안(검사 때 원본 DDL 에서 재파생)**. A안(명세서에 싣기)은 재료가 재생성에
  사라져 기각됐다.
- 기준 커밋: `main` `d9d28264`. 코퍼스 재생성은 사람이 **미뤘다**(2026-09-05, 세션 `reset-06`) —
  아래 분모가 유지된다는 전제로 잰다.

### ①을 재다가 하마터면 오탐을 배송할 뻔했다 — 옛 스타일 콤마 조인

첫 측정이 `ON` 절만 봤다. 다시 재니:

```
                          ON 만    ON ∪ WHERE
조인 등식을 가진 문장        12        38
조인 짝 총수                 39       124   (WHERE 쪽이 85)
WHERE 에만 조인 조건이 있는 문장  —      26   (38 중 68%)
```

**원본 SP 는 옛 스타일 콤마 조인이 지배적이다.** `ON` 만 보면 짝의 **69% 를 놓치고**, 그 26 문장에서
이행의 정상 조인이 전부 「이행이 더한 것」으로 보여 **오탐이 쏟아진다.** 그래서 원본 수집 범위가
설계의 일부다(§2-1).

## 2. 설계

### 2-1. 원본 짝은 `DmlScopeExtractor` **안에서** 뽑는다

별도 방문자를 만들지 않는다. 이유는 **서수 귀속**이다 — 짝을 `UPDATE 11` 에 붙이려면 그 번호가
명세서·앵커와 같은 체계여야 하는데, 번호를 두 곳에서 매기면 조용히 갈린다. 이 저장소가
「사본을 두면 규칙이 갈린다」로 이미 세 번 겪은 모양이다(`BareObjectName`·`ResolveOrdinal`·
`TableHeaderCells` 가 같은 이유로 공유된다).

- 수집 범위는 **`ON` ∪ `WHERE` ∪ 하위 스코프 전체**(§1 의 실측이 이유).
- 조인 등식의 판정은 기존 **`HaveDifferentQualifiers` 를 그대로 재사용**한다 — 한정자 둘이 다를
  때만 조인 키다. `A.YMD = A.AYMD` 나 한정자를 알 수 없는 비교는 아니다. 이 규칙은 리뷰 라운드 2 가
  오탐 여섯 자리(`EXCEPTION_PROC` 210·228·271·290, `COMM_UPD` 58, `EXPECT_PROC` 48)로 산 것이다.
- 별칭을 테이블로 해석해 `테이블.컬럼` 쌍으로 정규화하고, **두 변을 정렬해 방향을 없앤다.**
- 테이블 이름은 `BareObjectName`(마지막 식별자) — 검사 B 와 같은 규약.

### 2-2. 이행 짝은 리더가 **최상위만** 본다

`StepSqlStatement` 에 `JoinPairs` 를 더한다. 정규화 규칙은 원본과 같고 **범위만 좁다**(기존
`JoinColumns` 와 같은 최상위).

**원본은 넓게, 이행은 좁게 — 이 비대칭이 의도다.**

- 원본을 넓게 잡으면 「이행이 더했다」의 **거짓이 준다**(원본이 하위 스코프에 갖고 있던 짝을
  이행이 최상위로 올린 것을 「추가」로 오인하지 않는다).
- 이행을 좁게 잡으면 이행이 CTE·파생 테이블로 **옮긴** 짝이 「추가」로 오인되지 않는다.
- 대가는 미탐이다. 이 저장소의 규약(**귀속할 수 없으면 침묵한다**)과 같은 방향이라 받아들인다.

### 2-3. 판정 — 「이행이 더한 짝」만 발화한다

이행 짝 중 **원본 짝 다중집합에 없는 것**만 발화한다. 침묵 조건 넷:

1. 원본 또는 이행의 짝이 0 이면 대조가 성립하지 않는다.
2. 별칭을 테이블로 해석할 수 없는 짝(파생 테이블·CTE 별칭)은 **양쪽에서 버린다** —
   `HasOpaqueJoinSource` 와 같은 정신이다.
3. `(서수, 종류, 대상 테이블)` 매칭이 유일하지 않으면 침묵한다(검사 B 규약 그대로).
4. **잃은 짝은 발화하지 않는다** — 스윕 지표로만 센다(§2-5).

### 2-4. 배선

`ddlByProcedure` 를 오케스트레이터에서 `ValidateBatchStep` 까지 흘린다.
**재료가 있음은 확인했다** — `VerificationPipelineOrchestrator:1716` 에
`IReadOnlyList<SpDefinition> definitions` 가 있고, **같은 자리(1743·1749)에서 같은 모양의 프로시저
단위 사전 둘(`parametersByProcedure`·`callGraph`)이 이미 만들어져 같은 길로 내려간다.**
`SpDefinition.DdlText` 도 있다. §10 이 「착수 전에 잴 것 하나」로 남긴 층이 이것이고, 통과했다.

### 2-5. 잃은 짝은 지표로만 센다

`SweepIndicators` 에 계수를 더한다. **발화시키지 않는 이유**: 이행이 조인을 하위 스코프로 옮기는
관용구가 실재하고(검사 B 가 `relocated` 합류를 만든 바로 그 이유), 최상위만 보는 대조는 그것을
「잃었다」로 읽는다. 오탐은 `SuggestedPromptFix` 를 타고 재생성 프롬프트에 실려 재시도를 소진시킨다.

**그 수를 남기는 이유**: 다음 회차가 「그 방향을 켤 것인가」를 **재고** 정하게 하기 위해서다.
검사 D 가 18 → 0 으로 꺼졌는데 아무도 몰랐던 자리가 이 저장소에 있다 — 안 세면 안 보인다.

## 3. 캐시 인상은 없다 — 그 전제가 깨지면 순서가 뒤집힌다

`DmlScopeExtractor` 에서 새로 뽑는 값을 **검사만 쓰고 표 렌더에는 싣지 않는다.** 그래서 프롬프트
바이트가 안 바뀌고 `CurrentCacheFormatVersion` 도 그대로다.

**이 전제가 깨지면**(짝을 명세서 표에 실어야 한다는 결론이 나면) 캐시 버전이 올라가고 **전건
재생성이 따라온다.** 그러면 이 작업의 순서가 다시 짜여야 하므로, 그때는 사람과 세션 `reset-06`
양쪽에 알린다.

## 4. ★ 되돌림 조건 — 하나라도 어긋나면 되돌리고 다시 잰다

**숫자를 맞추려고 조건을 손보지 않는다.** 이 문장이 이 문서의 존재 이유다.

1. **코퍼스에서 발화한다.** 단위 시험 통과는 효력이 아니다 — T22 는 게이트 녹색(실패 0 · 건너뜀 0 ·
   경고 0 · 통과 3,566)에 코퍼스 발화 0 이었다.
2. **오탐이 다수가 아니다.** 발화 전량을 원본 DDL 과 눈으로 대조해 판정하고, **정당한 이행이
   절반을 넘으면 되돌린다.** 이 조건이 같은 날 T29 를 막았다(발화 후보 23 의 다수가 계약을 지킨
   섀도 재구축이었다).
3. **`POQSettleBatch1/S10` 의 `UPDATE 11` 이 실제로 발화한다.** N5 그 자리다. 안 하면 판별자가
   틀린 것이지 결함이 없는 것이 아니다.
4. **없앴을 때로 잰다.** 수정을 넣고 빼며 두 번 스윕해 **사라진 발화가 0** 인지 확인한다.
   발화 수는 활동이지 효력이 아니다.

**게이트**: 실패 0 · 건너뜀 0 · 경고 0. 통과 수는 게이트가 아니다(환경 내에서도 최대 5 까지 흔들린다).
워크트리에는 코퍼스 재료 **넷**을 전부 건다(`output` 하나만 걸면 건너뜀이 생기고, 세 세션이 각각
그 자리에서 당했다).

## 5. 이 설계가 보증하지 않는 것

- **자기결합의 별칭 재귀속 자체는 못 가른다.** `B.X = C.X` 를 `A.X = C.X` 로 옮긴 것은, `A` 와 `B` 가
  둘 다 `TSettleMst` 라 **테이블 정규화 뒤에 같은 짝이 된다.** N5 가 발화하는 것은 이행이 **원본에
  없는 등식**(`A.ClientID = B.ClientID`)을 함께 더했기 때문이고, 그 발화 사유는 「별칭이 옮겨갔다」가
  아니라 **「원본에 없는 조인 등식을 더했다」**이다. 그 문장을 사람 판정대에 올리는 것까지가
  이 검사의 몫이다.
  - **코퍼스 원본 DDL 전체에서 자기결합은 1 건**(이 자리)이므로, 그 하나를 위해 별칭 그래프 동형을
    지금 사는 것은 YAGNI 로 봤다. 다시 열 근거는 **자기결합이 늘어날 때**다.
- **조인 종류(`INNER` ↔ `LEFT OUTER`)를 안 본다.** 재감사가 「명세서에 기준값이 없다」고 못박은
  자리이고 축 A 의 몫이다.
- **원본 짝을 넓게 잡은 대가인 미탐을 안 쟀다.** 원본을 넓게 잡을수록 「이행이 더했다」가
  줄어든다 — 그만큼 놓친다. ⚠ **구현은 §2-1 이 적은 「하위 스코프 전체」까지 가지 않았다**
  (`ON` ∪ `WHERE` 까지다). 그 사정은 §6-3 에 있다.
- **의미 동등을 판정하지 않는다.** 짝이 같아도 조인이 대상 행 집합을 보존하는지는 로컬에서
  검증할 수 없다(`SubordinatePredicateColumns` 문서가 같은 한계를 적는다).

`SweepIndicators.JoinPairsLostFromImplementation`, 보고서 「침묵 분모」 절.

### 6-3. 설계와 달라진 것 둘 — 적어 둔다

1. **원본 수집 범위를 「하위 스코프 전체」까지 넓히지 않았다.** §2-1 은 `ON` ∪ `WHERE` ∪
   하위 스코프라 적었으나, 구현은 추출기가 이미 보는 `ON` ∪ `WHERE`(문장 최상위)다.
   ①의 실측(38 문장 · 짝 124)이 그 범위에서 나온 수이고, **그 범위로 오탐 0 에 닿았으므로**
   넓히지 않았다(YAGNI). 넓혀야 할 근거는 「원본이 하위 스코프에 갖고 있던 결합을 이행이
   최상위로 올려 오탐이 났다」는 실물이고, **그런 자리는 아직 안 나왔다.**
2. **`INSERT` 문장은 짝을 내지 않는다.** ①이 `UPDATE`·`DELETE` 만 셌고 N5 도 `UPDATE` 다.
   `INSERT` 는 원본 짝이 0 이라 침묵 조건 1 에 걸려 안전하게 조용하다 — **구멍이지만
   재지 않은 구멍**이라는 뜻이므로, 열려면 ①부터 다시 재야 한다.
