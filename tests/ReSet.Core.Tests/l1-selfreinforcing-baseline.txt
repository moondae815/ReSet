# 「한 객체의 연속한 두 시도에서 같은 검사키가 발화」한 자리 중, 사람이 판정한 것.
#
# 형식: <객체> <검사키>  # 판정과 근거(커밋 해시 포함)
#
# 여기 적는 것은 「봐줬다」가 아니라 「봤고 이렇게 판정했다」이다. 근거 없이 적지 마라 -
# 근거 없는 줄은 화이트리스트가 조용히 넓어지는 자리가 된다.
#
# 이 게이트의 관할은 「만족 불가능한 지시」이지 「나쁜 문구」가 아니다. 단발로 끝난
# 결함은 여기 안 걸린다(2026-09-09 MachineTableShapeBroken 이 그랬다).
#
# ★ 2026-09-10 첫 실물 승격(dbo.UP_UTIL_SETTLE_EXCEPTION_PROC) 판정 머리말 — 이
# 게이트가 내는 것은 「자기강화 후보」이지 「자기강화 판결」이 아니다. 아래 두 줄이 같은
# 서명(연속 발화)으로 잡혔지만 원인이 다르다:
#   - CheckErrorCodeUniquenessClaim = 검사 자체의 결함(오탐). 검사가 실제로 만족
#     불가능한 지시를 냈다 — 이 게이트가 잡으려던 바로 그 모양.
#   - AddUpdateMappingError = 검사도 지시도 옳다(프롬프트가 정확히 「### UPDATE 대상
#     테이블:」 형식을 요구했고 만족 가능함을 시도 3·4 가 증명한다). 모델이 그 형식을
#     붙들지 못하고 두 번 진동했을 뿐이다 — 「어렵지만 만족 가능한데 진동」이지
#     「만족 불가능」이 아니다.
# 다음 사람이 이 파일을 훑고 「연속 발화 = 전부 자기강화 결함」이라고 일반화하면 안
# 된다. 서명은 후보를 내리는 것까지고, 원인 판정은 그 아래 근거를 읽어야 나온다.

dbo.UP_UTIL_SETTLE_EXCEPTION_PROC CheckErrorCodeUniquenessClaim  # 오탐(검사 결함), 근거: l1-attempts.json 시도 4 메시지가 인용한 문장 —
  # "…위 두 쌍이 코드를 공유하므로 반환 코드 전체를 "고유하다"거나 "서로 다르다"고
  # 서술해서는 "안" 됩니다" — 이 문장 자체가 옳다(오류 코드 -1·-2 중복을 정확히
  # 부정하고 있다). MechanicalValidator.cs 의 UniquenessDenialTokens = { "아니",
  # "않", "중복", "공유" } 에 선행 부정 「안」이 없어 "서술해서는 안 됩니다"의 부정을
  # 못 가른다. 그리고 이 문장은 모델이 지어낸 게 아니라 프롬프트 공지문(규칙 층 수정
  # 8019ecfc)을 본문에 그대로 옮겨 쓴 것 — 규칙 층 수정이 L1 오탐의 새 입력을 만든
  # 사례다. 시도 1·2·3·5(HEAD 20ac803c 기준 재확인)는 실제로 "고유"·"서로 다른"을
  # 유일성 주장으로 쓴 진짜 결함 — 그 넷은 이 게이트가 옳게 잡은 것이다. 다만 게이트
  # 서명 자체는 "어느 시도가 옳고 어느 시도가 틀렸는지"를 안 가르므로, 이 줄은 그
  # 오탐 원인(토큰 구멍) 하나를 판정해 덮는다. src/ 의 토큰 구멍 자체는 이 태스크의
  # 범위 밖이라 고치지 않는다(별건으로 닫는다).

dbo.UP_UTIL_SETTLE_EXCEPTION_PROC AddUpdateMappingError  # 자기강화 결함이 아니라 진동(만족 가능한 지시), 근거:
  # raw/prompt-context.md 20행이 정확히 "### UPDATE 대상 테이블: …" (헤딩 레벨 3)을
  # 예시로 준다. MechanicalValidator.cs:2456 의 UpdateHeadingPrefix = "### UPDATE
  # 대상 테이블:" 도 같은 레벨을 요구한다. 그런데 실제 배송본(docs/Spec.md 99행 이하,
  # 18개 UPDATE 절 전부)은 "#### UPDATE 대상 테이블: …" (헤딩 레벨 4)로 썼다 —
  # "####"는 "### "로 시작하지 않으므로 CollectUpdateSections 가 0 건으로 못 찾고
  # ResolveSectionBody 가 매번 "매핑 표가 없습니다"를 낸다(시도 1·2·5·6 메시지가
  # 문자 그대로 동일한 이유). 시도 3·4 에서는 이 검사가 조용했다 — 즉 그 두 시도는
  # 헤딩 레벨을 실제로 맞췄다는 뜻이고(만족 가능함의 증거), 5 로 넘어가며 모델이 다시
  # 레벨 4로 되돌아갔다. 지시가 불가능한 게 아니라 모델이 자기 출력 형식을 일관되게
  # 못 지킨 것 — 이 게이트가 낸 「후보」는 맞지만 판결은 「진동」이지 「자기강화」가
  # 아니다. 검사도 프롬프트도 고칠 필요가 없다고 판정한다.
