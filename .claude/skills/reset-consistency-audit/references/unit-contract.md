# 단위 공통 반환 계약

모든 서브에이전트가 축과 무관하게 지킨다. 자기 축의 계약은 `axis-a.md` 또는
`axis-b.md`에 있다.

각 서브에이전트는 **자기 단위의 파일만** 읽고, 아래를 그대로 반환한다.

- 판정: `정합` / `결함` / `검증 불가`
- 결함 목록: 항목별로 `등급 · 원본 앵커(파일:줄) · 산출물 앵커(파일:줄) · 원본 내용 · 산출물 내용 · 영향`
- 읽지 못했거나 판단을 보류한 절

**캐시는 상위가 쓴다. 단위는 열지 않는다.** 아래는 상위가 그 반환값을 어떤 모양으로
저장하는지이고, 단위가 반환값을 그 모양에 맞춰 내면 상위가 변환 없이 담을 수 있다.
**필드 이름을 새로 짓지 마라.** 값의 모양이 달라지면 키가 맞아도 옛 판정을
읽어낼 수 없어, `../SKILL.md` 2-1절의 Job 간 재사용이 조용히 무너진다. 기존 캐시(실측 41개 항목,
결함 113건)가 쓰는 모양은 이것이다.

```json
{ "axisA:<Key>": {
    "key": "<sha256>|<sha256>|<sha256>", "verdict": "정합|결함|검증 불가",
    "defects": [ { "grade": "🔴", "src": "object_definition.sql:146",
                   "out": "Spec.md:92", "desc": "…", "impact": "…" } ],
    "holds": [],
    "callers": 5,        // 함수 단위만 - 호출하는 SP 수
    "row": "UF_GET_ROUND4VAT" } }   // 교차 단위만 - 대조한 표의 행
```

상위는 이 반환값을 **합치기만 한다.** 상위가 원본이나 계획서를 다시 읽어 판정을 바꾸지 않는다.
단위가 판정과 결함 목록을 어긋나게 반환하면(`정합`이라 쓰고 🔴·🟠·🟡을 함께 냄)
**결함 목록이 이긴다** — 판정 문구를 맞추는 것은 재판정이 아니라 합치기의 일부다.

등급: 🔴 결과 금액이 달라짐 · 🟠 대상 행 집합이 달라짐 · 🟡 표기·추적성 · ⚪ 정보

등급이 갈릴 때는 **영향이 배포 구성에 달려 있으면 높은 쪽**으로 매기고, 그 전제를
결함 행에 적는다. 실측에서 같은 결함(스칼라 서브쿼리 → `CROSS APPLY`)이 한 실행에서는
🟠, 다른 실행에서는 ⚪로 갈렸다.
