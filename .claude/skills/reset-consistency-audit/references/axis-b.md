# 축 B 대조 계약 (단계 단위)

이 파일은 축 B 단계 단위가 읽는다. 반환 형식과 등급은 `unit-contract.md`에 있다.

## 4. 축 B 대조 계약

단계 하나마다 그 단계의 `steps/SNN.md`와 대응 레거시 SP의 `Spec.md`만 들고 대조한다.
그 단계가 SP 여러 개를 흡수했다면 흡수한 SP의 `Spec.md`를 **전부** 기준값으로 삼는다.
계획서(`docs/BatchMigrationPlan.md`)는 단계 절을 이어붙인 조립본이므로 따로 읽지 않는다 —
**단, 조립본과 번들이 실제로 같은지는 기계로 확인**하고 결과를 보고서에 남긴다. 확인은
단계 본문에서 문장을 뽑아 계획서 안에 그대로 있는지 보는 것으로 충분하다. 실측: 번들이
있는 17개 Job 전부 100%였다(계획서 실측 최대 253KB를 읽지 않아도 되는 근거가 이것이다).

```python
c=[l.strip() for l in open(step,encoding='utf-8') if 60<len(l.strip())<200
   and not l.strip().startswith(('#','>','\ufeff'))]      # 배너·제목 제외
hit=sum(1 for x in c[len(c)//4:][:5] if x in plan)          # 앞머리 편향 제거
```

**배너를 빼는 것이 핵심이다.** 하한 미달·검증 불가 배너(`> ⚠️ …`)는 단계 파일 맨 앞에만
붙고 계획서에는 다른 형태로 실린다. 걸러내지 않고 앞에서부터 표본을 뽑으면 정상 Job이
67%로 나와(실측 `POQSettleProc6`, 33단계 중 32개 "불일치") 멀쩡한 조립본을 결함으로 보고하게
된다. 불일치가 남으면 그때 계획서의 그 절만 열어 확인한다.

**축 B의 기준값은 `Spec.md`이고, 원본 DDL이 아니다.** Spec 자체가 원본과 어긋난 경우는
축 A가 잡는다. 이것은 열람 금지가 아니라 분업이므로, 축 B 단위가 원본을 못 봤다는 사실을
결함이나 한계로 적지 마라 — 축 A 결과와 나란히 읽으면 함께 덮는다.

**단, 둘이 덮지 못하는 자리가 하나 있다.** 명세서가 참조 함수를 다루는 자리는
축 A(객체 대 원본)도 축 B(Spec 대 단계)도 대상으로 삼지 않는다. 그 자리는 `axis-a.md`의
3-2절이 맡는다 — **축 B 단위가 손댈 일이 아니다.**

**레거시 대응이 없는 신설 단계**(`Legacy:`가 공란)는 기준값이 없으므로 `검증 불가`로 판정한다.
다만 그 단계가 **앞 단계가 확정한 컬럼을 다시 쓴다면**, 그 컬럼을 확정한 SP의 `Spec.md`를
함께 들려 보내 "덮어쓰는가"만 대조한다. 판정은 여전히 `검증 불가`이고, 대조가 성립한
범위와 그 결과를 커버리지 표에 적는다. 기준값이 없다는 이유로 아무것도 보지 않으면,
실측에서 그 자리에서 나온 🔴 3건을 놓친다.

| 대조 항목 | 무엇을 본다 |
|---|---|
| 오류 코드 보존 | Spec의 반환 코드 집합 ⊆ 단계의 보존 코드 집합 |
| 출력 인터페이스 | 원본에 없는 출력 파라미터를 신설하지 않았는가 |
| 대상 테이블 | Spec의 쓰기 집합과 단계의 변경 대상이 같은가 |
| 계산식 | 상수·계수·반올림 자릿수·부호가 그대로인가 |
| 필터·조인 | **조인 키**와 조건 컬럼, 비교 대상이 그대로인가 — 기준값은 명세서의 `DML 범위` 표 `조인 키` 칸이다. **조인 종류(INNER/LEFT)는 축 B에서 대조하지 마라**: 명세서에 그 정보가 없어(실측 `COMM_UPD` 명세서의 `JOIN` 문자열 0건) 기준값이 존재하지 않는다. 종류가 바뀌었는지는 축 A(원본 DDL)가 본다. 단계 SQL의 한정자 없는 `JOIN`은 `INNER`이므로 그것만으로 결함을 세지 마라 |
| UDF 호출 | 함수명과 **인자 개수·순서**가 그대로인가 (본문은 축 A가 덮는다) |
| 컬럼 집합 | `INSERT` 컬럼 수와 값 수, `UPDATE` SET 대상이 빠짐없는가 |
| 후속 단계 간섭 | 뒤 단계가 앞 단계의 결과를 덮어쓰지 않는가 |

## 축 B에서 흔한 실패

| 실패 | 실제로 벌어진 일 |
|---|---|
| 이름이 등장하니 커버됐다고 본다 | S11이 SP 3개를 흡수했는데 단계 표에는 1개만 적혀 있었다. 오류 코드 매트릭스는 세 SP 코드를 한 줄에 합쳐 추적 불가였다 |
| 축 B 단위가 원본을 못 봤다고 한계로 적는다 | 그건 분업이다. 축 A가 덮는다 |
